# PSS 校准抗干扰：融合设计

> **日期**：2026-11-27
> **状态**：设计稿（未实现）
> **范围**：把 F6 之后的六个改进方案（守门集、跨模态共识、有界更新、鲁棒估计、定向投毒测试、来源隔离）融合成一条流水线，并消除方案之间的语义冲突。
> **依据**：`reports/claim_gaps/online_calibration/REPORT.md`、`pss/projection/online.py`、`pss/projection/calibration.py`、`pss/eval/scripts/run_gap_online_calibration.py`、`pss_eval/preregistration.py`。
> **一句话结论**：六件事不该各自判断"该不该信"，而应各自回答一个**正交**的问题——来源是否异常、样本是否可疑、参数该信多少、这一步能走多远、新参数是否真的更好。五个问题正交，答案自然不打架。

---

## 0. 问题陈述

F6 证明了三件事：

1. 校准可以做到 8 个样本（逐 seed 最低 96% 恢复）；
2. 投毒在 10% 以上能被检出，40% 会触发弃权；
3. **投毒最阴险的后果不是答错，而是让置信度失效**——准确率从 0.964 到 0.974 纹丝不动，置信度从 0.92 掉到 0.186，ECE 从 0.045 涨到 0.788。

但 F6 的结构有一个根本弱点：

> **先拟合，再审计。** 审计不过才弃权；审计一过，拟合结果直接被接受为新基准。

也就是说**拟合本身不设防**，全靠审计兜。而审计在 5% 投毒时只有 67% 检出率，在 σ=0.05 漂移时是 0%。

六个改进方案分别针对不同缺口，但直接叠加会打架。本文的目标是先解决冲突，再谈实现。

---

## 1. 设计目标

这是一个**双目标**问题，两个目标天然对立：

| 目标 | 想要什么 | 代价 |
|---|---|---|
| **适应性** | 世界变了，尽快跟上 | 跟得快 = 容易被投毒带偏 |
| **抗毒性** | 数据被污染，纹丝不动 | 不动 = 真漂移也跟不上 |

不存在"两个都最大"。最优的定义是：

> **在投毒导致的能力退化不超过 ε 的前提下，让真实漂移的适应时间最短；同时不破坏确定性。**

验收按 Pareto 曲线，不按单一分数（见 §8）。

附带三条硬约束：

- **确定性**：同一输入两次运行，参数逐位相同（`pss_eval` 的 `determinism` property 必须继续通过）。
- **可审计**：每一次参数变化、每一次拒绝、每一次隔离，都要留可追溯记录。
- **可回滚**：任何一次提升都能退回上一版参数（复用 F7 的 delta 快照思路）。

---

## 2. 核心洞察：漂移与投毒是两种失败

F6 现在用同一个检测器同时管两件事，所以两者互相干扰。拆开看，统计特征完全相反：

| | 真实漂移 | 投毒 |
|---|---|---|
| 变化方式 | 渐变、持续 | 突变、局部 |
| 跨模态 | **所有专家一起变**（世界变了） | **专家之间仍然一致**（只有标签坏了） |
| 标签 | 和专家一致（标签没坏） | **和专家不一致** |
| 来源 | 全局 | 常集中在某个来源/时段 |

**关键**：漂移时三个专家看到的是同一个新世界，所以**专家之间仍然一致**；投毒时标签坏了，**专家之间的共识反而成了最可靠的参照**。

于是判决可以做成 2×2：

| 专家之间一致？ | 标签与共识一致？ | 判断 | 动作 |
|---|---|---|---|
| 是 | 是 | 正常 | 小步更新（NORMAL） |
| 是 | **否** | **标签可疑（投毒）** | 隔离样本、冻结参数（QUARANTINE） |
| **否** | 是 | **世界变了（漂移）** | 允许大步重校准（RECALIBRATE） |
| 否 | 否 | 证据矛盾 | 停止自适应（ABSTAIN） |

这张表把方案 2、4、6 与原漂移检测串在一起，且两路信号几乎正交，不会互相干扰。

## 3. 融合后的管道

```
采集（带来源、时间戳）
   │
   ├─ ① 来源健康度        方案 6 —— 输出源级信任权重，不是独立参数
   ├─ ② 逐样本打分        方案 2 —— 输出连续权重 w ∈ [0,1]，不是硬掩码
   ├─ ③ 加权鲁棒拟合      方案 4 —— 输出一个候选参数
   ├─ ④ 证据驱动截断      方案 3 —— 输出实际可上线的候选
   ├─ ⑤ 双准则守门        方案 1 —— 输出接受 / 拒绝
   ├─ ⑥ 状态机            更新 / 隔离 / 重校准 / 弃权
   └─ ⑦ 有符号校准报告
```

每一步的位置都是被冲突逼出来的。三个关键决策见 §4。

## 4. 三个把冲突变成协同的决策

### 决策 A：硬掩码 → 连续权重（融合方案 2 + 4）

原方案里，方案 2 产出二值掩码，方案 4 又自己搞一套"共识子集"，会出现两套共识定义。

**融合做法**：只保留**一个**权重向量：

```
w_i = f(标签与共识是否一致, 模态间隔, 是否近重复, 是否质心离群, 来源信任)
     ∈ [0, 1]
```

- **审计**看 `suspect_mass = 1 - mean(w)`；
- **拟合**用 `w` 做加权 NLL 与加权准确率。

"截尾"退化为 `w=0` 的特例。方案 2 与方案 4 变成同一件事的两个视角。

**顺带解掉冲突 1**：审计统计量只依赖**预测和标签**，不依赖校准后的概率。方案 4 换估计器不会移动方案 2 的阈值。

### 决策 B：固定步长 → 证据驱动的步长（融合方案 3 + 漂移通道）

固定"每次最多 1.5 倍"安全但太慢。改为：

```
max_step = g(evidence)
```

| 证据 | 步长 |
|---|---|
| 专家一致、标签一致（正常） | 小步，如 ×1.2 |
| 专家集体偏离、标签仍一致（真漂移） | 大步，如 ×3 |
| 标签可疑（投毒） | **0（冻结）** |

截断从"刹车"变成"根据证据决定踩多深"。适应速度与抗毒性用同一个旋钮调节。

**顺带解掉冲突 4**：所有来源聚合成**一个**候选参数，上界永远定义在聚合结果上，不会出现"每源各走 1.5 倍"的叠乘。

### 决策 C：绝对阈值 → 相对比较 + 双准则（融合方案 1 + 4 + 漂移）

写死"ECE 必须 < 0.05"，方案 4 一换估计器阈值就废。改为**同数据、同估计器的相对比较**：

```
接受条件（两条都要满足）：
  (a) 完整性：候选在冻结守门集上不劣于现役（NLL 与 ECE 均不退化）
  (b) 适应性：候选在最近可信窗口的「留出切片」上优于现役
```

| (a) | (b) | 解释 | 动作 |
|---|---|---|---|
| 过 | 过 | 真漂移 | 接受 |
| 过 | 不过 | 没必要更新 | 拒绝（省算力） |
| 不过 | 过 | 投毒：新数据"变好"是因为标签被改得更容易拟合 | 拒绝 |
| 不过 | 不过 | 不确定 | 拒绝 + 计数 |

**(a) 用冻结集守完整性，(b) 用当前窗口守适应性**——这解决了"旧守门集在漂移后失效"的经典难题。

## 5. 接口

先冻结接口，五个方案才能并行（见 §9）。

```python
@dataclass(frozen=True)
class Params:
    temperature: dict[str, float]     # 每模态
    reliability: dict[str, float]     # 每模态

@dataclass(frozen=True)
class Evidence:
    cross_modal_agreement: float      # 专家之间一致性 [0,1]
    label_consensus_agreement: float  # 标签与共识一致性 [0,1]
    drift_score: float                # 特征分布漂移（无标签）
    suspect_mass: float               # 1 - mean(w)

@dataclass(frozen=True)
class SampleWeights:
    per_sample: np.ndarray            # w_i ∈ [0,1]
    reasons: dict[str, np.ndarray]    # 每类原因的布尔掩码，供审计

@dataclass(frozen=True)
class GateDecision:
    accept: bool
    integrity_ok: bool
    adaptation_ok: bool
    reason: str
```

四个核心函数加一个状态分类器，各自纯函数、可独立测试：

```python
def source_health(samples, source_ids) -> dict[str, float]:
    """每源信任权重。异常源 → 低权重；不产生独立参数轴。"""

def score_samples(samples, params, source_trust) -> SampleWeights:
    """逐样本连续权重。审计与拟合共用同一份。"""

def fit_params(samples, weights) -> Params:
    """加权鲁棒拟合：加权 NLL 定温度，加权准确率定可靠性。"""

def bound_step(old: Params, new: Params, evidence: Evidence) -> Params:
    """按证据强度限制单步变化。在 log T / reliability 空间裁剪。"""

def gate(old: Params, new: Params, gate_set, window_holdout) -> GateDecision:
    """双准则守门。只比较，不拟合。"""
```

`StreamingCalibrator.update()` 退化为组合：

```python
def update(self, samples):
    trust = source_health(samples, samples.source)
    w = score_samples(samples, self.params, trust)
    evidence = self._evidence(samples, w)
    state = self._transition(evidence)

    if state is ABSTAIN:
        return self._freeze(reason="conflicting evidence")

    cand = bound_step(self.params, fit_params(samples, w), evidence)

    if self._gate_due(state, evidence):
        decision = gate(self.params, cand, self.gate_set, self.window_holdout)
        if not decision.accept:
            return self._reject(decision)

    self.params = cand
    self._audit(...)
```

**门禁触发条件**（不是每次都跑，控制开销）：

- 任何 RECALIBRATE 提议；
- 累计参数漂移超过 δ；
- 每 K 次更新（默认 32）。

NORMAL 状态下的小步更新只受 `bound_step` 约束，不跑 gate。

## 6. 状态机

| 状态 | 触发 | 行为 | 审计记录 |
|---|---|---|---|
| **NORMAL** | 专家一致、标签一致 | 小步更新 | 参数变化量 |
| **QUARANTINE** | 标签与共识系统性不一致 | 隔离样本、冻结参数 | 被隔离样本与来源 |
| **RECALIBRATE** | 专家集体漂移、标签一致 | 大步更新 + 强制过 gate | 漂移证据 |
| **ABSTAIN** | 证据矛盾或连续 gate 失败 | 停止自适应、标记未知 | 原因；需人工解除 |

**ABSTAIN 必须是粘滞的**：不能自动恢复，必须由外部信号（人工确认、来源更换）解除。否则会在"弃权—重试—再弃权"之间抖动。

**状态转移的硬规则**：

```
NORMAL     → QUARANTINE    当 label_consensus_agreement < θ_L
NORMAL     → RECALIBRATE   当 cross_modal_agreement < θ_X 且 label_consensus_agreement ≥ θ_L
NORMAL     → ABSTAIN       当两者都 < θ
QUARANTINE → NORMAL        连续 M 个窗口标签恢复一致
RECALIBRATE→ NORMAL        gate 接受且证据回落
任意       → ABSTAIN       连续 K 次 gate 拒绝
```

阈值 θ 不在本设计中拍定，应按干净流的分位数标定（与 F6 现有漂移阈值同法：0.990 分位 + 下限）。

## 7. 守门集规范

这是整个设计的地基。五条硬性要求，少一条就不成立：

1. **永不参与拟合**——任何代码路径都不能碰；
2. **人工审核过**——至少抽样确认；
3. **来源多样**——避免单源占比过高；
4. **大小 32–64**——F6 已证明 8 个样本足够校准，64 个守门绰绰有余；
5. **不可自动更新**——刷新必须留审计记录 + 人工签字。

第 5 条最容易被忽略：**能被自动改写的守门集，等于没有守门集。**

> **命名**：不要叫 `anchor`。`pss/projection/anchor.py` 已有同名概念（投影头对齐用的冻结锚点），语义完全不同。本文统一用 **gate set / 守门集**。

## 8. 验收标准

不用单一数字验收，用四条：

| 指标 | 目标 | 方法 |
|---|---|---|
| **抗毒性** | 20% 随机投毒下，ECE 退化 < 0.05 | 现有 poison harness |
| **适应性** | 真漂移下 σ≥0.20 时 ≤ 32 个样本恢复正常；σ=0.10 保持 F6 的 110 | 现有 drift harness |
| **确定性** | 两次运行参数逐位相同 | `pss_eval` determinism property |
| **误伤** | 干净流更新拒绝率 < 5% | 干净流回归（当前 F6 误报 0.033） |

再加一条**定向投毒**（目前完全空白）：

- **把模型答错的样本的标签改成模型自己的答案** → 虚高准确率 → 可能造成**过度自信**（`poison_agree_with_prediction`）；
- 只翻转某一类 → 该类的置信度系统性坍塌（`poison_single_class`）；
- 只污染一个来源 → 检验方案 6。

## 10. 不作建议

| 做法 | 为什么不行 |
|---|---|
| 加更多检测信号 | 现有四个信号高度相关（都在看"标签对不对"）。需要的是**正交**信号，不是数量 |
| 把审计阈值调低 | 干净误报 0.033 会恶化，系统天天弃权 |
| 靠准确率监控 | 投毒时它根本不动（0.974 → 0.974） |
| 无界在线学习 | 这正是攻击入口 |
| 为鲁棒性牺牲干净精度 | 加权拟合会丢"难但答对"的样本，每加一层必须跑干净流回归 |

### 拆通道：置信度改用单调映射（2026-11-27 已实现）

**动机**：温度同时承担"跨模态可比 / 形状校正 / 置信度标定"三件事，漂移让三者解耦，只能靠限位硬撑。拆开：

- **排序/融合**继续用温度（只需要"可比"，卡不卡边界无所谓）；
- **置信度**改用单调分箱映射（`pss/projection/confidence_map.py`）：等数分箱 + 池化相邻违反者（PAV），**没有尺度参数，也就没有限位**。

映射每个窗口重新拟合，分箱权重用审计的样本信任度（不是硬剔除——剔除会偏向简单样本，反而抬高置信度）。

**真实数据（漂移测试集，无任何温度限位）**：

| 场景 | ECE（温度） | **ECE（融合映射）** |
|---|---:|---:|
| clean | 0.0208 | **0.0151** |
| `random_label_flip@0.10` | 0.0208 | **0.0109** |
| `drift@0.10` | 0.0559 | **0.0007** |
| `drift@0.20` | 0.1198 | **0.0349** |
| `drift@0.30` | 0.1554 | **0.0730** |
| `label_shift` | 0.0307 | **0.0292** |

**融合映射在每一行都优于温度，漂移下差距最大（0.155 → 0.073），且完全没有调任何温度上下限。**

**一个必须记录的失败**：**逐模态**映射会退化成常数（ECE 恒为 ~0.06）。原因：单个模态的 top-1 分数与"是否答对"的单调关系太弱，PAV 把所有箱池化成一个块，映射退化为"输出该窗口的平均准确率"。**置信度是关于融合决策的，不是关于单个专家的**；逐模态映射只保留为诊断，不作为系统置信度。

**结论**：限位问题在置信度通道上已经不存在。温度继续留在排序通道，它的取值范围只影响跨模态可比性，不再影响校准质量。

### gate 准则改为融合准确率（2026-11-27 已实现）

**先做了否定实验**：映射对温度是否敏感？同一份数据，温度从 0.01 到 1.0，映射后的样本外 ECE **精确相同（0.02132）**。

> 所以 **map-ECE 不能当 gate 准则**——它对全局温度完全不变，会把所有候选判成平局。

gate 改为保护**决策质量**：`integrity_ok` 与 `adaptation_ok` 都基于**融合决策准确率**（容忍 1 个百分点）。置信度归映射管，gate 只管排序。

**结果**（真实数据）：

| 场景 | ECE（温度） | **ECE（融合映射）** | 参数采纳 |
|---|---:|---:|---|
| clean | 0.0208 | **0.0151** | 是 |
| `drift@0.10` | 0.0559 | **0.0007** | 是 |
| `drift@0.20` | 0.1198 | **0.0349** | 是 |
| `drift@0.30` | 0.1500 | **0.0976** | **否**（准确率退步 > 1%） |
| `label_shift` | 0.0307 | **0.0292** | 是 |

**最重要的一条**：`drift@0.30` 参数被拒，但校准仍然从 0.1500 降到 0.0976。**置信度适配不再依赖参数适配**——这正是拆通道的目的。gate 拒绝的是一个会损害决策准确率的候选，这是它该做的事。

**语义变化**：拆通道之后，`accept_update` 不再是"校准是否成功"的判据，`ece_map_fused` 才是。现有预注册仍是温度范式的写法，需要重写（见下）。

### 预注册重写（2026-11-27）

**变更内容（记录在案，不是悄悄换表）**：

| 旧断言 | 新断言 | 理由 |
|---|---|---|
| 温度 ECE | `ece_map_fused` | 映射对全局温度精确不变，温度 ECE 不再度量校准 |
| 漂移场景 `accept_update=True` | 不再断言采纳 | gate 保护决策准确率，校准归映射；采纳与否不是校准判据 |
| — | 新增 `fused_accuracy` 下限 | 决策通道的质量由 gate 负责，需要独立断言 |
| — | 新增有符号偏差 `signed_gap_map_fused` | ECE 是绝对值，看不出过度自信/保守的方向 |

**阈值依据**：干净上限 0.03（与 F6 的 0.028 同量级）；投毒不超过干净上限的 2 倍（0.05）；漂移 0.03 / 0.05 / 0.12（σ=0.30 的世界噪声约为干净 3 倍，故取 4 倍上限）；准确率下限 0.90 / 0.85 / 0.75 / 0.60。

**结果：18 项中 16 项一致。** 2 项失败均为"定向攻击未被察觉"（`targeted_agree@0.10`、`targeted_single_class@0.20`），按方法论**保留为已知开放项**，不删除、不放宽。

| 场景 | ECE（映射） | 融合准确率 | 采纳 |
|---|---:|---:|---|
| clean | 0.0151 | 0.974 | 是 |
| `drift@0.10` | 0.0007 | 0.974 | 是 |
| `drift@0.20` | 0.0349 | 0.927 | 是 |
| `drift@0.30` | 0.0976 | 0.896 | 否（准确率退步） |
| `label_shift` | 0.0292 | 0.979 | 是 |

### 定向攻击：跨窗口 CUSUM（2026-11-27 已实现）

单窗口检测不到定向攻击，但**流式可以**。实现 `pss/projection/cusum.py`：标签/共识一致性的双侧 CUSUM，漂移窗口不喂给检测器（否则每次漂移都会报警，阻断适配）。

**标定过程暴露了一个坑**：slack 取 1 倍噪声标准差（教科书默认）时，**大于攻击幅度**，每窗口净增量是负的，CUSUM 永远不累积。实测改为 **slack = 0.4 sd，threshold = 4 sd**：300 个干净窗口约 1% 误报，1.15 sd 的偏移 5 个窗口检出，0.39 sd 的偏移 8 个窗口检出。

注意：第一版模拟**每个窗口用同一批样本**，窗口间无抽样噪声，标准差算成 0，标定完全失真。窗口必须 bootstrap。

**真实数据（20 个窗口，每窗口 bootstrap 重采样）**：

| 场景 | 报警次数 | 首次报警窗口 |
|---|---:|---:|
| clean | 0 | — |
| `random_label_flip@0.05` | 8 | 2 |
| `targeted_agree@0.10` | 3 | **10** |
| `targeted_single_class@0.20` | 3 | **7** |
| `drift_sigma@0.30` | 0 | — |

**两种定向攻击都检出了，干净流与漂移都没有误报。** 单窗口预注册里那 2 项仍然失败——那是单窗口协议的固有限制，CUSUM 是另一个（流式）协议。报告里已交叉引用。

### 逐类 CUSUM 补齐单类攻击（2026-11-27 已实现）

全局一致性的问题：单类攻击只把全局一致性拉动 0.86 个百分点，要靠噪声累积才能在 7 个窗口检出。但**被攻击那一个类**的错配率会跳到 ~20%。所以按 **consensus 类**分别做 CUSUM（按标签分组会把受害者藏进被翻入的类里）。

**真实数据（20 窗口）**：

| 场景 | 全局首次报警 | 逐类首次报警 |
|---|---:|---:|
| clean | — | — |
| `flip@0.05` | 2 | **1** |
| `targeted_agree@0.10` | **10** | — |
| `targeted_single_class@0.20` | 7 | **1** |
| `drift@0.30` | — | — |

**两个检测器是互补的，不是冗余的**：

- 逐类检测器看"错配率**上升**" → 抓标签污染（含单类）；
- 全局检测器（双侧，含 agreement-up）看"一致性**异常升高**" → 抓 `targeted_agree`（标签被改成模型的答案，错配率反而下降）。

**代价：多重检验。** 每类 1% 误报 × 16 类 ≈ 每几个窗口一次误报。因此逐类阈值取 5 sd（全局取 4 sd）来压 family-wise 误报率，代价是多花一两个窗口检出。实测 20 个干净窗口 0 误报。

### 置信度通道升级为自适应保形（2026-11-27 已实现）

`pss/projection/conformal.py`：自适应保形推断（ACI），输出**预测集**而不是概率，更新阈值为 `q ← q + γ(err − α)`。

**第一版实现有缺陷**：用"校准分位数 + 变 α"无法表达超出校准池范围的阈值，强漂移下覆盖率饱和在 0.56。改为直接更新阈值后恢复正常。

**真实数据（α_target = 0.10，目标覆盖率 0.90）**：

| 场景 | 覆盖率 | 平均集合大小 |
|---|---:|---:|
| clean | 0.911 | 0.92 |
| `drift@0.10` | 0.917 | 0.92 |
| `drift@0.20` | 0.891 | 0.94 |
| `drift@0.30` | 0.906 | **1.16** |
| `label_shift` | 0.979 | 1.00 |

**覆盖率在所有条件下都守在 0.89–1.0，而集合大小在强漂移下自动变大（0.92 → 1.16）。** 这正是保形该有的行为：不是一个拟合的数字，而是一个可写的保证——"长期漏检率 ≤ 10%，代价是漂移时集合变大"。

对论文的意义：置信度从"我们拟合得好"升级为"我们保证漏检率"，与契约叙事一致。

**结果全面变差**：

## 16. 样本需求（2026-11-27 实测）

真实数据，16 类，池 128，5 seeds × 40 draws（`reports/claim_gaps/sample_sweep/`）。

| 窗口 | 每类 | ECE(map) | flip10 单窗检出 | flip20 单窗检出 | agreement sd | agree snr | single snr |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 24 | 1.5 | 0.0418+/-0.0433 | 1.00 | 1.00 | 0.0395 | 0.26 | 0.16 |
| 48 | 3.0 | 0.0193+/-0.0177 | 0.80 | 1.00 | 0.0231 | 0.88 | 0.38 |
| 96 | 6.0 | 0.0180+/-0.0041 | 0.40 | 1.00 | 0.0119 | **1.60** | **0.74** |
| 128 | 8.0 | 0.0087+/-0.0062 | 0.40 | 1.00 | 0.0170 | 1.05 | 0.63 |

**结论**：

1. **校准：≥3 样本/类**。1.5/类时 ECE 标准差 0.043（不稳定），3/类降到 0.018，6/类 0.018±0.004。**推荐 6/类。**
2. **20% 投毒：任何窗口都能单窗检出**（1.00）。
3. **10% 投毒：单窗检不出，且小窗口的高检出率是假象。** N=24 时"检出率 1.00"不是灵敏度，是**噪声把状态机打进了非 NORMAL**——窗口越小越容易误报。N=96 时降到 0.40。**必须靠 CUSUM。**
4. **`targeted_agree`：≥3/类进入 CUSUM 可检区**（snr > 0.4），6/类最佳（1.60）。
5. **单类攻击：≥6/类**（snr 0.74）；3/类时 0.38，恰在 slack 边缘——与之前"脆弱"的判断一致。
6. **N=128 的 snr 回落不是"样本更多反而更差"**：池只有 128，等于池大小时只能 bootstrap（有放回），引入了额外噪声。这是实验设计的边界，不是真实趋势。

**一句话**：这套方法的下限是**每类 6 个样本**；低于 3 个，校准开始不稳定、定向攻击全部不可检。

### 可靠性加权（2026-11-27 已实现）

模态聚合从"等权平均"改为"按可靠性加权"，并复用投票权重同一个定义：可靠性低于最强模态一半的专家**不参与聚合**。gate 的两个候选都用**现役参数**的权重评估，避免候选通过重新分配权重来刷分。

**结果**：

| 场景 | ECE | 不适配 | 状态 | 采纳 |
|---|---:|---:|---|---|
| clean | 0.0208 | 0.0208 | normal | 是 |
| drift@0.10 | 0.0559 | 0.0558 | recalibrate | **是** |
| drift@0.20 | 0.1198 | 0.1186 | recalibrate | **是** |
| drift@0.30 | 0.1554 | 0.1500 | recalibrate | **是** |

**警告 1：clean 的 ECE 从 0.0433 掉到 0.0208，不是模型变好了。** 这是聚合口径变了——原来触觉（ECE ≈ 0.09）被平均进来，现在被排除。**改口径前后的数字不可比。**

**警告 2：漂移场景现在"采纳"了，但 ECE 几乎没动（0.1500 → 0.1554，甚至略差）。** 采纳的是触觉参数，而真正的视觉/几何仍被温度下限卡住。这就是"通过预注册 ≠ 能力提升"。

### 两遍法（2026-11-27 已实现）

原来漂移场景的 ECE 在**干净测试集**上计算，三个漂移场景都报 0.0433，与干净相同——失败被完全掩盖。现在漂移场景的测试集同步加噪，并额外报"不适配"对照：

| 场景 | ECE（漂移测试集） | ECE（干净测试集） | ECE（不适配） |
|---|---:|---:|---:|
| `drift@0.10` | 0.0522 | 0.0433 | **0.0522** |
| `drift@0.20` | 0.1060 | 0.0433 | **0.1060** |
| `drift@0.30` | 0.1225 | 0.0433 | **0.1225** |

**适配量精确为零。** σ=0.30 时校准误差是干净的 2.8 倍，而系统"知道"这是漂移（状态 RECALIBRATE）却一步没动。

**机制（已定位到具体行）**：筛查把"模型答错的样本"当成"标签被投毒"清零。保留下来的子集准确率恒为 **1.000**，于是拟合只看到简单样本，温度永远选最锐利的那个。校准失去了观察自身错误的能力——而观察自身错误正是校准的全部目的。

**已排除的假设**：不是优化器下界的问题。漂移下无权重的拟合温度是 0.062–0.109，在界内；把下界从 `exp(-3)` 放宽到 `exp(-8)` 反而让 geometry 的测试 ECE 从 0.0227 变差到 0.0525。当前下界起到正则作用，不要动。

### 两遍法（2026-11-27 已实现）

`score_samples` 增加 `state` 参数；驱动层先用影子权重算证据、判状态，再带着状态筛查。`RECALIBRATE` 下不惩罚标签不一致与间隔违背。

**效果**：
- 漂移下权重从被清零变成 **1.000**，机制打通；
- `label_shift` 真正改善：漂移测试集 ECE **0.0682 → 0.0523**（不适配 0.0687）；
- **但 `drift_sigma` 仍然不适配**，ECE 不变。定位到两个残余阻塞点。

### 残余阻塞点 1：温度下限挡住了漂移的方向

漂移会让 logits 的绝对值整体缩小（vision 最大 logit 从 ~1.0 降到 0.286），最优温度要**更小**才能保持同样的置信度。而搜索下界是 `exp(-3)=0.0498`：

| 模态 | 干净最优 T | 漂移 0.3 最优 T | 当前被夹到 |
|---|---:|---:|---:|
| vision | 0.063 | **0.032** | 0.0498 |
| geometry | 0.027 | **0.032** | 0.0498 |

**实测收益**（漂移 0.3，测试集同步加噪）：

| 配置 | 漂移测试集 ECE |
|---|---:|
| 不适配 | 0.1124 |
| 当前（下限 -3） | 0.1118 |
| 下限放宽到 -8 | **0.0802** |

相对改善 **28.6%**。注意不能全局放宽：干净数据上放宽会让 geometry 的 ECE 从 0.0227 变差到 0.0525。**只在 `RECALIBRATE` 下放宽**。

### 残余阻塞点 2：gate 用平均 NLL，被最差的模态绑架

宽度放宽后的候选：holdout ECE **0.1555 → 0.1365**（变好），但平均 NLL **1.7559 → 1.7745**（变差）。gate 看 NLL，所以拒绝。

原因：平均 NLL 被触觉专家（NLL ≈ 2.29）主导，把视觉和几何的变化淹没了。

**修法**：按可靠性加权聚合，或改用以 ECE 为主的接受准则。两种都改变投毒场景的 gate 行为，需要单独评审。

漂移场景全部适配失败，原因链是：

```
漂移 → 专家集体偏离 → 标签与共识不一致
     → score_samples 把不一致当"投毒"→ 权重归零
     → fit_params 有效样本崩塌 → 回退默认温度
     → gate 判定无增益 → 拒绝更新
```

但按 §2 的 2×2，漂移时标签是**可信的**，不该降权。问题在于管线顺序：`score_samples` 在 `classify_state` 之前，而后者依赖前者产出的 `Evidence`——**循环依赖**。

这不是阈值问题，是顺序问题。可行修法（Wave 2）：

- **方案 A（推荐）**：驱动层先跑一次 `suspect_mass=0` 的"影子"证据，判定状态，再把 state 传给筛查阶段，漂移态下不惩罚标签不一致。
- **方案 B**：把 `score_samples` 的标签惩罚上限从 0 提到 0.5，牺牲一部分投毒抵抗力换取漂移可适配。
- **方案 C**：把 gate set 传入筛查（需要改冻结签名）。

未采用任何一条，因为这属于 Wave 0 冻结后的接口变更，需要单独评审。

### Wave 1 过程中被数据推翻的三个设计假设

| 假设 | 实际 | 修正 |
|---|---|---|
| 三种模态等权投票 | 触觉 0.20 把共识拖到 0.73，83% 正常样本被误判 | 按可靠性加权投票，弱专家不参与筛查 |
| ECE/NLL 可做审计信号 | 换估计器即失效 | 审计只用预测+标签（决策 A） |
| 重复样本应降权 | 真实同类视图常规 >0.99 余弦，降权会偏向异类样本 | 只报告不降权（与 §8 "良性"一致） |
| 单类攻击看全局一致性 | 全局平均把 2.5% 的扰动稀释掉 | 改按 **consensus 类**分组算 spread |
| 筛查可在状态判定前独立完成 | 漂移时筛查会把标签不一致当投毒，权重归零，导致无法适配 | 两遍法已修复权重；温度下限与 gate 准则仍阻塞 |

### Wave 2：来源隔离

**状态（2026-11-27）：已完成。**

原方案的风险判断是对的——它确实改变了"聚合"的语义，所以放在最后做。实现分两块：

**1. 检测（`pss/projection/source_registry.py`）**

- 每个源一个 CUSUM，输入是该源的**绝对**标签/共识错配率，在干净窗口上标定；
- 两态：`trusted` / `quarantined`。隔离后该源样本权重归零、不参与聚合；连续 3 个正常窗口自动恢复；
- 状态切换全部进审计（`events`）。

**为什么用绝对值而不是相对值**：旧实现把源的一致率和**包含它自己**的全局均值比较。大的坏源会把基准拖下来，从而掩护自己——源越大越难发现。绝对错配率没有这个循环。

**2. 软权重（`source_health` 基线修复）**

参考值从"池化均值"改为**来源间的 75 分位**。两源时中位数只是两点中点，会把超额腰斩；75 分位保留较好的源作参照，又不至于被单个偶然值带偏。

**真实数据（20 窗口，40% good / 60% bad，坏源 35% 标签错误）**：

| 场景 | 全局首次 | 逐类首次 | 首次隔离 | 结束时被隔离 |
|---|---:|---:|---:|---|
| clean | — | — | — | [] |
| `source_outlier_stream` | 1 | 1 | **1** | **['bad']** |
| `drift@0.30` | — | — | — | [] |

**坏源在第 1 个窗口被隔离，好源不受影响，干净流与漂移零误报。**

**已知边界**：注册表只监视标定时见过的源。一个**全新来源**第一次出现时没有检测器，不会被监控——需要在线注册（用后续干净窗口标定）才能覆盖。
