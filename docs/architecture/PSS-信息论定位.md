# PSS 的信息论定位：公共语义空间会不会"信息密度天生更低"

> 日期：2026-11-27
> 范围：回答"PSS 的公共语义空间是否在信息密度上天然弱于 LLM 隐向量，导致推演水平永远超不过训练好的 LLM"
> 依据：`PSS-认知层架构定位.md` §4、`PSS_VS_TRANSFORMER_RESULTS.md` §2、`pss/projection/heads.py`（PUBLIC_DIM=128、PCA-whiten + residual）
> 关联实验：P2 开放集（§2.3）、P3 增量（§2.4）、P5b 关系组合 OOD（§2.16/2.20/2.21/2.22）、P0 长历史（§2.29）、公平归因（§2.28）
> 定位：本文件是 `PSS-认知层架构定位.md` 的理论补页，把 §4 那句"上限不取决于是否小"写成可证伪的信息论边界。

---

## 0. 核心判断

> **"公共语义空间的信息密度天生比 LLM 隐向量低一截，所以推演永远超不过 LLM"——不成立作为架构定律。**
>
> 真正的硬约束只有两条：**数据处理不等式（信息不能在下游被造出来）** 和 **冻结带来的协同适应损失（表示没有为推演被塑形）**。这两条约束的上界由 **"最弱的编码器 + 最死的投影 + 最浅的推理层"** 决定，不由"公共语义空间"这个概念决定。把最弱环替换掉，上界随之抬升。
>
> 反过来，在**组合关系泛化、知识热更新、冲突弃权、大实体规模**这四个维度上，是**训练完成的 LLM 有天花板（且不可改），PSS 没有**。

---

## 1. 问题的提法里混了三件事

"信息密度差一截"这句话同时指向三个不同的量，必须拆开谈，否则无法证伪：

1. **原始容量**：向量能线性容纳多少独立方向（4096-d vs 128-d）。
2. **内在维度**：流形实际用了几个自由度、有多少冗余。
3. **任务相关互信息** I(表示; 任务)：对下游推演真正有用、且**能被读出来**的比特。

LLM 隐向量在第 1 项上高，但第 2 项远低于 4096（大量冗余与纠缠），第 3 项掺入大量与任务无关的表示。PSS 公共空间在第 1 项上低，但**经过对比/锚点对齐后，单位维度承载的跨模态共享语义反而可能更高**——因为模态私有的 nuisance 被压缩掉了。

所以正确的表述不是"密度差一截"，而是一个权衡：

> **对齐（压缩 nuisance）提高了每个维度的语义密度，同时降低了总容量。** 这对下游是利是弊，取决于**任务是否需要那些被扔掉的 nuisance**。

对受限的推演任务（关系、状态、组合），低维对齐空间往往**更好用**（干扰更少、可校准）；对开放式的全套语言/细粒度感知分布，128 维装不下，需要更高容量或更强骨干。这是设计变量，不是宿命。

---

## 2. 两条真正的硬约束（都可写成不等式）

### 2.1 数据处理不等式（DPI）：下游不能造信息

设专家编码器为 $E_i$、投影为 $P$、推演函数为 $R$，任务标签为 $y$，原始输入为 $x$：

$$I\big(P(E_i(x));\,y\big)\;\le\;I\big(E_i(x);\,y\big)\;\le\;I(x;\,y)$$

含义：**任何在公共空间里做的推演，其上界是"投影之前编码器已经保留的任务信息"**。如果 DINOv2 没有编码进某个细粒度空间关系，或 PCA-whiten 96 维把它投影没了，再强的推理层也救不回来。

这条约束是真的、可证的，但它的边界是 **"最强的那一个编码器 + 最无损的那一次投影"**，不是"公共语义空间"这个概念本身。仓库里"保留原始特征，投影只做 adapter，不把信息压死"（`PSS-认知层架构定位.md` §3.2、`heads.py` 的 residual skip）正是在防这一条。

**推论**：当且仅当"编码器/投影"成为最弱环时，PSS 才被 DPI 真正卡住；此时该做的是换专家、加 residual/bilevel、扩公共维度，而不是继续堆推理模块。

### 2.2 协同适应（co-adaptation）损失：LLM 真正的护城河

LLM 强，**根本原因不是隐向量密度高**，而是：

> **表示与推算是同一套权重，被同一个任务损失端到端联合优化；表示是"被下游需要塑形出来的"。**

PSS 里通常是：专家冻结、投影服务外来对齐目标（对比/锚点）、推理层另做。于是出现一个具体错配：

> **"为对齐最优"的空间 ≠ "为推演最优"的空间。**

这是 PSS 在同规模下吃亏的主因，而它**可以被双层训练消解**（`PSS-认知层架构定位.md` 第五优先级"端到端 / bilevel"）：让 reasoning loss 回传到投影（必要时到编码器）。一旦推理也做成大而可微、投影参与联合优化，"计算函数"就被重新统一，此时"密度"不再是瓶颈。

## 3. 上界的四因子分解：什么时候真的低

把 PSS 能力上界写成乘积，就能看清哪些是可调因子：

$$\text{PSS 上界}\;\approx\; f\big(\underbrace{\text{最强编码器}}_{\text{可换}},\;\underbrace{\text{最强解码器}}_{\text{可换}},\;\underbrace{\text{公共空间维度/无损度}}_{\text{可调}},\;\underbrace{\text{推理层可学容量}}_{\text{可调}}\big)$$

当前实现四个因子都取了保守值：冻结小编码器、128-d plain/whiten 投影、手写规则与阈值。于是"上限低"是**实现取值的结果**，不是分层架构的属性。

反过来，有一个**真正的**硬天花板需要承认：

> **如果推理层保持符号规则、投影保持冻结、编码器不再升级，那么"符号规则 vs 可微大模型"在模糊/开放/需要细微高阶特征的场景下确实会输。** 但这时输的是"符号推理 vs 可微大模型"，**不是"公共空间 vs 隐空间"**。把这两件事分开，才不会把实现短板误诊为架构宿命。

---

## 4. PSS 上界更高的维度（该比的地方）

"和训练好的 LLM 比推演水平"这句话暗含单一标量比较。公平的做法是**分维度**。在 LLM 的主场（开放式语言、细粒度感知精度）PSS 不该比也比不过——`PSS_VS_TRANSFORMER_RESULTS.md` 已经诚实记录：公平归因后 re-ID 只剩 +0.012，同 tactile 的 sparse_k1 transformer 0.996 反超 PSS 0.989。

但在另一组维度上，**LLM 的上界在训练那一刻封死，PSS 的没有**：

| 维度 | 训练完成的 LLM 上界 | PSS 上界 | 已验证证据（仓库内） |
|---|---|---|---|
| **知识总量 / 时效性** | 冻结；微调会遗忘（full 掉到 0.735，forgetting 0.265） | **无上界**，随 FactStore 增长；0.171 ms/条、零遗忘、可回滚 | §2.26 事实热更新；§2.27 多源优先级 1.000 vs 0.800 |
| **组合 / 关系泛化** | 依赖训练分布，新组合 OOD 崩（0.434） | 显式关系结构，**系统性组合** | P5b：**1.000 vs 0.434**；渲染版 1.000 vs 0.453；执行闭环 1.000 vs 0.400 |
| **可信度 / 弃权** | 过度自信，无原生弃权 | 知道自己被打架、知道不知道 | 开放集 AUROC **0.993 vs 0.886**；冲突下弃权 accepted accuracy 1.000 |
| **规模（实体/历史）** | O(L²)/O(N²)，上下文有上限；长历史 0.12 | O(k²) active-set；**1.000，延迟不随历史增长** | §2.29 长历史 1.000 vs full attention 0.12；N=1000 快 24× |

最后一条是**质变不是量变**：LLM 的知识与工作记忆被上下文窗口封顶，PSS 的没有。因此在"知识更新的天花板"和"组合推演的天花板"上，**是 LLM 有天花板，PSS 没有**。

**需要同时承认的边界**（与 §3 一致，避免过度声称）：
- 闭集识别、属性 OOD、re-ID 的架构级优势**未被证明**（公平归因后 +0.012；P5 属性 OOD 仅 +0.011）。
- 上述优势多数来自**小型、从零训练的 transformer**；对真实预训练 VLM，结论需重跑。
- P5b 的优势来自**显式几何 goal check**，在完全模糊、无可判定关系结构的世界里未必保持。

## 5. 把"差一截"实验性地判掉（归因协议）

"密度是否差一截"可分解、可测量，不必停留在哲学。**在同一冻结编码器输出上**比较：

```
(a) 线性探针 / 小 MLP       —— 读出的信息下界
(b) PSS 推理层（投影+关系+规划）—— 结构先验带来的增量
(c) 全微调                  —— 容量上限参照
```

判读规则：

| 观测 | 结论 | 下一步 |
|---|---|---|
| **(b) > (a)** | 公共空间不是瓶颈；推理层从同样的冻结特征里多榨出了信息 | 天花板由 reasoning 容量决定，继续加可学关系层 |
| **(b) ≈ (a) < (c)** | 瓶颈在 **编码器/投影（DPI 约束）** | 换专家、上 residual、扩公共维度、跑 bilevel；别加推理模块 |
| **(b) < (a)** | 公共空间的对齐/投影**丢信息** | 检查 whiten 维度、residual、是否压死原始特征 |
| **(c) ≫ 全部** | 末端联合优化带来的增益无法用冻结路径复现 | 这就是协同适应损失的量化值；用 bilevel 缩小差距 |

必要消融（三选一即可定位"差一截"落在哪一段）：

1. **投影**：冻结 vs 与 reasoning 联合训练（bilevel）。
2. **维度**：128 vs 256/512 vs 128+residual（`heads.py` 已有 residual 开关）。
3. **估计量**：只测精度 vs 同时测校准（`calibration.py` / `conformal.py` / `cusum.py` 已就绪）。

理想产出是一张**归因表**：

$$\text{总损失} \;=\; \underbrace{\text{encoder loss}}_{I(x;y)-I(E_i(x);y)} \;+\; \underbrace{\text{projection loss}}_{I(E_i(x);y)-I(P(E_i(x));y)} \;+\; \underbrace{\text{reasoning loss}}_{\text{剩余可被 }R\text{ 读出的部分}}$$

三段各占多少，就回答了"密度差一截"具体差在哪个环节——而不是笼统归给"公共语义空间"。

### 5.1 首次运行结果（2026-11-27，category_pretrain，16 类）

脚本：`pss/eval/scripts/run_attribution_ablation.py`；报告：`eval/results/attribution_ablation/ATTRIBUTION_REPORT.md`。

| 量 | 值 | 备注 |
|---|---:|---|
| encoder ceiling（raw 最好读出） | 0.984 | raw MLP |
| projection best（同族读出） | 0.984 | proj LR |
| **projection loss** | **0.000** | 融合层面无损 |
| PSS reasoning | 0.979 | 原型融合 |
| reasoning gain（vs proj LR / MLP） | −0.005 / +0.016 | MLP 臂本身过拟合到 0.964 |
| **co-adapt gap** | **0.000** | 学习型 128-d 瓶颈+原型 = 0.979 |
| open-set AUROC（PSS / proj LR / raw LR） | **0.993 / 0.926 / 0.750** | 唯一显著区分点 |

分模态线性探针（raw → projected）：vision 0.990→0.995，tactile 0.203→0.219，geometry 0.911→**0.880**（保留率 0.966）。也就是说，128-d 投影在本任务上几乎无损，**唯一可测的损失是 geometry 的 −0.031**；融合把它补回来了。

Few-shot（每类 K=8/4 训练）：所有臂都在 0.958–0.995，仍然饱和，没有制造出可测的余量。

**结论（限定在本任务）：**
1. **公共空间不是瓶颈**——projection loss ≈ 0，且监督学习的 128-d 瓶颈也没有超过冻结投影（co-adapt gap = 0）。这直接反驳了"128 维公共空间天生丢信息"在本任务上的版本。
2. **PSS 推理在闭集精度上没有增量**（vs 线性探针为负、vs 过拟合 MLP 为正但后者不可信），与 `PSS_VS_TRANSFORMER_RESULTS.md` 的公平归因一致。
3. **唯一的架构级差异在开放集排序**：PSS 0.993 vs proj LR 0.926 vs raw LR 0.750。
4. **但闭集概率校准 PSS 反而更差**（ECE 0.458 vs 探针 ~0.02–0.12）：温度在 val 上拟合到 T≈0.2，测试集过锐。PSS 的优势是**拒绝排序（AUROC）**，不是闭集 softmax 校准；两者不要混谈。
5. **本任务太简单，无法检验"高维信息是否能被 128 维装下"的上界**：需要换 harder regime（跨视角实例、near-identical re-ID、真实 VLM 骨干）才能让 projection loss 和 reasoning gain 有可测的余量。

### 5.2 硬任务复跑（2026-11-27，cross-view instance，384 类）

为了制造余量，用 `category_pretrain_instance8`（每个物体 8 视角）做**跨视角实例判别**：同一物体的视角 0–5 训练、视角 6 验证、视角 7 测试；类别 = 实例身份（384 类，seen 类别）。专用专家/投影为 `category_pretrain_instance8_{experts,projection}`。

| arm | acc | 备注 |
|---|---:|---|
| raw LR / raw MLP | 0.747 / 0.776 | 冻结特征读出 |
| proj LR / proj MLP | 0.818 / **0.877** | 投影后同族读出 |
| PSS 原型融合 | 0.833 | |
| 监督瓶颈+原型 | 0.708–0.719 | 小样本过拟合 |

| 量 | 值 | bootstrap 95% CI |
|---|---:|---|
| **projection loss（raw−proj）** | **−0.101** | raw_mlp−proj_mlp = −0.094 [−0.138, −0.049] |
| reasoning gain（vs proj LR / MLP） | +0.016 / **−0.043** | vs MLP = −0.039 [−0.073, −0.005] |
| co-adapt gap | −0.115 | 监督瓶颈在 384 类 6-shot 下过拟合，非干净估计 |

分模态（raw → projected）：vision 0.732→0.721，tactile 0.195→0.216，geometry 0.109→**0.143**。

**结论（硬任务，可与 §5.1 对照）：**
1. **投影不是瓶颈，反而是增益**：投影后的融合读出比原始特征高 **+9.4 点（CI 排除 0）**。这直接反驳了"128 维公共空间信息密度天生低于原始/隐向量"——在这类需要细粒度实例信息的任务上，对齐层**提升**了可读信息（它压掉了视角 nuisance）。
2. **损失落在读出层，不落在空间**：PSS 原型融合显著低于同表示上的非线性探针（−3.9 点，CI 排除 0），只与线性探针打平。也就是说，**瓶颈是 reasoning 的读出容量/形式，不是维度**——与 §3"推理层若浅或手写，就是天花板"一致。
3. **协同适应臂不能当结论**：监督瓶颈在 384 类、每类 6 shot 下过拟合（0.71），这一轮的 co-adapt gap 是负的，不能解读为"协同适应不重要"；需要更大数据或更强正则重测。
4. 净结论：**"信息密度差一截"在本任务上不成立；真正可测的短板是读出层。** 下一步检验可学读出（见 §5.3），而不是扩公共空间维度。

### 5.3 可学融合头复跑（2026-11-27，同一跨视角任务）

为检验"换掉原型最近邻、改用可学融合头能否让 reasoning gain 转正"，在同一 projected 表示上训练两个可学读出（3 seeds 概率集成，同 train/val/test）：

- `learned_fusion_gated`：分模态嵌入 + 逐样本 softmax 门控（学习 reliability 权重，替代固定 `{vision:1, tactile:0.5, geometry:1}`）+ 头；
- `learned_fusion_concat`：分模态嵌入 + 拼接（保留每个模态的信息）+ 头。

| arm | acc | ±std(seed) |
|---|---:|---:|
| 原型融合（原 PSS） | 0.833 | 0 |
| 可学门控融合 | 0.839 | 0.190 |
| 可学拼接融合 | 0.831 | 0.006 |
| **通用 concat MLP（同表示）** | **0.878** | 0.003 |

bootstrap 95% CI：
- 门控 − 通用 MLP = **−0.039 [−0.078, 0.000]**；门控 − 原型 = +0.005 [−0.036, 0.049]
- 拼接 − 通用 MLP = **−0.047 [−0.078, −0.016]**；拼接 − 原型 = −0.003 [−0.042, 0.039]

**结论：**
1. **reasoning gain 没有转正**：两个可学融合头与原型读出统计上无差别（门控 +0.5pt、拼接 −0.3pt，CI 跨 0），且都显著低于同表示的通用 concat MLP（−4～−5 点，CI 排除 0）。
2. **"可学融合" ≠ "融合结构有用"**：把固定权重换成学习门控、或加分模态嵌入，只是复现了原型水平；真正拉开差距的是**普通高容量读出**（直接 concat + MLP），不是 PSS 式结构。
3. **门控融合不稳定**：跨 seed 标准差 0.19（会塌缩），需要集成才追平原型；不宜作为默认。
4. 因此在本任务上，**PSS 的结构性读出（原型 / 门控 / 分模态拼接）没有超过一个普通高容量头**。PSS 的差异化价值必须来自这些头不具备的维度——开放集、显式关系、记忆、热更新——而不是闭集实例判别的融合方式（显式关系在组合 OOD 上的增量见 §5.7）。

### 5.4 为什么通用 MLP 更高，能不能直接换（2026-11-27）

**逐项归因（跨视角任务，同一 projected 表示）：**

| 归因项 | 证据 | 结论 |
|---|---|---|
| 非线性判别读出 | 线性探针 0.818 → MLP 0.878 | **+6.0 点**，最大单项 |
| 判别式 vs 最近原型 | 原型 0.833 → MLP 0.878 | +4.5 点 |
| seed 概率集成 | 单 seed 0.877 → 集成 0.878 | 可忽略 |
| 结构位置（ReLU） | 拼接 0.831 → 去 ReLU 0.841 | +1.0，CI 跨 0 |
| 融合结构 | 门控 0.839 / 拼接 0.841 / MLP 0.878 | 结构都追不上，−3.6～−4.7（CI 排除 0） |
| 容量 | ConcatFusion ≈247k 参数 > MLP ≈197k | **不是容量不足** |

**机制：**
1. MLP 第一层**在非线性之前**混合所有模态（`Linear(384→256)→ReLU`），能形成跨模态组合；分模态结构先各自 `Linear+ReLU` 再拼，丢符号与跨模态组合。
2. MLP 直接优化实例分类目标；原型是"冻结空间 + 最近质心"（Voronoi 线性判决），不具判别性，也无法表示每个实例 6 个视角形成的流形。
3. 投影按"跨模态**类别**对齐"训练，不是按实例判别训练；MLP 读出是第一个直接对齐任务目标的阶段，**它替投影补上了目标错配**——这正是 §2.2 协同适应在读出端的体现。

**能不能直接换？可以，但代价明确**（category 任务实测）：

| 读出 | closed-set acc | open-set AUROC |
|---|---:|---:|
| 原型（PSS 默认） | 0.979 | **0.993** |
| 通用 MLP | 0.984 | 0.935 |
| 门控融合 | 0.984 | 0.878 |
| 拼接融合 | 0.943 | 0.868 |

- 用 MLP 替换原型：closed-set +0.5（已饱和），**open-set −5.8（仅 max-softmax 打分；见 §5.5）**；还丢掉 0.17 ms 热更新、零遗忘、回滚、分模态冲突弃权与审计。
- **建议不要直接替换，改用双头**：原型作默认读出头（开放集 / 弃权 / 热更新 / 审计），可学头只对"已被原型接受"的样本做闭集精排；或把可学头的判别边界蒸馏回原型空间（学习度量 / 子原型）——但 384 类 6-shot 下监督瓶颈已过拟合（0.708），需要更多数据或正则。若给可学头配距离式打分器，则可不损失开集（见 §5.5）。
- 边界：合成代理数据 + 小编码器；真实 VLM 骨干下幅度可能不同，结论需重跑。

### 5.5 开集打分诊断：不是过拟合，是打分器（2026-11-27）

针对"闭集高、开集低 = 过拟合"的判断，做了控制变量诊断：**固定同一个 MLP 表示，只换开集打分器**。脚本 `pss/eval/scripts/run_openset_scoring_diag.py`，报告 `eval/results/openset_scoring_diag/`。

同一 MLP 头：train 0.994 / val 0.974 / test 0.974，**train−test gap 0.020** → 没有过拟合。

| scorer（同一表示） | AUROC | unseen reject @95% seen accept |
|---|---:|---:|
| MLP max-softmax | 0.935 | 0.799 |
| MLP energy | 0.968 | 0.786 |
| **MLP Mahalanobis** | **0.999** | **1.000** |
| MLP kNN | 0.993 | 0.958 |
| 原型 cosine（参考） | 0.993 | 0.977 |
| projected kNN | 0.998 | 1.000 |

**结论：**
1. **"闭集高、开集低 = 过拟合"在本例中不成立**：train−test gap 只有 0.020。
2. **低开集分主要是打分器问题**：max-softmax 对未见类天然过度自信；换 Mahalanobis/kNN 后，同一表示的 AUROC 从 0.935 升到 **0.999 / 0.993**，超过原型的 0.993，operating point 也到 1.000。
3. 因此"用 MLP 换原型会掉开集"**只在 max-softmax 打分下成立**；可学头 + 距离式打分器，开集不亏、闭集略高。
4. **但打分器有代价**：Mahalanobis/kNN 需要每类统计/近邻库，类更新时要重算，不是 0.17 ms 热更新。原型真正剩下的优势是**更新成本与可审计**，不是开集精度本身。
5. **评测口径**：不要只看 AUROC（拒绝一切也能刷高），要看 operating point（固定 seen accept 下的 unseen reject）与覆盖率。

边界：16 类、合成代理、任务偏易（Mahalanobis 到 1.000 说明余量大）；384 类 6-shot 与真实数据需重跑，Mahalanobis 在小样本下可能不稳，kNN 更稳。

### 5.6 识别版归因 v2：公共空间基本无损，剩下的是读出税（2026-11-27）

§5.1–5.5 的 (a)/(b) 都是在识别任务上做的代理；这一节补上**匹配读出 + 生产训练器 + 冻结算子最强可读参照**的复跑。脚本 `pss/eval/scripts/run_attribution_grid.py`、`summarize_attribution.py`；报告 `eval/results/attribution_v2/ATTRIBUTION_V2_REPORT.md`。

任务：`category_pretrain_instance8`，view-instance 跨视角实例判别，384 类；train = views 0–5（2304）、val = view 6（384）、test = view 7（384）。

| 表示 / 读出 | test acc |
|---|---:|
| raw（vision+tactile+geometry）+ MLP | 0.771 |
| **PCA-whiten → 128 + MLP（无监督）** | **0.875** |
| 生产投影 mlp128/category + MLP（seed 均值） | 0.866 |
| 同投影 + 原型融合（seed 均值） | 0.846 |
| 微调 vision 编码器 + MLP | 0.875 |
| DINOv2 + 学习投影 128 + MLP | 0.784 |

把 `A_frozen_best` 定义为冻结特征上最强可读（PCA-whiten + MLP = 0.875）：

| 段 | 点数 | 占正损失 | 说明 |
|---|---:|---:|---|
| encoder | 0.0（0–0.8） | 0% | 微调编码器 0.875 = PCA 0.875；无可测信息缺口 |
| projection | +0.9 | 31% | 学习投影 0.866 vs PCA 0.875 |
| reasoning | +2.0 | 69% | 同投影上，原型 0.846 vs MLP 0.866 |
| **total** | **+2.9** | 100% | PSS 原型 vs 冻结特征最好读出 |

**判读：**

1. **旧口径的 10.4 点 encoder loss 是读出假象**：raw MLP 只有 0.771，但无监督 PCA-whiten 就能从同一冻结特征读出 0.875；这 10.4 点是**原始特征几何条件差、MLP 读不出来**，不是编码器信息缺口。
2. **投影不是损失，反而是增益**：相对 raw 读出 +9.5 点；相对 PCA 只差 0.9 点。增益主要来自 whitening/条件化，不是“语义对齐”本身。
3. **reasoning 的 2.0 点是原型相对判别式 MLP 的残余劣势**，且 seed 不稳：seed 0 +4.9、seed 1 −1.0、均值 +2.0；不能把单 checkpoint 的 4–5 点当稳定结论。
4. **维度/残差不是瓶颈**：128→512 只 +0.8～1.1，seed 0 的 MLP 差异 CI 跨 0；residual 无增益。
5. **任务匹配投影反而更差**：mlp128 category→instance 掉 11.8 点；384 类 6-shot 的 instance SupCon 过拟合，category 对齐起正则作用。
6. **朴素 bilevel 有害**：部署 init 下，冻结投影 + 新头 0.876，联合微调投影+头 0.848；需要对齐正则/蒸馏，不能直接 CE 微调。
7. **DINOv2 不自动更好**：最好 0.784，低于 E0 的 0.875；通用大骨干需要任务适配。

边界：合成代理、跨视角实例、小编码器；T3 re-ID、T4 关系组合未在这一版跑。结论是“识别侧的公共空间基本无损”，不是“所有推演都无损”。

### 5.7 Version B：关系/组合 OOD 的三臂对照（2026-11-27）

§5 开头的 (a)/(b)/(c) 判读表，此前**没有按字面跑齐**：§5.1–5.5 的 (b) 实际是“投影 + 识别读出”，不是“投影 + 关系 + 规划”；(c) 也只有部分微调代理。这一节在 P5b 关系/组合任务上补上真正的三臂对照。

**任务**：P5b 符号关系组合。三个物体、五个区域；目标 = 物体 0 在 G，物体 1 与物体 0 满足 R1，物体 2 与物体 1 满足 R2。训练关系对 `(left,above) (right,below) (above,left) (below,right)`；测试是 held-out 组合 `(left,below) (right,above) (above,right) (below,left)`——每个关系都见过，组合是新的。每 seed 每 split 200 episodes；3 seeds。

**三臂**：

- **(a) 平坦探针**：one-hot 状态 + 关系对 → 动作的线性 / 小 MLP 策略；无显式 goal check、无搜索。
- **(b) PSS 组合**：学习空间关系头 + 显式 goal check + 对放置做 BFS；`pss_hand` 是同一规划器配手写关系。
- **(c) transformer**：端到端 token 策略，行为克隆训练。

脚本 `pss/eval/scripts/run_version_b_composition.py`；报告 `eval/results/version_b/VERSION_B_REPORT.md`。

| arm | ID success | OOD success | OOD invalid |
|---|---:|---:|---:|
| **(a) 线性平坦策略** | 0.987 ± 0.005 | 0.390 ± 0.062 | 0.000 |
| **(a) MLP 平坦策略** | 0.997 ± 0.002 | 0.573 ± 0.111 | 0.000 |
| **(b) PSS 学习关系（全区域）+ BFS** | **1.000** | **1.000** | n/a |
| **(b) PSS held-out 区域关系 + BFS** | 0.842（基线） | 0.682 ± 0.006 | n/a |
| **(b) PSS 手写关系 + BFS** | 1.000 | 1.000 | n/a |
| **(c) transformer 端到端策略** | 0.995 ± 0.007 | 0.425 ± 0.045 | 0.025 |

关系头探针（(a) 的知识读出）：

| 训练区域 | exact-4 | per-label |
|---|---:|---:|
| 全部区域（in-dist） | 1.000 | 1.000 |
| A/B/C（held-out 区域） | 0.571 | 0.893 |

**判读：**

1. **ID 不是区分点，OOD 才是**：三臂 ID 都在 0.987–1.000；换 held-out 关系对后，平坦探针掉到 0.39–0.57，transformer 掉到 0.425，PSS 保持 1.000。
2. **(b) > (a)**：显式关系谓词 + goal check + BFS 比最好的平坦 MLP 多 **+42.7 点**，比线性多 **+61.0 点**。从同一份符号输入里，结构先验确实多榨出了组合泛化。
3. **(b) > (c)**：transformer 的 ID 与 PSS 打平，OOD 只有 0.425；它在记“训练关系对 → 动作”，不是在学可组合的关系。小 transformer 的 OOD 天花板来自训练分布，与 §4 的 P5b 结论一致。
4. **(b) 的优势不是免费的**：关系头覆盖决定上限。全区域头 exact-4 = 1.000 → PSS OOD 1.000；只训 A/B/C 的头 exact-4 = 0.571 → PSS OOD 0.682。也就是说，(b) = **关系知识 + 组合/搜索**：头好时组合接近完美；头差时组合仍比平坦策略稳（0.682 vs 0.39–0.57），但不再 1.000。

**与 §5.6 的关系**：

- §5.6 回答“识别侧公共空间是否丢信息”：基本无损，剩下的是 ~2 点读出税。
- §5.7 回答“结构先验是否从同一表示里多榨出组合泛化”：在关系/组合 OOD 上是 **+43～+61 点**。
- 两者不矛盾：PSS 的差异化价值不在闭集识别的信息密度，而在**系统性组合**；这正是 §4 的主张。

**边界**：P5b 是符号、小规模任务，`(a)` 的“冻结特征”是状态/区域 one-hot，没有 encoder/projection；它测的是组合读出，不是感知信息。transformer 是小型、从零训练的 BC 策略，不是预训练 LLM；关系头 held-out 区域只有 exact-4 0.571，1.000 依赖“头覆盖测试区域”，不能外推到任意新关系。

## 6. 什么不能声称（保持与实验一致的诚实口径）

- 不能声称 PSS 的**公共空间信息密度高于** LLM 隐向量；只能说二者是**容量 ↔ 语义密度**的不同权衡点。
- 不能声称 PSS 在**开放式语言/细粒度感知**上能超过大模型；那不是它的主场。
- 不能把本文的"四因子可调"当成"已经调到"；当前实现仍处保守取值（冻结小编码器、128-d、部分规则）。
- 不能把 P5b/开放集/热更新的证据外推到**预训练 VLM** 或**真实机器人**而未重跑（见 `PSS_VS_TRANSFORMER_RESULTS.md` §3.2、§4.5）。
- 本文的 DPI 不等式是**上界陈述**，不是"一定能达到上界"的构造性证明；达到上界仍需 §5 的工程。

---

## 7. 一句话

> **LLM 的优势是"计算函数的端到端可微优化"，不是"隐向量密度高"；PSS 的约束是"DPI + 冻结带来的协同适应损失"，其边界由最弱的编码器和最死的投影决定，可由换专家 / 可学投影 / 双层训练 / 可学推理层逐级抬升。真正结构性的天花板不在 PSS 这边——在组合关系、可热更新知识、冲突弃权、大实体规模上，是训练好的 LLM 有天花板，PSS 没有。所以别问"能不能在 LLM 的主场超过它"，要问"最强冻结骨干 + 可学认知层"这个混合体的上界在哪；P5b 的 1.000 vs 0.434、开放集 0.993 vs 0.886、0.171 ms 热更新，已是这个上界的三个实证锚点。**
