# 序：这条推演的主线

整场讨论并非一次规划好的设计，而是被七个关键追问推动着不断转向，最终收敛到一个可落地的架构。这条主线值得先看一眼：

```
Q1 不同感官的电信号本质相同吗？
   → 是。同一波形，靠通路（Labeled Line）区分来源
        ↓
Q2 视觉从光子到逻辑判断的全流程？
   → 六阶段：光学 → 视网膜换能 → LGN → V1 → 双通路 → 联合皮层
        ↓
Q3 联合皮层具体怎么用"电信号"完成思考？
   → 特征绑定 → 记忆检索 → 语义映射 → 工作记忆推理 → 价值决策
        ↓
Q4 这套和人脑思维，和 LLM 有什么异同？
   → 都是模式匹配系统；但记忆、感知、推理范式、内驱力根本不同
        ↓
Q5 完全照人脑重新设计 AI？
   → 七模块：SNN神经元 + 可塑突触 + 分层皮层 + 海马 + 前额叶 + 价值系统 + 预测反馈
        ↓
Q6 单个脉冲不携带信息，大脑怎么知道"红、圆、50cm"？
   → 群体编码 + 相位绑定。信息在"哪群神经元在何时放电"
        ↓
Q7 分组为什么必须靠相位？电信号没有别的维度吗？
   → 振幅会与特征强度冲突；模拟波远距离失真；专用线布线爆炸
        → spike 是生物湿件约束下的最优解，不是数学唯一解
        ↓
【转折一】既然 spike 只是生物硬件的最优解，硅基上能不能换一种载体？
   → 可以。多感官专家模型 + 统一向量空间 + 结构化绑定
        ↓
Q8 特征向量空间为什么天然不兼容？有理论支撑吗？
   → 神经网络表征的正交旋转不变性 + 流形假设 + 维度≠语义
        ↓
Q9 统一语义空间里，思考能力从哪来？
   → 思考 = 空间上的一套算子（检索/拆解/组装/对比/模拟）+ 显式工作记忆
        ↓
Q10 这套架构现实中有人做出来了吗？
   → 零件齐全，局部原型大量存在，完整一体化系统没有
        ↓
【转折二】大模型输出一定要是文本吗？
   → 不必。语言只是众多读出头之一，动作/目标/价值可以并行直出
        ↓
Q11 向量推理比 token 推理快吗？
   → 动态多客体场景快得多；纯文本场景不一定；关键在"状态"是否显式
        ↓
【落地】做成可运行 Demo
        ↓
Q12 Demo 算出大模型吗？只做到这种程度？
   → 不是大模型，是骨架验证器。特征与概念均为人工预置
        ↓
【关键澄清】识别不是目标，思考才是
   → 识别已被 CNN 解决；本架构真正的价值是：
     推理直接面向实体向量、原生支持物理场景追踪、
     感知/记忆/因果模拟共享同一语义空间
```

> **这一节（Q12）是整份文档的定位锚点。** 如果把本架构理解成"更强的识别器"，它的所有设计选择都会显得多余；只有把它理解成"面向物理实体的原生推理引擎"，前面每一层才各安其位。详见 [5.1 核心价值定位](#51-核心价值定位它不是更强的识别器)。

# 第一部分 生物侧：大脑到底怎么处理电信号

## 1.1 不同来源的电信号本质上是同一种

**结论：所有动作电位（沿神经纤维传导的脉冲）本质相同——波形、幅度基本一致。大脑不靠"电信号本身长得不一样"来区分感官来源。**

区分机制是 **标记线理论（Labeled Line）**：

> 通路身份 = 信号类型。
> 视神经上的脉冲，大脑默认解释成"光"；听神经传来一模一样的脉冲，解释成"声音"。

经典反证：用力揉眼睛会压迫视神经，产生的是标准动作电位，但因为走的是视神经通路，大脑依然报告"看到闪光"（**光幻视**），而不是触觉。

**强度不靠幅度，靠频率：** 光线越强 → 单位时间脉冲越多；不存在"这个脉冲更大"这种情况。

**空间位置靠拓扑：** 视网膜每个位置映射到 V1 对应区域（视网膜拓扑映射），激活不同位置即知不同空间点。

**重要例外：** 轴突上传的是电信号，但突触之间传递靠**神经递质（化学信号）**。这用于调制兴奋性、学习记忆、情绪，但**不用于区分感官类别**。

## 1.2 视觉通路全流程：从光子到逻辑判断

整体链路分六大阶段。核心前提：**眼睛只是镜头+传感器，真正"看见"发生在皮层。**

### 阶段 1｜光学成像（纯物理，还没有神经信号）

角膜（主要屈光）→ 房水 → 瞳孔（虹膜调光，类似光圈）→ 晶状体（睫状肌调节焦距）→ 玻璃体 → 视网膜

成像为**倒立、缩小的实像**。视神经穿出眼球处无感光细胞，形成盲点。

### 阶段 2｜视网膜：光电换能

视网膜不是底片，是一层会做**初步预处理**的神经组织。

| 细胞类型 | 功能 |
|---|---|
| 视杆细胞 | 弱光、暗视觉，只辨明暗，分布在周边 |
| 视锥细胞 | 强光、明视觉，三色感知（L/M/S），集中于中央凹 |

**工作细节（反常识）：** 静息状态下感光细胞**持续释放递质**；光子到来反而使其**超极化**、减少递质释放。这与绝大多数神经元相反。

信号接力：**感光细胞 → 双极细胞 → 神经节细胞（RGC）**，中间由**水平细胞、无长突细胞**做横向抑制，实现边缘增强与对比度提取。

**RGC 是视网膜的最终输出单元**，产生标准动作电位；其轴突汇聚成视神经。

> 到此，光彻底变成神经脉冲，离开眼球。

### 阶段 3｜视交叉 → 外侧膝状体 LGN

**视交叉：** 鼻侧纤维交叉、颞侧纤维不交叉 → **左半视野全部投射到右脑，右半视野全部投射到左脑**。

**LGN（丘脑视觉中继核团）不是简单中转站**，它会：
- 接收皮层**反向反馈**；
- 调节信号增益（注意力强时放大目标、压制背景）；
- 分层处理（小细胞通路管颜色细节，大细胞通路管运动与粗轮廓）；
- 抑制噪声。

LGN 输出经**视辐射**投射到枕叶 V1。

> 旁支：少量纤维不经 LGN，去上丘（眼动反射）、顶盖前区（瞳孔对光反射），不参与有意识识别。

### 阶段 4｜V1 初级视皮层（枕叶，Brodmann 17 区）

Hubel & Wiesel 的经典发现：

| 细胞类型 | 响应特性 |
|---|---|
| 简单细胞 | 特定方向的线段、边缘 |
| 复杂细胞 | 特定方向、可在一定范围内移动的边缘 |
| 超复杂细胞 | 线段端点、拐角 |

V1 提取的基元：**边缘、朝向、明暗边界、空间频率、粗立体视差**；并完成左右眼整合、视网膜拓扑映射。

> ⚠️ **V1 只看到边缘和明暗，它不知道这是什么物体。** 它不会输出"苹果"，只检测"这里有一条红色弧形边缘"。

### 阶段 5｜两条并行高级通路

V1 之后，视觉信息分成两条**并行**信息流（同时处理，互不阻塞）：

**① 腹侧通路（What）**：V1 → V2 → V4 → IT 下颞叶
- V2：整合轮廓、简单形状、边界填充
- V4：**颜色、复杂形状、曲率**
- IT：**整体物体特征**；梭状回面孔区 FFA 识别人脸，旁位置体区 PPA 识别场景
- → 回答：**这是什么？**

**② 背侧通路（Where/How）**：V1 → V2 → MT(V5) → 顶内沟
- MT：**运动检测**（方向、速度）
- 顶叶：**空间位置、距离、手眼协调**
- → 回答：**在哪里？怎么伸手去拿？**

### 阶段 6｜联合皮层：意义、记忆、逻辑、决策

这是本系列讨论着墨最多的部分，单独展开于 1.3。

## 1.3 阶段 6 深度展开：思考在电信号层面究竟怎么发生

**核心前提：不存在一个单独的"CPU 神经元"。思考是大量神经元集群的同步放电。**

**信息不是存在单个神经元里，而是"一组神经元的共同发放模式"代表一个概念。**

### 涉及的分工网络

| 脑区 | 职责 |
|---|---|
| 下颞叶 IT → 海马 | 记忆检索 |
| 颞上回 / 角回 | 语义、语言编码 |
| 背外侧 PFC | 逻辑推理、工作记忆 |
| 腹内侧 PFC | 价值、偏好、情绪评估 |
| 前扣带回 ACC | 冲突监测、错误检测 |
| 顶下小叶 | 多感官融合 |
| 杏仁核 / 伏隔核 | 情绪打分、奖励预期 |

### 第一步：特征绑定 + 多模态整合（角回为核心节点）

IT 传来的碎片（红、圆、曲面）+ 背侧传来的坐标距离 + 触觉的光滑 + 嗅觉的果香，在顶颞联合区做**特征绑定**。

**底层机制：神经同步振荡（γ 波，30–80Hz）**
- 同步放电 = 这些特征属于同一个东西
- 不同步 = 属于不同物体

> 此步只完成"绑定知觉"，**还不等于知道它叫"苹果"**。

### 第二步：调取长期记忆（海马 + 颞叶新皮层）

1. 当前知觉模式作为**检索探针**
2. 海马做**模式完成（pattern completion）**：给部分特征即召回完整记忆
3. 匹配成功 → 激活对应**概念集群**，包含：名字、属性（水果/可食/甜）、过往场景、关联情绪

> **记忆不是存图片，是存放电模式。** 回忆苹果不是读取一个图像文件，而是重新复现当初那套脉冲发放。

匹配失败 → 只能感知外形，无法命名、不知用途。

### 第三步：语义理解（角回、语言网络）

角回是视觉与语言的桥梁：把客体表征转换成词语与抽象概念。提取的抽象属性超出当前画面（苹果 → 属于水果 → 大多可食用）。

**电信号层面：** 代表「苹果视觉特征」的集群与代表「苹果」「水果」「可食用」的集群之间存在强突触连接，一组放电驱动另一组。**突触权重 = 学习到的关联强度**，由反复激活（LTP）强化而来。

### 第四步：逻辑推理与工作记忆（背外侧 PFC）

**工作记忆的本质：神经元集群持续维持放电**，把信息在线保存数十秒。这是大脑的"黑板"。

以"两个苹果，大的更甜"为例：
1. 工作记忆同时维持两套客体表征（两组集群持续放电）
2. 读取属性：A 尺寸大，B 尺寸小
3. 调取规则集群【更大 → 更成熟 → 更甜】
4. 比较推理，生成新结论表征：A 更甜

> **人脑逻辑不是串行布尔运算，而是并行的向量相似度运算**——集群间的兴奋/抑制突触互相调制。
> ACC 在此持续监测冲突（如"方形苹果"的特征矛盾），激活后标记异常。

### 第五步：价值评估与抉择（vmPFC + 杏仁核 + 多巴胺通路）

- vmPFC：整合奖励、成本、情绪，计算主观价值
- 杏仁核：快速情绪评估（危险/愉悦）
- 中脑多巴胺 / 伏隔核：预期奖励

候选选项（拿大苹果 / 拿小苹果）对应的神经表征**互相侧向抑制**，激活强度最高者胜出。

> **决策的本质：多个候选表征的神经竞争。**

### 第六步：输出

获胜决策从 PFC 输出到运动皮层 → 锥体束 → 脊髓 → 肌肉。

也可以**抑制运动输出**：前额叶压制运动通路，决策仅停留在内心判断。

### 本层的信息载体总结

所有脑区传递的仍是同一种动作电位。**信息不在脉冲本身，在三件事：**

1. **哪些神经元集群在放电**（群体身份 = 编码内容）
2. **发放频率**（激活强度 / 置信度）
3. **脉冲间的时序与同步**（绑定特征、建立关联）

以及第四个隐藏维度：

4. **突触权重**（长期存储的关联强度 = 大脑的"参数"）

### 自上而下的预测（容易被忽略但极关键）

高级脑区持续反向投射到 V4、V1 甚至更上游。大脑不是被动接收图像，而是**持续预测接下来会看到什么**：
- 输入与预测匹配 → 误差信号小
- 不匹配 → 产生预测误差信号，重点处理意外信息

**注意力，本质就是这套自上而下反馈选择性增强部分神经元的响应。**

### 时间线

| 时间 | 事件 |
|---|---|
| 0–20 ms | 视网膜光电转换 |
| 20–50 ms | LGN → V1，提取边缘 |
| 50–150 ms | V1→V2/V4/MT→IT+顶叶，识别与定位 |
| 150–200 ms | 多模态绑定、海马检索，识别概念 |
| 200–350 ms | PFC 工作记忆、逻辑比较、价值评估、决策竞争 |
| >350 ms | 输出内心结论或运动指令 |

## 1.4 关键澄清：单个脉冲不携带任何信息

**必须区分两类电信号：**

| 类型 | 位置 | 特性 |
|---|---|---|
| **感受器电位** | 视网膜感光细胞内 | **模拟信号**，幅度连续可变，编码光强与波长 |
| **动作电位 spike** | RGC 往后：视神经、LGN、V1、V4、IT… | **事件脉冲**，波形幅度固定，只有时间戳 |

> 也就是说：**你直觉中"电信号有强弱"的那个东西，存在于感光细胞里；一旦进入神经传导，就变成了全或无的离散事件。**

**大脑怎么知道这组脉冲 = {红, 圆, 曲面, 50cm}？**

**机制一：标记线 + 神经元选择性调谐。** 存在三组互相独立的神经元集群：
- V4 颜色调谐集群 → 只在红光输入时高频放电 → "红色"
- V1/V4 曲率集群 → 只对弧形边缘响应 → "曲面"
- MT/顶叶深度集群 → 只对 50cm 对应的视差调谐 → "距离"

通俗类比：**一个控制面板，红灯组亮 = 红，圆弧灯组亮 = 曲面，距离灯组亮 = 50cm。灯泡闪动的电脉冲全都一样，"哪一排灯在闪"才代表属性。**

这就是**群体编码（population coding）**。

**机制二：特征绑定。** 视野里同时有红苹果和蓝杯子，红色集群和弧形集群同时激活，大脑怎么知道"红色属于苹果"？→ γ 相位同步（见 1.5）。

**机制三：拓扑映射。** 保留空间位置坐标。

**机制四：概念关联。** 绑定后的集群送 IT/海马，靠 STDP 学到的权重联动激活"苹果"概念。

> **纠正一个自然误区：**
> ❌ 错误：脉冲里编码了 `{color:red, shape:circle, dist:0.5m}` 这样的数据包
> ✅ 真实：**没有数据包，没有字段。表征就是"哪一堆神经元正在发放"这个状态本身。**

---

## 1.5 γ 相位绑定：分组靠相位，不靠频率

**结论：不是靠两组振荡频率不同来区分物体。两组可以是同一个 γ 频段（如 40Hz），区分靠「相位」。**

```
时间轴： 0ms     12.5ms   25ms    37.5ms   50ms
γ波：    ┌─┐     ┌─┐      ┌─┐      ┌─┐
苹果spike:  ●       ●        ●        ●    （卡在波峰，相位 0°）
杯子spike:     ●        ●        ●        ●（卡在波谷，相位 180°）
```

- γ 振荡（局部场电位 LFP）：一大群神经元集体活动叠加出的慢波动，作为**全局节拍器**
- 神经元的 spike 倾向锁定在 LFP 的特定相位发放
- **相位对齐 = 同一物体；相位错开 = 不同物体**

**类比：** 两个乐队都按 120 拍/分钟演奏（同频率）。苹果乐队在重拍敲鼓，杯子乐队在弱拍敲鼓。节拍器频率一样，但敲击的**时间位置（相位）**不同，你能听出是两组。

### 三个要点

1. **相位是相对关系**，不是单个 spike 自带标签。是集群之间的时序对齐关系作为绑定信号。
2. **LFP 提供公共时钟**：LFP = 节拍器波形，spike = 鼓手敲击，相位 = 敲击落在周期哪个位置。
3. **相位槽位有限**。40Hz 可划分 0°/90°/180°/270° 四个槽，最多并行区分约 4 组物体——**这恰好对应人脑并行知觉客体上限与工作记忆组块上限**。物体一多，绑定易出错（视觉拥挤现象）。

### 数学形式

给定脉冲时间 $t$、振荡周期 $T$：

$$\phi = 2\pi \cdot \frac{t \bmod T}{T}$$

判断两个脉冲是否同一客体：

$$|\Delta\phi| < \theta \quad (\text{如 } 30^\circ)$$

### 学术地位

γ 同步绑定是**特征绑定假说（Feature Binding Hypothesis，Singer & Gray）**，证据很强，是解释"绑定问题"最经典的理论，但**并非已完全破译的生物底层代码**。

# 第二部分 与 LLM 的对照

## 2.1 相似之处

| 维度 | 说明 |
|---|---|
| **本质** | 都是**归纳式模式匹配**，不是内置公理系统的演绎引擎。人脑靠突触权重做相似性检索；LLM 靠海量文本学到 token 共现统计 |
| **分层特征提取** | 人脑 V1→V4→IT；Transformer 低层学语法、高层学概念 |
| **注意力机制** | 人脑自上而下反馈调节；Transformer 自注意力动态加权 |
| **分布式表征** | 人脑靠神经元集群放电模式；LLM 靠高维隐向量。都不是一对一标签查表 |
| **序列生成** | 内心语言串行流动 ≈ 自回归逐 token 生成 |
| **预测机制** | 预测处理理论 ≈ 训练目标"预测下一个 token" |

## 2.2 根本差异

| 维度 | 人脑 | LLM |
|---|---|---|
| **底层载体** | 神经元 + 突触；脉冲时序 + 化学递质 | 硅晶体管；0/1 数字；浮点向量 |
| **编码方式** | 脉冲时序 + 群体编码 | 固定长度浮点向量，无时间维度 |
| **长期记忆** | 修改突触权重（LTP/LTD），终身在线学习 | 固化在权重，**推理阶段完全冻结** |
| **工作记忆** | PFC 神经元持续放电，容量 4±1 组块 | 上下文窗口，本质是"重读历史" |
| **感知** | 原生多感官，具身，有感受质 | 图像编码为向量拼接，**无真实体验** |
| **推理范式** | System1 直觉 + System2 逻辑，双系统 | 单一统计联想，模仿推理文本模式 |
| **错误检测** | ACC 原生冲突监测 | 无原生机制，易自信地输出幻觉 |
| **价值与动机** | 多巴胺/情绪/生存驱动，内生目标 | 无内生目标，被动响应 prompt |
| **学习方式** | 持续在线，少样本即可学会 | 推理不可学，需重训或塞上下文 |

**最关键的一条：**

> LLM 没有真正的**工作记忆**。上下文窗口只是"把过去内容再读一遍"，不是在网络内部维持激活状态，且有硬上限。
> 而人可以在思考时记住中间结论，不需要反复重读全部历史。

# 第三部分 第一次尝试：照人脑重设计 AI

## 3.1 七模块架构

**核心原则：学习 = 修改连接权重；信息 = 集群脉冲发放；两套记忆分离；具身感知；预测处理为核心范式；内置冲突监测与价值系统。**

```
① 感知换能层
② 初级特征皮层（V1/V2/V4/MT）
③ 多模态联合皮层（特征绑定）
④ 海马记忆系统（情景 + 概念分离）
⑤ 前额叶（工作记忆 + 推理 + ACC）
⑥ 边缘价值网络（杏仁核 / 多巴胺 / vmPFC）
⑦ 运动输出 + 全局自上而下预测反馈环路
```

### ① 底层单元：LIF 脉冲神经元

替代 Transformer 的"线性+激活"：
- 输入脉冲累积膜电位
- 超过阈值 → 发射脉冲 → 重置 + 不应期
- 膜电位随时间自然衰减（模拟漏电）

编码方式：**发放频率 + 时序**，而非固定长度向量。

### ② 突触：STDP 可塑

**这是与 LLM 最大的区别之一。**

- 前神经元放电后极短时间内后神经元也放电 → **LTP，权重增强**
- 时序反过来 → **LTD，权重减弱**

> LLM：权重训练时一次性优化，推理冻结。
> 类脑：**推理运行中权重可持续微小更新**，实现持续在线学习。

同时区分**兴奋性/抑制性突触**，靠二者平衡实现侧向竞争（多个想法互相抑制，最终选出一个决策）。

### ③ 初级皮层

- 原生并行多感官传感器，各做换能 → 脉冲流（不是像素数组）
- V1 检边缘朝向、V4 检颜色曲率、MT 检运动
- 网络拓扑用**视网膜拓扑映射**
- 内置**横向抑制**（对应水平细胞）
- **自带自上而下反馈**：高层下发预测，低级只上传**预测误差**

### ④ 多模态绑定：γ 同步

属于同一物体的特征集群强制同步发放，不同物体相位错开。

### ⑤ 海马系统：两套记忆分离

- **海马（情景索引）**：模式完成（局部召回完整）、模式分离（区分相似场景）；新体验先存海马
- **颞叶新皮层（长期语义）**：储存成熟概念集群；随重复体验慢慢巩固固化

遗忘 = 主动削弱突触，不是简单覆盖。

### ⑥ 前额叶：真正的工作记忆

一组神经元集群**持续自维持放电**，在线保持中间结论，容量 4±1，不需要重读全部历史。

推理机制：概念集群间的兴奋/抑制链式激活；ACC 持续监控表征冲突。

### ⑦ 价值网络

- 杏仁核：快速情绪评估
- 多巴胺：预期奖励
- vmPFC：综合成本收益算主观价值

决策：候选表征侧向抑制竞争，激活最强者胜出。

### ⑧ 输出闭环

决策 → 执行器（机械臂/虚拟身体）→ 动作 → 新感官反馈 → 回到感知层。

**感知 → 皮层 → 记忆 → 推理 → 抉择 → 动作 → 新感知。这就是具身认知。**

# 第四部分 关键追问与路线转折

## 4.1 能不能用 0/1 表达这套机制？

**能，但要区分两种路线。**

**关键洞察：spike 本身就是天然的 0/1 事件——某时刻神经元放电=1，不放电=0。**

但信息**不在单独的 0 或 1，而在：哪个神经元、在哪个时间点出现这个 1**。

### 编码方式

给每个神经元分配 ID，记录事件：`(神经元ID, 时间t, spike:1)`，无 spike 隐式记 0，不必存。

```
苹果（R 和 C 相位对齐，0°）
t=0ms：   R=1, C=1
t=25ms：  R=1, C=1
t=50ms：  R=1, C=1

杯子（B 和 L 相位 180°）
t=12.5ms：B=1, L=1
t=37.5ms：B=1, L=1
```

**"红色"这个语义不来自比特本身，来自"R 集群出现 1"。相位关系 = 多条序列里 1 的时间差。**

### 两条实现路线

| | 路线 A：GPU 软件仿真 | 路线 B：神经形态芯片 |
|---|---|---|
| 硬件 | 冯诺依曼，内存全是 0/1 | Loihi / 天机芯 |
| 0/1 含义 | 仿真产物，需逐时间步遍历全部神经元 | **硬件总线上真实的事件信号** |
| 效率 | 大部分神经元是 0 仍需全量计算 | 只有 spike 时才通信，几乎不耗电 |
| 时钟 | 固定时钟强制全网络更新 | 事件驱动，来了才算 |

> **本质差别**：GPU 用 0/1 **模拟** spike 事件，硬件本身不懂"脉冲"；神经形态芯片的 spike **就是**硬件事件。

### 与 LLM 的编码范式差异

- **LLM**：语义压缩为固定维度浮点向量，一次性矩阵乘法，**几乎没有时间维度**。是**静态快照**。
- **类脑 SNN**：跨时间分布的稀疏 0/1 事件序列。是**动态脉冲短视频**。

### 一个必然的限制

数字仿真必须把时间切成离散片（dt）。生物时间连续，仿真 spike 只能落在离散格子里。dt 越小越精准，但算力内存暴涨。原型一般取 0.1~1ms 足够演示 γ 相位绑定。

## 4.2 能不能直接用物体的特征词当 token？

**可以，但要补上关键的「客体槽」，否则会撞上特征混淆。**

### 原生 LLM 的问题

输入 `[红, 弧形, 蓝, 直线]`，自注意力只知道这些 token 共现，**没有独立的"客体绑定寄存器"**，无法区分"红+弧形是一组，蓝+直线是另一组"。

> **这就是 binding problem，也是 LLM 幻觉的重要来源之一。**

### 改造方案：显式客体槽

```
<obj0> 红 <obj0> 弧形 <obj0> 曲面 <obj0> 距离50cm
<obj1> 蓝 <obj1> 直线 <obj1> 杯状 <obj1> 距离70cm
```

`<obj0>`、`<obj1>` 就是抽象的相位槽。自注意力天然倾向在同一 obj 标记内绑定。

**这就是结构化绑定（Structured Binding），类脑计算里非常重要的数学框架。**

> 人脑用**脉冲相对相位**当动态分组标签；符号 token 系统可以用**绑定标记/向量叠加**当分组标签。功能等价，载体不同。

### 这个方案最大的短板

**你直接喂特征词 token，等于预先人工帮系统做完了特征提取。**

- SNN：原始像素 → 自动提取边缘、颜色、深度 → 自动绑定
- Token 方案：人先看图片，人工提炼出 `红、圆、曲面` 再丢进去

若图像里出现从未见过的新物体：人脑/SNN 自动提取新特征并绑定为新客体；Token 模型必须你手动发明新特征词。

### 折中路线（实践推荐）

```
视觉编码器（CNN/SNN，自动从图片提特征）
    ↓
结构化绑定模块（叠加客体槽，完成分组）
    ↓
映射到语言 token，送入大模型推理
```

兼顾自动感知与显式绑定。

### 符号接地问题

token `红` 只是文本符号，知道"红常和苹果共现"，但**没有绑定到原始感官体验**。
人脑的"红"与视网膜视锥、V4 颜色神经元的脉冲绑定在一起。

**SNN：符号 ↔ 感官脉冲双向绑定（接地）；纯 token：符号只与其他符号关联（悬空）。**

### 延伸：Transformer 自主归纳的「词语特征」到底是什么

有人会问：Transformer 的注意力本来就在算词与词的关系，训练中会自主归纳特征组合，那还需要外部特征提取吗？

**需要区分它归纳的是什么。**

```
文本语料 → token embedding → 自注意力计算 token 间关联
                                 ↓
                      学到的是「共现统计」：
                      苹果 常与 红/圆/甜 一起出现
```

> **它学到的是文字符号之间的关系，不是现实物理物体的感官特征。**

### 计算主体：符号关系 vs 实体关系

这是两者最根本的分野：

| 项目 | LLM / VLM | 本架构 |
|---|---|---|
| **计算主体** | **Token 嵌入**（文字/图像离散 token） | **`<obj>` 实体实例**（附带多感官特征向量） |
| **关系类型** | 符号统计关联（token 共现） | **物理空间关系、因果关系、属性绑定** |
| **接地性** | 符号悬浮，只在语言潜空间 | 锚定真实传感器（视觉、触觉、3D 激光）测量信号 |
| **实体归属** | 靠注意力隐式推断，容易实体混淆 | 属性天生挂在 obj 槽，**归属显式确定** |

**所以准确的说法不是"它算词、我们算感官"，而是：**

> **LLM 计算符号（token）之间的语义关联；**
> **本架构计算携带多感官属性的实体实例之间的物理与因果关系。**

关键在**实体作为载体**：感官特征不是单独互相运算，而是先归属到某个 `<obj>`，再由实体之间发生关系。

```
<obj0> 苹果 ——[在]——> <obj1> 盘子
   ↑ 携带：视觉红 + 弧形 + 触觉光滑
```

> **关系的主体是物体实例，感官特征只是物体的属性。**

## 4.3 特征是怎么被拆解出来的？

**人眼不会直接吐出文字 token。`<obj0> 红 <obj0> 弧形` 是我们事后用符号翻译出来的描述，大脑内部没有这些文字。**

```
光子
 → 视网膜：视锥产生模拟电位，RGC 转脉冲流，保留空间拓扑
 → LGN：降噪、增益，维持拓扑
 → V1：提取边缘、朝向
 → V4（腹侧）：颜色调谐集群 + 曲率集群
 → MT/顶叶（背侧）：双眼视差 → 距离
 → γ 相位同步：三组集群绑定为同一客体
 → IT：匹配概念记忆，激活"苹果"
 → PFC：翻译成内心语言"红苹果，50cm远"
```

**最关键的区分：**

| 阶段 | 输出 |
|---|---|
| **底层感知**（视网膜→V1→V4→顶叶） | 并行独立脉冲集群，**没有文字，没有 token** |
| **高层语言**（前额叶） | 才把神经客体表征翻译成语言符号 |

**`红`、`弧形`、`苹果` 这些词是认知的产物，不是视觉输入的原始输出。**

> 对比多模态模型：图像编码器把像素一次性变向量，向量里混合了颜色形状距离，**天然没有分离的独立特征通道，也没有动态绑定机制**。
> 人脑是**先拆分独立特征，再通过相位绑定合并成客体**，顺序完全相反。

## 4.4 为什么分组一定要用 spike？电信号没有别的维度吗？

**核心：spike 不是数学上唯一的分组方案，也不是绝对最优；它只是生物在肉体、化学、物理约束下演化出的最优工程方案。**

分组本质只需要：**在众多并行信号间，建立一个动态、临时的关联标记，把属于同一物体的特征打上同一归属标签。**

### 逐一检验其他方案

**方案 A：用振幅（电压高低）分组**
- ❌ 致命：振幅同时要编码**特征强度**（红色饱和度本身占幅度）
- **两个信息互相干扰，必然混叠**

**方案 B：用不同载波频率分组**
- ❌ 大量并行载波互相干扰、拍频噪声
- ❌ 神经元膜是漏电模拟器件，难稳定维持大量不同频率连续振荡，功耗极高

**方案 C：专用分组信号线（类似 `<obj0>` 通道）**
- ❌ 视野里 N 个物体就要 N 套独立总线
- **神经元布线量指数爆炸，大脑体积扛不住**

**方案 D：连续模拟波的相位**
- 理论可行！但 ❌ **轴突长、膜漏电，模拟信号远距离严重衰减、波形变形，相位直接乱掉**

### spike 的真正优势（全部来自生物硬件约束）

| 优势 | 说明 |
|---|---|
| **全或无，抗噪声** | 超过阈值就产生固定波形；轴突上可不断再生，跨脑区稳定传递。模拟信号传远即变形 |
| **天然时间戳** | 离散事件有精确时间点，相位只需比较事件时间差，神经元电路易实现 |
| **事件驱动，极省电** | 绝大多数神经元多数时间静默；人脑 860 亿神经元仅约 20W |
| **原生支持 STDP** | 学习规则依赖脉冲先后与时差，模拟电压难判断"到达时序差" |
| **信号维度解耦** | **频率**编码特征强度，**相位/时序**编码分组归属，互不抢占 |

### 最重要的是这句话

> ❌ 不是"数学上只有 spike 才能实现特征绑定"。
> ✅ 是：**在生物细胞膜、离子通道、轴突这套湿件上，spike 是综合噪声、功耗、布线、长距离通信、在线学习所有约束后的最优解。**

**在不同硬件上，最优解会变：**

- **硅基数字系统（GPU）**：完全不需要 spike，直接用**向量结构化绑定（SBP）**，在向量空间完成客体打包，更高效
- **神经形态芯片（模拟生物硬件特性）**：spike 又成为优选，复用事件驱动、稀疏通信

## 4.5 多感官专家模型方案

**这是整场讨论的第一个重要转折：既然 spike 只是湿件最优解，硅基上就该换一种载体。**

### 提议的架构

```
原始图像 → 视觉专家 → [颜色向量，轮廓向量，曲面向量，距离向量]
触觉传感 → 触觉专家 → [硬度向量，粗糙度向量，温度向量]
                        ↓
              【结构化绑定模块】 ← 关键新增
              按客体归属打包，生成 Obj0 / Obj1
                        ↓
              中央逻辑模型（LLM类）
```

### 与传统多模态大模型的本质区别

普通多模态 LLM（如 GPT-4V）把图片整体编码成一个**混合向量**——轮廓、颜色、深度全揉在一起，没有拆解开的独立特征通道，缺少显式客体绑定。

本方案：**感官专家主动拆分独立特征 + 单独绑定模块打包客体**，刚好补上 binding problem 这一短板。

### 优点

1. **模块化可扩展**：加分听觉/嗅觉只需新增专家，不动全局
2. **特征解耦减少幻觉**
3. **训练成本可控**：小专家可分开预训练，无需一次性端到端大网络
4. **天然支持具身交互**：视觉+触觉绑定到同一客体，建立符号接地

### 工程难点

1. 绑定槽数量有限，物体过多会错乱
2. **跨感官特征空间对齐**（最难的，见 4.6）
3. 动态客体追踪（物体移动时维持身份）
4. 多感官同步成对数据极度稀缺

---

## 4.6 真正的难点是「表征格式」

> **这是整场讨论中最关键的一次认知收敛。**
> 感官专家只解决"信号→特征向量"；真正的瓶颈是：**逻辑模型的内部计算机制决定它偏好哪类向量格式，我们要把多感官特征打包成这种格式。**

### Transformer 原生的偏好

它处理**序列** `[emb₀, emb₁, …]`，每个 emb 同维度，靠自注意力算两两关联。

✅ 它喜欢：
1. **维度统一**（视觉触觉全部投影到公共维度）
2. **带归属标识**（能看出属于 obj0 还是 obj1）
3. **长度可控**（对应并行客体上限）
4. **可比较相似度**

❌ 它不擅长：
- 维度不一致的原始向量（视觉 1024 维、触觉 64 维不能直接拼）
- 无归属标签的独立特征堆（直接触发特征混淆）
- 高分辨率稠密特征图（太长，算力爆炸）

> **一句话：逻辑模型想要的不是"一大堆独立特征"，而是「客体为单位的结构化序列」。**

### 两种可行格式

**方案 A：特征-token 序列（推荐做基础原型）**

每个"特征 + 客体归属"映射成一个固定维度 embedding：

```
emb_obj0_red       # obj0，红色
emb_obj0_curve     # obj0，弧形曲面
emb_obj0_dist50    # obj0，距离50cm
emb_obj0_smooth    # obj0，光滑（触觉）
emb_obj0_hard      # obj0，硬质（触觉）
emb_obj1_blue      # obj1，蓝色
...
```

归属编码两种实现：
1. **显式拼接投影**：`emb = Project(concat(feat_vec, obj_id_vec))`
2. **结构化绑定**：`emb = feat_vec ⊙ obj_basis_vec`（逐元素乘法）

✅ 细粒度可查询（能单独取出"这个物体的颜色"）
⚠️ 序列随客体数线性增长

**方案 B：客体整体 embedding**

```
[ObjEmb0, ObjEmb1]   # Combine(红,弧形,曲面,50cm,光滑,硬)
```

✅ 序列极短，开销低
⚠️ **细粒度特征被压缩融合，丢失独立访问能力** → 与传统多模态大模型同样的短板，易产生幻觉

### 必须增加的一层：跨感官投影头

```
视觉特征 → MLP投影 ┐
                   ├→ 统一公共表征空间（d=1024）
触觉特征 → MLP投影 ┘
```

训练目标：让**同一客体的跨感官特征在公共空间内形成可关联的分布**。

**这一步就是在解决符号接地：视觉表征和触觉表征绑定在同一个客体上。**

## 4.7 感官向量空间为什么天然不兼容？

**结论：不是数学上永远不能兼容，而是两个独立训练的生成器，在没有额外约束的前提下，几何与统计分布完全对不上。**

### 理论支撑

**① 神经网络表征的正交旋转不变性（最核心）**

一个网络学到的特征空间，可以做**任意正交旋转而不改变预测性能**。

> 网络学到的是**向量间的相对距离**，但**坐标系的朝向是随机的**——由随机初始化、数据顺序决定。

两个独立训练的网络，坐标系朝向完全独立随机。**即使都是 512 维，语义对应的向量在空间上可以相距极远。**

**② 流形假设**

- 视觉数据：2D 空间光强网格，**空间静态分布**
- 触觉数据：压力时序信号，**接触式时序分布**

属于不同数据域，学到的向量分布在不同低维流形上。两个流形嵌在同一欧氏空间但**不重合**。

**③ 语义不是内生于维度，而由训练任务定义**

视觉把"形状"拆成曲率、朝向；触觉把"软硬"拆成形变率、压力弛豫。**特征分解维度本身就不是一套体系。**

### 必须破除的误区

> ❌ "都输出 512 维，空间就兼容了"
> ✅ **维度只是容器大小，不是坐标系语义。容器一样，里面语义坐标可以完全错位。**

二维极简例子：
- 视觉：红=(1,0)，蓝=(-1,0)  → X 轴是颜色
- 触觉：硬=(0,1)，软=(0,-1)  → Y 轴是硬度

维度都是 2，直接混用毫无意义。

### 所以「对齐」必须靠训练强制

目标：
- 同一物体同步采集的视觉+触觉样本，投影后**距离尽量近**
- 不同物体样本，**距离尽量远**

这就是 CLIP 的跨模态对比学习思想。

### 与人脑的对照

婴儿刚出生时视觉与触觉表征也不对齐。靠**大量"一边看一边摸"的具身交互**，通过突触可塑性慢慢对齐。

> **人脑也不是天生对齐的，是靠具身经验训练出来的。**

## 4.8 跨感官投影层：MLP 投影头 + 对比学习

> **后文更新**：投影头的训练方式在本节确立；它在工程落地中的**漂移问题与冻结锚点重训姿势**、以及 `<obj>` 绑定后加法的数学边界，见 **9.1、9.2**。

> **这一节把 4.7 的结论落到工程实现上。**
> 4.7 说了"独立训练的两个网络向量空间天然不兼容"；这一节说**怎么把它们对齐**，以及**对齐会丢什么**。

### 三个感官专家的原生状态

| 模态 | 典型维度 | 编码内容 |
|---|---|---|
| 视觉专家 | 128 | 色彩、轮廓、纹理 |
| 触觉专家 | 64 | 硬度、粗糙度、接触形变 |
| 3D 激光 | 256 | 曲面几何、空间坐标 |

**三者维度不同、数值分布不同、度量含义不同。直接算相似度毫无意义。**

### MLP 投影头结构

```
输入（原生感官特征，维度可变：64 / 128 / 256）
   ↓
Linear1 + LayerNorm + GELU
   ↓
Linear2 + LayerNorm + GELU
   ↓
Linear_out → 固定 D 维公共语义向量（如统一 128 维）
   ↓
L2 归一化（模长 = 1）
```

**三个关键设计点：**

| 设计 | 原因 |
|---|---|
| **每个模态独立一套 MLP** | 视觉一套、触觉一套、激光一套。**不是共享同一个 MLP**——各自负责把自己模态的坐标变换到公共空间 |
| **输出强制同维度** | 所有 MLP 输出维度一致（128） |
| **L2 归一化** | 向量模长归一，余弦相似度才等价于向量距离 |

> MLP 本质上做的是**非线性坐标变换**。它要学的是：视觉看到苹果的弧形红色曲面、触觉摸到苹果的光滑硬质表面，经过各自投影后，在公共空间里**距离很近**。

### 对比学习怎么约束这个空间

只有 MLP 没有损失函数，投影出来的空间毫无语义。**靠跨模态对比学习训练全部投影头。**

**样本构造：**

| 类型 | 构成 | 目标 |
|---|---|---|
| **正样本对** | 同一物体的不同感官观测（同一苹果的视觉 + 触觉） | 投影后距离**尽量近** |
| **负样本对** | 不同物体的不同感官（苹果视觉 + 杯子触觉） | 投影后距离**尽量远** |

**损失函数：InfoNCE**——最大化同实体跨模态相似度，最小化不同实体相似度。

> 用一句话概括训练目标：
> **只要来自同一个物理物体，不管视觉、触觉还是激光点云，投影后都靠近；不是同一个物体，就互相远离。**

⚠️ **重要区分：这个公共空间不是语言语义空间。**
它是**多感官物理实体语义空间**——向量距离衡量"物理上是不是同一个/同一类物体"，不是文字语义相似度。

### 高维映射会不会丢精度

**一定会有信息损失。但要分两种：可控的、要规避的。**

**① 可控的压缩损失**

256 维压到 128 维，必然丢一部分细粒度信息。丢的是什么？

| 丢掉 | 保留 |
|---|---|
| 该模态独有的细粒度冗余（点云微小曲面噪声、触觉传感器抖动） | 识别物体身份、类别、核心物理属性的关键信息 |

> **设计目标就是丢模态专属噪声、保留跨模态共享的实体信息。这是有意的压缩。**

**② 灾难性的信息丢失（必须规避）**

训练不好时，关键物理属性会被抹掉：

| 案例 | 后果 |
|---|---|
| 红苹果与绿苹果投影后向量几乎重合 | 颜色信息丢失，无法区分 |
| 硬塑料杯与软硅胶杯向量靠近 | 材质区分消失 |

**三条规避手段：**

1. **样本多样性**：同一类别要覆盖不同颜色、材质、尺寸
2. **加辅助预测头**：从投影后的公共向量反向预测颜色/材质/尺寸，用属性预测损失强制保留关键特征
3. **维度不要压太狠**：物体种类和属性多时，32 维太危险；128 / 256 维更稳妥

### 三个工程边界

**① 投影头是轻量小网络**

相比感官专家，MLP 参数量很小。**感官专家冻结后，可以单独训练这套投影层**——完全契合 5.6 的流水线分阶段训练。

**② 推理阶段只做前向**

没有训练，计算开销极低。

**③ 新增模态只加一个新头**

以后要加嗅觉：新增一套独立 MLP 投影头，用同样的对比学习接入公共空间，**原有模块完全不动**。

### 4.8.1 常见误区：维度一致 ≠ 空间对齐

> **一个非常自然但错误的想法：**
> "既然大模型每个维度不是唯一对应某种特性，那我人为要求所有感官专家的输出维度一致、取最大值，是不是就不需要训练 MLP 投影头了？"

**答案：先把被混在一起的两件事拆开。**

| | 问题 | 谁来解决 |
|---|---|---|
| **维度数一致** | 视觉 128、触觉 64、激光 256，形状不一样 | 补零 / 截断，**不需要训练** |
| **空间对齐** | 两个空间里同一物理含义的轴，朝向、尺度、分布都不同 | **必须靠投影头或联合训练** |

"取最大值"解决的只是第一行。

**为什么维度一致了仍然不能直接放一起**

假设视觉和触觉都被凑成 128 维：

```
视觉空间：第 3 维 = 红色强度
触觉空间：第 3 维 = 表面粗糙度
```

**两边的第 3 维含义完全无关。** 独立训练的网络，坐标轴朝向是随机的（4.7 的正交旋转不变性）。即使形状都是 128，两个空间之间隔着一个**未知的旋转 + 拉伸 + 非线性变换**。

> 直接算余弦相似度，等于在两套互不相干的坐标系里比角度——**结果是噪声，不是语义**。

**拿"取最大值"具体验一遍**（视觉 128 / 触觉 64 / 激光 256，统一到 256）：

| 操作 | 问题 |
|---|---|
| 触觉 64 → 补零到 256 | 补出的 192 维是**空信息**，但在余弦距离里会被当成方向参与计算，**反而干扰相似度** |
| 视觉 128 → 扩展到 256 | 扩展部分无信息；硬塞高维不增加实质特征 |
| 以激光 256 为基准 | 只是形状匹配，**空间错位原封不动保留** |

> 补零/截断能让两个向量"长得一样长"，**但不能让它们"说同一种语言"**。

**投影头到底在消除什么**

| 要消除的错位 | 纯维度对齐能否消除 |
|---|---|
| 坐标轴朝向不同（**旋转**） | ❌ |
| 各维度拉伸比例不同（**尺度**） | ❌ |
| 特征关系中含**非线性**成分 | ❌ |
| 不同模态数值**分布偏移** | ❌（可部分靠归一化缓解，但不彻底） |

**想省掉投影头，只有三条路径**

| 路径 | 做法 | 代价 |
|---|---|---|
| **A. 从头联合训练** | 各专家一开始就在共享空间里一起训 | **失去模块化流水线**，专家无法独立训练与替换（5.6 那一套不成立） |
| **B. 手工约定维度含义** | 硬编码"第 i 维=颜色、第 j 维=硬度" | 就是 4.2 的**人为定义特征**，新物体要手工加维度，自动感知能力丧失 |
| **C. 用线性投影替代 MLP** | 错位较简单时，单层线性映射足够 | 更轻，但**仍是一个需要训练的投影层** |

> **省投影头的前提：要么牺牲模块化，要么牺牲自动感知。没有"维度凑齐就白送一个公共空间"的免费午餐。**

### 4.8.2 投影之后，苹果的视/触/嗅/味真的能连在一起吗

**核心结论**

✅ **在训练收敛、样本充足、损失设计合理的前提下：能。**
但要加两个限定：

1. 这个"绑定"是**统计学习出来的向量邻近关系**，不是数据库式的硬编码键值对；
2. 它不是万能的——**只能学到训练数据中出现过的跨感官关联**，没见过的新组合会失效。

**原理：MLP 负责坐标变换，对比学习负责把"同一个物体"编码进距离**

当模型充分收敛，同一个苹果的四种感官向量会在公共空间聚在一小块邻域：

```
苹果视觉 → MLP → Vₐ ┐
苹果触觉 → MLP → Tₐ ├─ 在公共空间聚成一小簇
苹果嗅觉 → MLP → Sₐ │
苹果味觉 → MLP → Gₐ ┘
```

于是只看到视觉信号 Vₐ，检索邻域就能带出这个物体的触觉、嗅觉、味觉原型：

> **看见红苹果的曲面，自动关联"摸起来光滑、闻着果香、尝起来酸甜"。**

> 本质：MLP 做坐标变换，对比学习把"属于同一个物理物体"**编码成向量距离**。

**四个不能神化的边界**

| 边界 | 说明 |
|---|---|
| **必须有配对样本** | 训练集里从未出现"苹果视觉 + 苹果嗅觉"成对样本，模型无法凭空建立这个关联。人脑可以靠单次体验快速建立（快速突触可塑性），这套架构需要新增样本再微调投影头 |
| **要区分「同类」与「同一实例」** | 类别层面：红/绿苹果都聚到苹果原型簇；实例层面：obj0 的感官向量聚在一起，obj1 的聚在旁边。**需要在损失里同时约束这两项** |
| **存在混淆风险** | 桃子的视觉向量投影后可能靠近苹果的嗅觉向量。呼应 7.3/7.4 的实体漂移与解体问题 |
| **相似度不足以保证正确** | 单纯向量相似度杜绝不了混淆，**显式 `<obj>` 槽是兜底机制**，二者需配合 |

**与 LLM 多模态融合的核心区别**

| 项目 | 本架构 | LLM / VLM |
|---|---|---|
| 绑定对象 | **物理实体的感官观测信号**（像素、压力、气体传感器） | 文字 token、图像 patch token（符号空间） |
| 绑定依据 | 是否来自同一个物理物体实例 | 文本共现统计 |
| 底层载体 | 多感官物理语义向量空间 | 语言潜空间 |
| 推理时 | 底层用向量相似度完成关联，语言只是读出头 | 全转 token 序列，靠自注意力建立关联 |

### 4.8.3 训练数据必须同步采集吗

**结论：不强制物理同步。可以分开采集、人工配对，但两种方式能学到的东西不一样。**

| 对比项 | 同步实时采集 | 分开采集 + 人工配对 |
|---|---|---|
| **样本含义** | 同一实例 `<obj>` 在同一时刻的多感官观测 | 同一**类别**不同实例、不同时间的观测 |
| **能学到的** | 既能学**实例绑定**（这一个苹果的视觉绑它自己的触觉），也能学**类别原型绑定** | **只能学类别原型层面**的跨感官关联；学不到单实例的时序联动 |
| **采集成本** | 高：多传感器协同、固定被测物、同步触发 | 低：可分批、分设备、甚至不同地点，后期在库里关联 |
| **主要噪声** | 同步误差、运动模糊、传感器耦合 | **标签错误是最大风险**：把桃子嗅觉错配给苹果视觉，直接污染对比损失 |
| **泛化到动态场景** | 能（物体形变、摔碎、被咬） | 不能，只能学静态类别属性 |

**关键区分：实例级正样本 vs 类别级正样本**

| 类型 | 构造 | 学到什么 | 能否人工拼接 |
|---|---|---|---|
| **实例级（强样本）** | 桌上这一个苹果，先拍照、再触摸、再闻 | **同一个物体，视觉与触觉绑定**。支撑物体追踪、形变、解体等动态推理（7.4 摔碎杯子） | ❌ 无法靠跨实例拼接生成，**必须真实同步采集** |
| **类别级（弱样本）** | 苹果 A 的图 + 苹果 B 的触觉，人工标"同属苹果" | **苹果这一类，视觉簇与触觉簇在公共空间靠近** | ✅ 完全可以分开采集后配对 |

**推荐的混合训练策略**

| 阶段 | 数据 | 目的 |
|---|---|---|
| **预训练** | 大量**类别级拼接样本**（低成本） | 快速搭起基础公共空间：苹果视觉 ↔ 苹果触觉 |
| **微调** | 少量**实例级同步样本**（高价值） | 学会同一 obj 的多感官同步变化，支撑追踪/形变/解体 |

**三个风险**

1. **标签污染**：人工配对标错，InfoNCE 损失被严重干扰，公共空间对齐失效 → 需标签清洗与校验
2. **学不到实例专属属性**：只用跨实例拼接，学不到"这个苹果有一处磕碰（视觉），磕碰处摸起来凹陷（触觉）"这类**局部对应**
3. **分布偏移**：分开采集时环境不一致（视觉强光、触觉常温、嗅觉密闭容器），各模态分布差异变大，对齐更难 → 需数据增强

### 4.8.4 单感官输入能不能识别物体

**核心观点：不需要同一时刻拿到全部感官信号。仅凭单一感官，也能识别物体，只是置信度降低。**

人类的例子：只看一眼能认出苹果；闭眼只用手摸也能判断；只闻到果香也能推断附近有苹果。

> 大脑不是必须激活全部感官才能识别。多感官的价值是**提升置信度、消除歧义、补充属性**，不是识别的前置必要条件。

**架构内部怎么实现**

推理时每个模态可以**独立前向**：

```
仅视觉图像 → 视觉专家 → 视觉 MLP → 公共向量 V
                                    ↓
                        与原型库检索 → 判定"苹果"，置信度 0.72
```

多感官同时在时，是**融合多个投影后的公共向量**再检索：

| 输入 | 典型置信度 |
|---|---|
| 仅视觉 V | 0.72 |
| V + T 融合 | 0.94 |

**必须分清：训练阶段 vs 推理阶段**

| 阶段 | 要求 |
|---|---|
| **推理（上线）** | ✅ 支持任意单一感官独立输入 |
| **训练（学习）** | ⚠️ 仍需要多感官配对样本，才能建立跨感官的公共空间关联 |

> 类比人脑：小时候**曾经同时看过、摸过、闻过苹果**（相当于训练时的配对样本）。学会之后，以后只看一眼就能认出。
> **不是要求每次看见苹果都要同步触摸**，而是过去的**学习过程**里建立过关联。

**单感官识别的三个短板**

| 短板 | 说明 |
|---|---|
| **歧义易错** | 红色圆形物体，可能是苹果也可能是红塑料球。加上触觉（果面细纹 vs 光滑）可快速消歧 |
| **属性是先验非实测** | 仅视觉时，软硬/气味来自原型库的先验（苹果默认带果香、偏硬），**不是当前实例的实时观测** |
| **实例追踪更脆弱** | 遮挡、形变时实体漂移风险更高；多感官可互相校验，稳定 `<obj>` 绑定 |

### 4.8.5 和 Transformer 在训练、推理上到底差在哪

**核心结论：不是"把文本 token 换成感官向量，其余照搬"。**

输入向量只是表层替换。**表征载体、状态管理、训练目标、推理范式全部不同**。可以复用的只是底层算子（MLP、LayerNorm、余弦相似度、交叉熵、GPU 矩阵运算）。

**推理阶段对比**

| 项目 | 传统 Transformer | 本架构 |
|---|---|---|
| **基本计算单元** | Token（文本/图像 patch） | **`<obj>` 实体实例**（挂载多感官公共向量） |
| **状态保存** | 全部上下文压进 KV 缓存，是**不断增长的 token 序列** | 独立**实体工作记忆池**（3~5 个激活 obj），保存 3D 坐标、属性、身份 |
| **计算逻辑** | 自注意力：算 **token 与 token** 的关联；逐 token 串行生成 | 向量相似度 + 关系推理；**实体之间并行**做空间/因果运算，无强制自回归 |
| **多模态处理** | 全部转 token 塞进同一注意力模块，视觉 patch 与文字混排 | 各感官专家独立编码，各自 MLP 投影进公共空间；**实体 slot 是顶层绑定载体** |
| **空间与时序** | 无原生 3D 坐标、无实体同一性；时序只是阅读顺序 | 原生内置 3D 坐标、遮挡、同一性、形变时序 |
| **输出** | 默认 token 序列，必须序列化 | 实体状态更新 / 动作指令 / 向量 / 文字（文字仅上层读出头） |

> Transformer 的自注意力本质是**一维序列上 token 间的相似度计算**，它是为序列设计的。
> 本架构的核心是**实体对象的状态与实体间关系**，面向场景中的物体集合，不是一维序列。

**训练范式对比**

| 项目 | 传统 Transformer | 本架构 |
|---|---|---|
| **训练目标** | 预测下一个 token，学序列统计共现 | 两层：①跨模态对比学习对齐感官向量；②实体关系/因果预测学物理规则 |
| **训练方式** | 端到端整体预训练，微调靠 LoRA/全参，**模块高度耦合** | **流水线分阶段**：专家 → 投影头 → 推理模块；模块可独立更新、热替换 |
| **样本形式** | 连续 token 序列 | 成对多感官样本（正/负对）+ 场景实体关系样本，**不组织成一维序列** |
| **记忆与可塑性** | 知识固化在权重；新增知识需微调，有灾难性遗忘 | **两类记忆分离**：规则进权重，实例进外部实体库；新增物体不改主干 |
| **符号接地** | 基于文本/图像 patch 统计，符号悬浮 | 数据来自传感器物理观测，**向量锚定真实信号** |

**最容易犯的误区：把感官向量直接塞进 Transformer**

❌ 即使把感官向量喂进 Transformer，它依然会把这些向量当成**序列里一个个独立 token**。

- 它不会自动理解"这一组向量都属于同一个 `<obj>`"
- 不会天然维护 3D 位置与物体同一性
- 只会算序列位置上的相似度，**没有实体 slot 绑定机制**

> 例：把苹果视觉向量、触觉向量当两个 token 丢进去 —— 模型会混淆：这是两个独立物体，还是同一个物体的两种感官？**实体绑定问题立刻回来了。**

**折中方案：实体架构 + 顶层轻量 Transformer**

```
底层：感官专家 + MLP 投影 + <obj> 实体槽 + 公共语义空间（主体）
上层：把实体向量送入轻量 Transformer，做长程因果推理 / 自然语言输出
```

> 此时 Transformer **只是上层推理/语言输出模块**，底层感知与实体表征仍是实体架构。

### 本节总结

**投影层做了什么：**

> 为每一类感官专家配备**独立 MLP 投影头**，通过**跨模态对比学习（InfoNCE）**约束，把异构感官特征映射进同一个固定维度公共语义空间。
> 映射过程存在**可控的压缩损失**：损失函数设计合理时，优先丢弃传感器噪声、保留物体身份与核心物理属性；但维度设置过低或样本不足时，会发生**关键物理特征被抹除**的风险。

**5 个子问题的结论：**

| 子节 | 问题 | 结论 |
|---|---|---|
| **4.8.1** | 统一维度就能省掉投影头吗？ | ❌ 维度一致 ≠ 空间对齐。省投影头只能靠联合训练或手工定义维度，两条都要付代价 |
| **4.8.2** | 能真的把视/触/嗅/味连在一起吗？ | ✅ 能，但这是**统计邻近关系**，依赖成对样本，且需 `<obj>` 槽兜底防混淆 |
| **4.8.3** | 必须同步采集吗？ | 不必。**类别级可异步拼接**，但**实例级动态绑定必须同步采集** |
| **4.8.4** | 单感官能识别吗？ | ✅ 能，只是置信度低、有歧义。**训练要配对，推理不必配对** |
| **4.8.5** | 只是把 token 换成向量吗？ | ❌ 表征载体、状态管理、训练范式、推理范式全不同，只有底层算子可复用 |

## 4.9 特征向量长什么样，人类怎么看懂它

> **两个问题：这些特征向量具体是高维数组吗？如果是，人怎么读懂里面每个数字的含义？**

### 先明确：是高维浮点向量，但不是 token 转换来的

| | Token Embedding | 本架构感官特征向量 |
|---|---|---|
| **来源** | 文字/图像 patch 经模型投影 | **传感器原始信号**（像素、点云、压力采样）经感官专家编码 |
| **编码对象** | 符号语义 | 物理测量：曲率、光谱、粗糙度、3D 坐标、法向、反射率 |
| **数学形式** | N 维浮点数组 | N 维浮点数组（**形式相同，来源与含义完全不同**） |

> 举例：视觉专家输出 128 维数组（编码色彩、饱和度、轮廓）；触觉输出 64 维（编码软硬、光滑度）；3D 激光输出 256 维（编码曲面几何）。
> 这些向量挂到 `<obj>` 实体槽上，作为该实例的属性。

### 人类为什么不能直接读懂

**原始高维向量本身人类无法直接解读。** 一长串浮点数，没人能一眼看出"这代表红色弧形苹果"。

**更关键的一点：不要幻想每个维度都有独立清晰的人类可读含义。**

| 误解 | 事实 |
|---|---|
| 第 7 维 = 红色，第 23 维 = 圆形 | **绝大多数维度是混合编码，分布式表征** |

> 这和 LLM embedding 是同一个麻烦：维度是分布式编码，不是"一个维度一个特征"。

### 三种把向量翻译成人能理解的形式

**方式一：向量解码器（投影回感知空间）**

训练一个小型反向解码器，输入特征向量，还原对应感知信号：

| 向量类型 | 解码输出 |
|---|---|
| 视觉特征 | 重建局部图像片段 |
| 触觉特征 | 输出粗糙度/硬度数值 |
| 3D 几何 | 重建物体局部曲面点云 |

> 用途：校验这个向量到底编码了什么感官信息。

**方式二：向量检索 + 原型库映射（架构主推方案）**

公共语义空间里预存**类别原型向量**（【苹果】【杯子】）。计算实例向量与各原型的余弦相似度：

```
obj0 特征向量 ↔ 【苹果】原型：相似度 0.92
obj0 特征向量 ↔ 【杯子】原型：相似度 0.21
                    ↓
              判定：obj0 是苹果
```

原型附带人类可读标签（`类别:苹果 / 颜色:红 / 形状:圆形`）。

> ✅ **这就是本架构的方案：向量运算在底层，可读标签只是附加的人类接口，推理本身不依赖标签文字。**

**方式三：降维可视化（PCA / t-SNE / UMAP）**

把几百维压到 2D/3D 画散点：物理属性相近的向量自然聚成一团（苹果一团、杯子一团）。

> 用途：**仅限研发调试**观察聚类效果。降维会丢大量信息，**不能用于运行时推理**。

### 边界说明

| 边界 | 说明 |
|---|---|
| **维度不可逐位解读** | 分布式编码，单维不对应单一特征 |
| **优势不在"读懂数字"** | 而在于：绑定显式 obj 槽 / 锚定物理观测 / 可与原型库检索映射成标签 |
| **和 LLM 的差别依旧在接地** | LLM embedding 同样不可直接解读，区别仍是符号接地 |

### 一句话总结

> 特征向量**确实是高维浮点向量，但不是文字 token 转出来的 embedding，而是传感器信号经感官专家编码得到的**。
> 人类不能直接读懂一串浮点数；需要借助**原型检索、解码器、降维可视化**三类工具，才能把向量翻译成人能理解的物体属性描述。

## 4.10 统一语义空间里，思考能力从哪来？

**结论：公共语义空间只是表征舞台；思考不是空间自带的，而是一套作用在这个空间上的运算规则 + 记忆系统 + 目标驱动的迭代循环。**

### 空间里存什么

| 类型 | 内容 |
|---|---|
| **客体表征** | obj0 绑定一组属性 |
| **属性表征** | 红、弧形、光滑、硬度、距离 |
| **关系表征** | 在…里面、比…更大、可被拿起 |

**结构化绑定支持双向操作：**

$$Obj0 = \sum_i Bind(\text{attr}_i,\ obj0\_base)$$

可以正向组装，也可以反向拆解。**原生 LLM 的混合 embedding 做不到可逆拆解，这是"想象、假设推理"的核心能力。**

### 思考的五类基础算子

| 算子 | 说明 | 对应人脑 |
|---|---|---|
| **① 检索** | 拿到表征，在空间中找邻近向量 | 联想记忆 |
| **② 比较** | 计算向量距离判断属性差异 | 大小/软硬判断 |
| **③ 组合与解构** | 属性↔客体双向绑定，可组装新客体（想象） | 创造性想象 |
| **④ 时序预测** | 在语义空间运行世界模型，推演物理因果 | 心理模拟 |
| **⑤ 目标驱动搜索** | 设定目标表征，搜索状态变换路径 | 规划 |

> 原生 LLM 只是"下一个 token 预测"；这套是**在语义表征空间做状态运算**。这是本质区别。

### 系统组织

```
感官专家 → 投影 → 公共语义表征（带 obj 绑定）
                    ↓
          【工作记忆】保存当前客体序列（容量有限）
                    ↓
          【推理引擎】执行五类算子，多步迭代
                    ↓
          【长期记忆库】向量数据库
```

**工作记忆是关键约束**：同一时刻只能保留少量客体表征，推理引擎反复读取、修改、迭代。

> 思考不是一次前向传播，而是**多步迭代、不断改写工作记忆**。
> 原生 LLM 是单轮前向，没有独立的可读写工作记忆——这正是它推理易错的根源。

### 训练目标：不能只做文本预测

需要**多任务联合损失**：
1. 跨模态对比损失（对齐感官）
2. 绑定/解构损失（保证可逆拆合）
3. 世界模型预测损失（因果与物理）
4. 问答损失（语言 ↔ 语义空间双向映射）

> **语言只是语义空间的读出接口，不是思考本身。**
> 传统 LLM 反过来了：思考发生在 token 序列空间，所有感知都被压成文字符号。

## 4.11 这套架构现实中有人做出来了吗？

**结论：零件齐全，局部原型大量存在；完整一体化系统至今没有成品。**

### 三层现状

**① 理论地基：早已存在**
- 结构化绑定 SBP / Semantic Pointer Architecture（Eliasmith）
- Conceptual Spaces 概念空间理论

**② 独立模块原型：大量论文**

| 模块 | 代表工作 |
|---|---|
| Object-centric slot | SceneBind、NSI（Neural Slot Interpreter）、OC-CLIP |
| 跨模态公共空间 | CLIP 系 |
| 显式工作记忆 + 世界模型 | Mimir、KARMA |
| LLM 高层规划 | 各类具身 Agent |

但各自都缺环：
- SceneBind：视觉+音频+语言，**缺触觉、缺工作记忆迭代、缺世界模型**
- NSI：**只有视觉**，高层推理弱
- Mimir/KARMA：LLM+记忆，但底层是传统场景图，**不是连续向量语义空间+可逆绑定**

**③ 完整端到端系统：没有**

### 为什么完整版难产（差距藏在耦合处，不在单模块）

1. **多感官同步对齐数据稀缺**——大部分 object-centric 只做"视觉+文本"，真实"同时看+摸"的大规模数据集很少
2. **可逆绑定在大规模高维噪声下不稳定**——仿真里很美，真实相机噪声一进来反向解码就有误差。Slot 方法是近似绑定，**非严格可逆**
3. **工作记忆与语义空间深度耦合难**——现有方案多是外挂式（感知输出结果存记忆，LLM 读取），不是推理引擎**直接在语义向量空间读写客体**
4. **世界模型与语义空间融合难**——现有世界模型多在像素/潜空间预测下一帧，而非在客体属性语义空间预测抽象属性变化
5. **多任务联合训练冲突**——梯度互相干扰，单项容易，全部联合很难

### 两条路线的分野

| | 神经符号 AI | 本方案（连续向量公共语义空间） |
|---|---|---|
| 表征 | 图、本体、离散谓词 | 全程稠密向量 |
| 优点 | 逻辑严谨 | 感官可接地 |
| 缺点 | 符号接地弱，原始信号难转符号 | 可逆性与稳定性工程难 |

> 本方案属于「神经表征 + 组合绑定」，介于纯 LLM 与传统符号 AI 之间，是当前认知 AI 的前沿探索方向。

## 4.12 大模型输出一定要是文本吗？

**结论：完全不必然。文本只是最成熟的读出通道之一，语言只是众多输出端口中的一个。**

**这是整场讨论的第二个重要转折。**

### 内部表征 vs 输出读出头

- **思考发生在公共语义向量空间**
- **输出只是在同一表征上接不同读出头**：

| 读出头 | 输出 |
|---|---|
| 文本头 | token 序列 |
| 动作头 | 关节控制 / 运动规划序列 |
| 目标头 | 目标状态表征（留在空间继续迭代，不转文字） |
| 情绪/内感受头 | 内部价值向量，调制注意力与偏好 |
| 想象头 | 视觉潜空间（内部模拟画面） |

> 语言头和动作头是**并行、平等的分支**。人伸手拿苹果，不需要先在心里默念"我要伸手"。

### 现状与短板

现有工作（RT-2、VoxPoser、Dreamer、Genie）已做非文本输出，但大多仍是**文字做中间媒介**：LLM 先输出 `["伸手","抓取"]`，再另用模型翻译成动作。

**不是直接从语义表征读出动作。** 这与人脑不同。

### 情绪/感受在这套架构里是什么

**不是魔法，是一套内部估值向量。**

公共语义空间里每个客体表征可附带价值维度：
- 苹果 → 正向价值（可食、高奖励）
- 刀片 → 负向价值（危险、高代价）

情绪子系统的作用：
1. 调节注意力权重（危险物体自动抢占工作记忆）
2. 给候选目标打分排序
3. 调制搜索策略（紧急时快速简化推理）

> **感受不是外部输出，是系统内部状态。** 就像人感到害怕不一定说话，只是注意力被捕获、身体准备逃跑。

### 目标是什么

**不是文字 `"拿到苹果"`，而是语义空间里的一个期望状态表征。**

推理引擎 + 世界模型的任务：找一系列状态变换，把**当前表征**推向**目标表征**。

全程可以零文字：只有当需要"让人类看懂思考过程"时，才开启文本读出头。

### 为什么大家默认输出文本

**工程惯性，不是认知必然：**
1. 文本数据海量易得，next-token 损失好训练
2. 是人最方便的交互与调试接口
3. 早期大模型定位就是对话助手

代价：**整个模型被迫把所有内部思考映射到 token 这一个媒介**，引入符号接地与动作中转的额外开销。

## 4.13 向量推理比 token 推理快吗？

**结论：动态多客体场景快得多；纯文本场景不一定；关键差别在「状态是否显式」。**

### 用户的直觉是对的

自回归 token 推理：每生成 1 个 token，都要把**全部上下文重新塞进 Transformer**，重算全部注意力。

$$\text{每步复杂度} = O(N^2), \quad N = \text{上下文长度}$$

> 每多一个字，代价都在涨。长上下文天生笨重。

### 向量架构快在哪

**① 工作记忆是可读写状态存储，不是把所有历史摊成序列**

- Token 架构：场景、历史、客体信息**全部平铺成一条长 token 序列**，没有独立"场景状态变量"
- 向量架构：场景保存在**显式工作记忆** `[obj0, obj1, obj2, obj3]`，推理迭代是**原地修改属性向量**

**每一步只更新变化的客体，不变的直接复用。**

复杂度不再随历史文本长度爆炸，而**绑定在并行客体数量 K 上（很小，4~8）**。哪怕交互几百步，工作记忆长度基本不膨胀。

**② 推理粒度是客体/属性，不是字符**

推演"苹果能不能放进杯子"：token 架构要翻译成长串文字再算注意力；向量架构直接取两个尺寸向量做一次比较算子。

**③ 世界模型直接更新物理状态**

苹果移动 → 视觉专家更新 obj0 位置向量 → 世界模型预测下一时刻位置。不需要编码成 token 再解码。

### 三个必须承认的"但是"

**① 硬件不匹配**

GPU 是为**稠密矩阵乘法与注意力**优化的。SBP 的绑定运算（循环卷积/逐元素乘法）在 GPU 上并不比 attention 加速得好。

> 算法复杂度低 ≠ 现有硅硬件上跑得快。需要专用神经形态硬件才能释放优势。

**② 纯文本任务不一定更快**

写短文、闲聊：需要"向量表征 → 文本读出头翻译成 token"，多了一层转换开销。原生 LLM 在这种场景更直接。

> 优势集中在**具身感知、动态场景、多物体因果模拟**。

**③ 迭代次数不一定更少**

向量架构是**迭代状态推演**。每步便宜，但复杂规划仍要多轮搜索。只是**每步成本不再随历史膨胀**。

### 核心复杂度对比

设 K 个客体，每客体 M 个属性：

| 架构 | 输入长度 | 单步复杂度 | 随交互步数增长 |
|---|---|---|---|
| 自回归 Token | N 持续增长 | $O(N^2)$ | **是，会爆** |
| 向量空间 | ≈ K×M，固定 | $O((KM)^2)$，K 很小 | **否，稳定** |

### 两种推理循环的本质差异

```
token 循环：
  全部上下文 token → Transformer → 下一个 token → 追加 → 再次送 Transformer
  （旧信息重复参与全部注意力计算，大量冗余）

向量状态循环：
  当前工作记忆 [obj0, obj1] → 推理引擎 → 更新 obj0 属性 → 写回工作记忆
  （不变的 obj1 直接复用，只更新变化部分）
```

> **Token 自回归的最大缺陷，就是把「状态」压进平铺的 token 序列，没有独立可读写的场景状态。**

> 补充：State Space Model（SSM）也是在 token 体系内为解决这个痛点而生，但它仍是序列潜向量，**没有显式客体绑定、没有拆解开的独立属性**。

## 4.14 三大工程难点：算力、可塑性稳定性、同步绑定工程化

> **3.3 只列出了名字，这一节逐个拆开。**
> 而且要说清一件事：**这三者不是三个独立难题，它们互相纠缠、互为因果。**

### 难点一：算力——事件驱动的稀疏性碰上稠密硬件

**问题在哪**

| 事实 | 数字 |
|---|---|
| 人脑神经元 | 约 860 亿 |
| 人脑突触 | 约 100 万亿 |
| SNN 的理论优势 | **事件驱动**：只有放电的神经元才产生计算 |

**但 GPU 的物理结构是稠密 SIMD**——它必须把所有神经元、所有时间步展开成规则的矩阵运算，**稀疏性在硬件层面无法转化为实际加速**。

**数量级估算**

```
时间离散化 dt = 1ms
1 秒 = 1000 个时间步
100 万神经元的网络，1 秒需要 10^9 次神经元状态更新
```

> 对比：同样规模的 ANN，一次前向只是 1 次矩阵乘。
> **SNN 的时间维度把计算量放大了 1000 倍，而稀疏性省不回这个开销。**

**为什么难**

- 稀疏计算需要**寄存器级别的条件跳过**，GPU 的 warp 执行模型做不到细粒度跳过
- 每个神经元需要维护膜电位、每个突触需要维护 trace，**状态常驻显存**
- 生物是"连续时间 + 异步事件"，数字系统是"离散时间步 + 同步时钟"，**底层不同构**

**候选解法**

| 方向 | 做法 | 成熟度 |
|---|---|---|
| **神经形态芯片** | Loihi 2 / TrueNorth 等，原生事件驱动 | 硬件已存在，**规模远小于人脑** |
| **稀疏算子** | 事件驱动稀疏计算、条件计算 | 研究阶段 |
| **自适应时间步** | 大步长 / 事件触发更新 | 牺牲时间精度 |
| **只仿真关键层** | 不追求全脑规模，只对绑定层做脉冲仿真 | 可行，但不完整 |
| **混合架构** | 感知用 SNN 思路，推理用稠密向量 | **本架构实际采用** |

> **诚实结论：本架构其实是"绕开"了这个难题，不是解决了它。**
> 它不追求 SNN 全仿真，改用稠密向量 + 显式状态，**是以算法结构换取算力友好，代价是放弃了生物脉冲时序的完整保真度。**

### 难点二：可塑性稳定性——在线学习与遗忘的悖论

**问题在哪**

STDP 的本质是"根据突触前后神经元的放电时间相关性调整权重"，但这要求：

```
每个突触维护一个 eligibility trace（可塑性历史标记）
```

| 规模 | 状态开销 |
|---|---|
| 100 万突触 | 100 万份 trace 状态，需实时读写 |
| 万亿突触（人脑规模） | 不可行 |

**更致命的是灾难性遗忘**：在线更新时，学新物体直接覆盖旧概念的表征。

**为什么难——稳定性-可塑性困境**

| 倾向 | 后果 |
|---|---|
| 学得快（高学习率） | **忘得快**，旧知识被覆盖 |
| 学得稳（低学习率） | **学不进**，新知识留不下 |

> 这是一个**结构性矛盾**，不是调参能消除的。

**人脑是怎么绕过去的**

| 生物机制 | 作用 |
|---|---|
| **突触归一化 / 竞争** | 一个突触变强，同组其他变弱，总预算守恒 |
| **稀疏编码** | 任一时刻只有少数神经元活跃，减少干扰 |
| **双系统** | 海马快速写新事，皮层慢速提炼规律 |
| **睡眠重放** | 离线回放旧经验，巩固而不覆盖 |

**工程上的对应解法**

| 机制 | 生物对应 | 工程实现 |
|---|---|---|
| 权重归一化 | 突触竞争 | L2 归一化、k-WTA |
| 稀疏激活 | 皮层稀疏放电 | 稀疏惩罚、top-k |
| **双系统** | 海马 / 皮层 | **实例库快写 + 权重慢更新**（见 8.6） |
| 离线重放 | 睡眠巩固 | 回放缓冲、生成式重放 |
| 参数保护 | —— | EWC / MAS / 突触重要性标记 |

> **诚实结论：没有彻底解法，只有缓解手段。**
> 本架构的取巧之处在于——**把"实例记忆"移出权重，只让"通用规则"进权重**，从根本上压缩了需要在线更新的参数量。代价是：能被权重吸收的只有通用规律，具体经验永远待在外部库里。

### 难点三：同步绑定工程化——相位是假说，工程难复现

**问题在哪**

γ 同步绑定（约 40Hz，相位周期 25ms）作为客体分组机制，**证据很强，但仍是假说**。

要区分 4 个客体：

```
25ms 周期 / 4 个相位槽 ≈ 6ms 间隔
→ 需要亚毫秒级时间精度才能稳定分辨
```

**三个工程障碍**

| 障碍 | 说明 |
|---|---|
| **离散化误差** | 生物时间连续，数字仿真必须切 dt。dt 越小越准，**但算力内存暴涨**（回到难点一） |
| **噪声漂移** | 脉冲时刻抖动 → 相位错位 → **错误绑定**（苹果的红色绑到背景） |
| **槽位受限** | 相位分辨率有限，实用槽位只有约 4 个，直接限死了并行客体数 |

**工程替代方案对比**

| 方案 | 原理 | 优点 | 缺点 |
|---|---|---|---|
| **相位绑定** | 脉冲相对时间差 | 生物一致，理论最优雅 | 精度要求高、噪声敏感、难大规模 |
| **向量绑定（VSA/HRR）** | 逐元素乘法 / 循环卷积 | **精确可逆、不依赖时间精度** | 容量有限、维度固定 |
| **Slot Attention** | 迭代竞争 slot | 可学习、端到端 | 无可逆性、归属靠学习 |
| **显式槽索引** | 直接分配 obj ID | 最简单直接 | 需要外部监督 |

**本架构的选择**

> 用**向量绑定（逐元素乘法）**替代相位绑定。理由：
> demo 已验证**精确可逆**（`unbind(bind(x,s),s) = x`），且**完全不需要时间精度**。
> 代价：容量比相位方案小，且不能容纳"同频不同相"这种生物式的动态分组。

### 三者如何互相纠缠

**这不是三个并列的问题，而是一条因果链：**

```
算力不匹配
   ↓ 不能大规模跑脉冲时序仿真
   ↓ 只能用向量绑定替代相位绑定
   ↓ 绑定容量受限
   ↓ 工作记忆只能放 3~5 个客体（呼应 7.3 的焦点机制）
   ↓ 与"可塑性稳定性"共同逼出"实例记忆移出权重"的设计
```

反过来：

```
可塑性不稳定
   ↓ 不能在线全量更新权重
   ↓ 必须把实例知识放进外部实体库
   ↓ 需要持久存储 + 检索机制（呼应 7.3 的 3D 场景图）
```

> **所以三大难点的最终产物，是同一套设计决策：**
> **放弃生物保真度 → 换取可工程化的显式结构。**

### 三大难点成熟度总表

| 难点 | 核心矛盾 | 是否有彻底解 | 本架构的处理 |
|---|---|---|---|
| **算力** | 事件驱动 vs 稠密硬件 | 否 | **绕开**：不追求全 SNN，用稠密向量 |
| **可塑性稳定性** | 学得快 vs 忘得快 | 否 | **拆分**：实例记忆出权重，规则才进权重 |
| **同步绑定** | 生物精度 vs 工程可实现 | 否 | **替换**：相位绑定 → 向量绑定 |

### 一句话总结

> 三大工程难点没有一个被真正"解决"，本架构的做法是**用结构设计绕开它们**：
> 不算全 SNN（绕开算力）、把记忆移出权重（绕开可塑性）、用向量绑定替代相位（绕开同步精度）。
> **代价是放弃了生物机制的保真度，换来可运行、可验证、可模块化更新的工程实现。**

# 第五部分 最终成型的架构

经过十一轮推演，架构收敛为下面这一版：**硅基载体 + 公共语义空间 + 显式客体绑定 + 多读出头**。

```
┌─────────────────────────────────────────────────────────────┐
│  ① 感官专家层（分工专精，各自提取独立特征）                    │
│     视觉专家 → 颜色 / 形状 / 距离 / 曲率                      │
│     触觉专家 → 硬度 / 纹理 / 温度                             │
│     （可扩展：听觉、本体觉…）                                │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│  ② 跨感官投影层（MLP 投影头 + 对比学习）                      │
│     把所有感官特征映射到统一公共语义空间 D 维                  │
│     ⚠️ 不做这一步，两个空间天然不兼容（正交旋转不变性）        │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│  ③ 结构化绑定模块（替代 γ 相位槽）                            │
│     bind(feat, slot) = feat ⊙ slot                          │
│     unbind(bound, slot) = bound / slot   （精确可逆）         │
│     把多特征打包成客体 Obj0/Obj1/…，并支持反向拆解            │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│  ④ 工作记忆（容量有限，约 4 组块）                            │
│     保存当前场景的客体表征，原地更新，不做全历史重读            │
│     ➜ 这是速度优势的根本来源                                  │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│  ⑤ 推理引擎（五类算子，多步迭代）                             │
│     检索 / 比较 / 组合解构 / 时序模拟 / 目标搜索               │
│     + ACC 式冲突监测                                          │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│  ⑥ 长期记忆库（向量数据库）                                   │
│     概念模板、属性、关系、因果                                │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│  ⑦ 多读出头（并行、平等）                                     │
│     文本头 │ 动作头 │ 目标头 │ 价值/情绪头 │ 想象头            │
│     ⚠️ 文本只是其中一个，不是必经中介                          │
└─────────────────────────────────────────────────────────────┘
```

## 5.1 核心价值定位：它不是"更强的识别器"

### 先破除一个定位误区

看到这个架构，最自然的反应是问："它能识别物体吗？识别得比 CNN 准吗？"

**这个问法本身就问错了方向。**

物体识别这件事，CNN、SAM、多模态大模型已经做得足够强，**识别是附属能力，不是目标**。

这套架构真正的价值在于：

> 把**思考、推理、因果、规划**的计算媒介，从离散 token 序列，替换成**承载物理客体属性的高维向量**。
> 推理直接在向量空间做客体关系运算，天然面向物理世界的实体与状态变化。
> 语言只是可选的输出读出头。

前面 4.x 的所有推演，最终收敛到的不是"识别得更准"，而是**"思考得更像思考"**。

### 价值点一：推理直接计算向量之间的关系，绕开 token 转译

**Token 范式的问题：**

所有感知信息必须先编码成文本 token 序列。哪怕已经识别出物体，也要翻译成文字描述：

```
"红色苹果，距离50cm，硬质光滑"
```

推理在 token 序列上做统计预测，**实体本身没有独立、稳定的状态载体**。

由此产生三重损耗：

| 问题 | 说明 |
|---|---|
| **状态被平铺** | 实体状态摊在长序列里，每次推理都要重复加载全部上下文 |
| **两次转译损耗** | 属性与位置是文本符号而非连续物理量，做物理推演时需把文字再解析回数值 |
| **实体混淆** | 长上下文里分不清两个苹果，即 binding problem |

**向量范式的做法：**

每个物理实体对应一个独立客体向量 slot，属性（颜色、位置、硬度、尺寸）是向量空间里的独立维度。推理即向量运算：

| 运算 | 实现 |
|---|---|
| **求相似度** | 苹果向量 与 记忆中苹果概念向量的余弦相似度 |
| **做对比** | 苹果尺寸向量 − 杯子尺寸向量，直接得大小关系 |
| **更新状态** | 移动苹果 → 只改 obj0 的位置子向量，其余属性复用 |
| **做组合** | 把新属性绑定到客体，生成新实体表征 |

> ✅ **核心优势：客体是一等公民。**
> 思考的对象就是物理实体本身的向量表征，不需要先翻译成文字。

### 价值点二：对物理世界的理解，天然适配「状态随时间变化」

**LLM 学到的是语言共现，不是物理动力学。**

LLM 知道"苹果掉下来会落地"，是因为文字里经常这么写。它没有内部场景状态，没有客体的位置、质量、摩擦这些连续物理量。当场景动态变化（移动、遮挡、形变），token 很难持续追踪同一个实体。

**本架构的处理方式：**

1. 工作记忆持续维护场景里**每一个客体的完整状态向量**
2. 世界模型作用在公共语义向量空间：输入当前客体向量，预测下一时刻的位置、接触、形变
3. 因果推演直接在实体属性上跑：

```
obj0(苹果) 与 obj1(桌面) 接触
    → 重力向量作用
    → 预测 obj0 位置向量变化
```

> 它理解的不是**描述物理的文字**，而是**物理实体本身的状态表征**。
> 这是它更适合具身智能、机器人、动态场景规划的根本原因。

### 价值点三：与 CNN 是上下游关系，不是替代关系

**CNN / SAM 的定位：从原始像素提取视觉特征。属于「感官专家」模块，是这套架构的输入前端。**

| CNN 能做 | CNN 做不到 |
|---|---|
| 识别像素里哪一块是苹果 | 把视觉特征与触觉特征融合到同一客体表征 |
| 提取视觉特征向量 | 跨时间追踪同一物体的状态变化 |
| 单帧静态识别 | 在特征空间做多步因果推理、规划、模拟未来 |
| — | 维护独立工作记忆，区分场景内多个实体 |

> **CNN = 眼睛；这套公共语义空间架构 = 大脑的客体感知 + 推理 + 记忆系统。**
> 眼睛能认出苹果，但思考、推演、想象、规划，都不在 CNN 里面。

### 三个核心差异化价值（提炼）

| # | 价值 | 说明 |
|---|---|---|
| **1** | **推理原生面向实体，而非文本符号** | 推理介质是绑定了多感官属性的客体向量。支持直接向量运算，消除文本编解码的中间转换开销，避免长上下文重复计算 |
| **2** | **原生支持动态物理场景的实体追踪** | 显式工作记忆保存多个客体的独立状态。移动、遮挡时仅局部更新向量，实体身份持续稳定，不会出现 token 场景里的实体混淆 |
| **3** | **感知、记忆、因果模拟共享同一套语义空间** | 感知输出的客体向量直接送入世界模型做未来预测。表征统一，不存在跨空间转换断层 |

### 也必须承认的四个短板

不能只写优点。这套架构当前的真实短板：

| # | 短板 | 说明 |
|---|---|---|
| **1** | **数值稳定性** | 向量绑定/解绑存在数值噪声，多轮迭代会产生表征漂移；逐元素除法在近零分量处尤其危险 |
| **2** | **自主学习概念未成熟** | 大规模无监督自主归纳概念的方案尚无成熟工程实现，当前仍需预置概念或人工介入 |
| **3** | **硬件不匹配** | 现有 GPU 为 Transformer/token 矩阵运算优化，向量绑定运算（循环卷积/逐元素乘法）没有硬件原生加速 |
| **4** | **语言能力需外挂** | 语言是读出头，想达到 LLM 那种流畅生成能力，需额外的文本读出模块，不能指望它自己涌现 |

### 一句话总结

> 物体识别只是前端感官网络的任务，不是这套架构的目标。
> **它真正的价值，是构建一套以物理实体向量为基础的原生推理系统，摆脱 token 作为思考媒介的限制，让模型直接在实体表征空间进行关系计算与物理因果推演。**

## 5.2 与各路线对照

| | 原生 LLM | 脉冲类脑 SNN | 本架构 |
|---|---|---|---|
| 载体 | 浮点向量 + token | 脉冲时序 | 稠密向量 + 客体槽 |
| 绑定 | 无显式机制 | γ 相位同步 | 结构化绑定 SBP |
| 工作记忆 | 上下文窗口（重读） | PFC 持续放电 | 显式客体槽存储 |
| 输出 | 只有文本 | 运动/内部状态 | **多读出头并行** |
| 硬件友好 | GPU 原生 | 需神经形态芯片 | GPU 可跑（SBP 略低效） |
| 落地难度 | 最低 | 最高 | 中等 |
| 停留问题 | 绑定/接地弱 | 长推理弱 | 可逆性与多任务冲突 |

## 5.3 泛化能力：实例与原型双层表征

> **这一节回答一个必然会被追问的问题：**
> 一个红色苹果和一个绿色苹果，模型会把它们识别成两个不同的 obj，还是同一种？
> 这直接决定这套架构是否具备**泛化（generalization）**能力。

### 核心答案：分两层存储

**实例 obj 与类别概念，必须分成两层独立表征。**

| 层 | 内容 | 例子 |
|---|---|---|
| **场景实例层** | 场景里的**单个具体物体**，唯一 ID | `<obj0>` 红苹果、`<obj1>` 绿苹果 |
| **类别原型层** | **概念模板**，跨实例泛化 | 【苹果】 |

> 红色苹果 = `<obj0>`；绿色苹果 = `<obj1>`
> 它们是**两个不同的实例 obj**，但二者都映射到**同一个类别原型：苹果**。

这与人脑完全一致：眼前两个苹果，你知道这是**两个独立个体**（可以单独拿起红的、不动绿的），同时知道二者都属于"苹果"这一类，共享一套通用属性（圆形、有果皮、可食用、会腐烂）。

### 第一层：场景实例层（瞬时感知）

每检测到一个物理物体，生成**独立实例 obj**，分配唯一 ID：

```
<obj0>：{红色, 圆形, 曲面, 直径8cm,   距离50cm}
<obj1>：{绿色, 圆形, 曲面, 直径7.5cm, 距离60cm}
```

**为什么必须是两个独立 obj？**

因为在物理世界里它们是两个独立物体：可以移动其中一个，另一个保持不动。**实例 ID 用来做场景追踪、实体绑定、动作交互。**

若合并成同一个 obj，机器人就分不清"拿红苹果"和"拿绿苹果"，物理操作直接错乱。

### 第二层：类别原型层（泛化与概念）

每个实例向量都会做**相似度检索**，映射到已存在的类别原型向量：

```
<obj0> 特征向量 → 与【苹果】原型相似度高 → 归类：苹果
<obj1> 特征向量 → 与【苹果】原型相似度高 → 归类：苹果
```

原型向量存储这类物体的**通用不变特征**：

```
【苹果】原型 = {近似球形, 薄果皮, 带果柄, 可食用, 受挤压会形变, 掉落会滚动}
               颜色 → 标记为可变属性，不是类别必需特征
```

> **关键设计：原型向量区分「不变核心特征」与「可变属性」。**
> 苹果的核心是外形结构、材质、物理属性；
> 颜色、大小是**实例可变参数**，不影响类别判定。

### 泛化是怎么实现的

1. 视觉专家提取新物体的多感官特征向量
2. 与公共语义空间里全部**类别原型向量**计算余弦相似度
3. 相似度 > 阈值 → 绑定到已有类别原型
4. 全部原型相似度都低 → 判定为新类别，两种处理：
   - **模式 A**：新建临时原型，持续多次观察、收集多个实例后凝练出稳定原型（类似人脑反复看多了绿苹果，完善"苹果"这个概念，知道苹果可以是红/绿）
   - **模式 B**：标记为未知物体，等待交互试错，收集更多感官数据再更新原型

> **泛化能力的来源：类别原型向量只保留类别不变特征，剥离无关可变属性。**
> 而且原型不是写死的，看到更多不同颜色、大小的苹果，原型向量会慢慢迭代，学会"苹果颜色可以是红、也可以是绿"。

### 与 LLM / 知识图谱的区别

**LLM + 知识图谱：**
"苹果"是文本符号，泛化靠语言统计。要让它知道颜色可变，得**手动写规则**：`苹果的颜色可以是红、绿`。遇到从未在文本里出现过的青色苹果，只能靠脑补。

**本架构：**
原型向量**从大量感官实例自动凝练**。多次看到红/绿/青苹果之后，原型向量在颜色维度上自然学到"这是可变的"——**不需要人工预写文本规则**。

### 两个边界案例

**案例一：长得像苹果，其实是塑料玩具**

```
<obj0> 实例向量：外形向量匹配【苹果】原型
              但触觉向量（硬度、密度）差距巨大
```

公共语义空间融合多感官后，**综合相似度下降** → 判定：外形类似苹果，但类别是【苹果模型】。

> 这正是多感官融合的价值。纯视觉模型在这里几乎必然翻车。

**案例二：苹果切了一半**

实例 `<obj0>` 特征变了（出现切面、半圆轮廓）。

| 判断 | 结论 |
|---|---|
| 实例状态 | **objID 不变**（还是这一个物体），只更新特征向量：完整 → 对半切开 |
| 类别归属 | 与【苹果】原型相似度略降，但核心材质、曲面特征仍在，**仍属苹果类别** |

> **这里必须区分两个完全不同的概念：**
> ① 同一个物体发生状态变化 → **实例 obj 保持 ID 不变，只修改特征向量**
> ② 两个独立物理个体 → **两个不同 obj 实例，映射到同一类别原型**

### 三个尚未解决的难点

| 难点 | 说明 |
|---|---|
| **可变/不变特征自动划分** | 系统需要自动学习哪些属性是类别核心（如有果皮）、哪些只是实例变化（如颜色）。**目前没有完美的自动方案**，可以用对比学习来训练 |
| **相似类别混淆** | 桃子和苹果外形接近，纯视觉难区分，需要触觉、重量等多感官向量提升区分度 |
| **原型漂移** | 持续看到大量变异实例，原型向量会慢慢跑偏（如塑料苹果看多了，原型偏向玩具）。需要设计遗忘机制，控制原型更新速率 |

### 小结

> **实例负责"这一个物体"，原型负责"这一类物体"。**
> 红色苹果和绿色苹果是两个独立实例 `<obj0>`、`<obj1>`，方便机器人分别操作；
> 两个实例的多感官特征向量，在公共语义空间中与类别原型做相似度匹配，共同映射到【苹果】。
> 原型保存类别不变核心特征，颜色尺寸作为可变属性；
> 系统通过观察大量不同实例迭代更新原型，实现泛化，**无需人工预写符号规则**。

## 5.4 推理运行时：一次推理到底发生了什么

> **这一节回答一个非常具体的问题：**
> 这套架构在推理时怎么运作？还会像 LLM 一样，每输出一个新 token 都要把之前所有上下文重新输入一遍吗？
>
> **答案：完全不会。这不是"优化得更好"，是两套根本不同的运行时结构。**

### LLM 的运行时结构（对照基准）

```
所有历史 → 编码成 token 序列 → [t1, t2, t3, ..., tn]
                                    ↓
生成第 n+1 个 token：整条序列进 Transformer
生成第 n+2 个 token：整条序列（含新 token）再进 Transformer
...
```

**KV Cache 只是加速手段，不改变结构：**

| KV Cache 做了什么 | KV Cache 没改变什么 |
|---|---|
| 缓存历史 token 的 Key/Value，避免重复做注意力矩阵乘法 | **每一步仍然"以整条序列为条件"做预测** |
| 降低重复计算 | 显存占用随上下文长度**线性上涨** |
| 让长上下文可跑 | 「上下文越长越贵」这个关系没变 |

> 一句话：**LLM 的推理上下文是一条不断增长的序列，长度就是成本。**

### 本架构的运行时结构

```
          ┌──────────────────────────┐
感知输入 → │ 全局 3D 场景库（休眠）    │  数百实体，只存位姿+ID，不参与计算
          └──────────────────────────┘
                     ↓ 注意力焦点筛选
          ┌──────────────────────────┐
          │ 工作记忆（激活 3~5 个）    │  只有这几个进入实时运算
          └──────────────────────────┘
                     ↓
          ┌──────────────────────────┐
          │ 向量空间关系运算           │  特征相似度 / 空间关系 / 因果
          └──────────────────────────┘
                     ↓
          ┌──────────────────────────┐
          │ 输出：实体状态更新         │  不是 token，是状态与关系
          │      + 动作向量            │
          └──────────────────────────┘
                     ↓（可选末端）
          ┌──────────────────────────┐
          │ 文本读出头 → 自然语言      │  语言只是输出通道
          └──────────────────────────┘
```

### 五步流程

**① 感知输入**

视觉/触觉/激光专家输出特征向量，更新全局 3D 场景库。**大量物体处于休眠状态**——只保留空间坐标与基础原型特征，**不参与实时运算**。

**② 注意力焦点筛选**

只把**关注范围内的 3~5 个 obj 加载进工作记忆（激活状态）**，其余全部休眠。

> 休眠物体：仅保留 3D 坐标 + 实体 ID；注意力切回来时，才重新提取特征、载入工作记忆。

**③ 向量空间推理（核心）**

对激活的 obj 集合直接计算：

| 运算类型 | 具体内容 |
|---|---|
| **特征相似度** | 当前实例 vs 类别原型（是不是苹果） |
| **空间关系** | A 在 B 内部、A 接触 B、A 距 B 50cm |
| **因果/事件** | A 掉落 → A 碎裂；实例同一性置信度下降 |

**推理输出不是 token，而是实体状态更新、新关系、动作向量。**

**④ 工作记忆更新与归档**

- 实体状态直接覆盖/更新 obj 内部属性（如：杯子 → 碎裂为碎片集合，修改实体绑定与置信度）
- **不需要保留一长串历史序列**
- 旧实体放回休眠全局库

**⑤ 语言输出（可选，且只在末端）**

若需要自然语言，**仅在最后一步把当前激活实体向量映射成文本**。

> **语言是输出通道，不是推理媒介。**

### 关键差异：不重读历史

> **推理不依赖历史序列，只依赖「当前激活的少量实体 + 它们之间的关系向量」。**
> 历史信息沉在休眠实体库，按需调取，**不做全量加载**。

### 一个具体例子：杯子摔碎

| | LLM 路线 | 本架构 |
|---|---|---|
| **推理时携带的信息** | 必须把整段描述塞进上下文：`[看到杯子在桌上 → 杯子滑落 → 摔到地上 → 碎裂 → ...]`，每输出一句话都要重读整段 | 工作记忆只激活【桌子、杯子、地面】3 个 obj |
| **推理产出** | 下一步的文本 token | 因果：杯子掉落 → 碎裂；原 obj 同一性置信度下降，生成碎片子 obj |
| **推理后状态** | 上下文继续变长 | 碎片存入场景库；视线移开则休眠，仅留 3D 坐标 |

> 视线再回到地面时：注意力激活碎片 → 调取特征向量 → 继续推理。**不是回读一整段历史。**

### 关键澄清：这里的"并行"指什么

> **⚠️ 必须精确表述，否则容易被误解。**

**不是"GPU 硬件层面的并行 vs 串行"。** Transformer 本身就在用 GPU 做大规模并行矩阵运算。

**真正的差别在「任务逻辑结构」：**

**LLM：硬件并行，但生成逻辑是自回归串行**

```
生成"杯" → 依赖全部上文
生成"子" → 必须等"杯"算完，把"杯"并入上下文再算
生成"摔" → 必须等"子"算完...
```

- ✅ GPU 内部矩阵乘法是并行的
- ❌ **token 生成的步骤无法并行**，只能一个接一个
- 即使 KV Cache 优化，也改变不了「下一个 token 依赖前序所有 token」这个自回归约束

**本架构：实体关系计算在逻辑层面天然可并行**

工作记忆激活【桌子、杯子、地面】三个 obj，需要计算：

```
obj0 ↔ obj1 的空间关系
obj0 ↔ obj2 的空间关系
obj1 ↔ obj2 的空间关系
```

**这三组两两关系互相不依赖，可以一次性全部算完，不需要等 A 算完再算 B。**

所有激活实体的特征相似度、距离、接触关系都可以并行求值。

> **⚠️ 但有一个例外：因果时序推导依然存在顺序依赖。**
> 杯子从桌面下落 → 撞击地面 → 碎裂，这个因果事件有时间先后，这部分推演仍要按时间顺序分步执行。
> 但这不是 token 式的逐字符串行——它是**事件状态的步进更新**，每一步更新的是**实体属性向量**，不是一个个文字符号。

### 严谨表述（可直接作为结论引用）

> 本架构的并行，不是 GPU 硬件层面的并行加速，而是**认知推理逻辑层面**的并行。
> Transformer 本身大量使用 GPU 并行做矩阵运算，但其自回归生成的任务逻辑是串行的：下一个 token 依赖全部前文 token 序列。
> 本架构中，工作记忆池内多个激活实体之间的两两关系、特征匹配计算相互独立，可以并行求解；**仅在处理时序因果事件时，存在状态更新的先后依赖**。
> 本架构没有"逐 token 生成"这个强制串行步骤。**语言输出只是一个可选的末端映射模块，不属于核心推理链路。**

### 这个并行优势的边界

| 情形 | 收益 |
|---|---|
| 激活实体 3~5 个 | 收益最明显，两两关系只有 6~20 组 |
| 激活实体变多 | 两两关系是 **O(k²)**，并行计算量快速上涨 |

> **这正是要用注意力焦点限制同时激活实体数量的第二个原因**（详见后文 7.3：容量上限与算力上限本是同一约束的两面）。

### 代价：不能理想化

| 代价 | 说明 |
|---|---|
| **注意力切换有开销** | 焦点切到休眠物体时，需从 3D 场景库读取并重新加载特征到工作记忆。但这是**按需单点读取**，不是加载全部历史 |
| **长程记忆检索开销** | 调取很久之前的实体因果记录（几天前打碎杯子这件事）需在全局实体库做向量相似度检索。类似 RAG，但**检索对象是实体向量，不是文本片段** |
| **不是完全无状态** | 工作记忆会保存当前激活 obj 的瞬时状态。但状态规模**硬限制在 3~5 个实体**，不会无限膨胀 |

### 一句话总结

| | LLM | 本架构 |
|---|---|---|
| **推理载体** | 文本 token 序列 | 激活实体的向量集合 |
| **每一步读什么** | **整条不断增长的历史序列** | **固定的 3~5 个实体 + 关系向量** |
| **上下文成本** | 随长度线性上涨（KV 缓存也压不住结构） | 与历史长度**基本无关**，只与激活实体数相关 |
| **串行性** | token 生成强制自回归串行 | 关系运算可并行；仅因果时序需步进 |
| **输出** | 下一个 token | 实体状态更新 + 动作向量（文本是可选末端） |

> **LLM 在一条越来越长的句子上下功夫；本架构在一小撮越来越清楚的实体上下功夫。**

## 5.5 训练要点：分阶段课程训练

> **这一节回答：这套架构在训练时需要什么注意事项和要点。**
> 它和 LLM 的训练难点很不一样——LLM 是"一个语言目标一把训到底"，这里是"要对齐多个感官、绑定客体、推演时序、再接多个输出头"。

### 总原则：分阶段课程训练，不要端到端一把训

这是最重要的一条。整套架构如果从随机初始化就把所有损失一起回传，**大概率训不出来**，原因有三个：

| 原因 | 说明 |
|---|---|
| **表征还没对齐，下游无法学习** | 视觉和触觉向量空间错位（4.7 正交旋转不变性），投影层没收敛之前，绑定模块拿到的就是**错位的特征** |
| **梯度互相打架** | 跨模态对齐、绑定解构、状态预测、问答/动作四类损失优化方向不一致（7.1 ②） |
| **槽位和身份没有先验** | 多物体场景下，网络不知道哪个槽对应哪个物体，早期只能乱配 |

> 正确路径是**自下而上逐级固化**：先让感知层有可用特征，再对齐空间，再练绑定，最后才接推理和输出头。**每一级收敛后冻结或半冻结，再训下一级。**

### 五个训练阶段

| 阶段 | 训练对象 | 主要损失 | 要点 | 典型失败 |
|---|---|---|---|---|
| **① 感官专家预训练** | 视觉专家、触觉专家 | 自监督重建 / 对比特征学习 | 各自先学会从原始信号提取稳定特征（轮廓、材质、软硬）。**不要在这一层让文本标签主导** | 特征被拉向"好说人话"，而不是"好存世界" |
| **② 跨感官投影对齐** | 投影层（MLP） | InfoNCE / 余弦对比损失：同一物体的视-触样本拉近，不同物体推远 | 这是整个公共语义空间的地基。**两个专家本身冻结**，只学投影矩阵 | 跨物体特征混在一起，后续绑定全部失真 |
| **③ 绑定/解绑训练** | 结构化绑定模块 | 重建损失：`unbind(bind(feat, slot), slot) ≈ feat` | 逐元素乘除在近零分量处放大噪声，要加**范数约束**；训练时就要模拟多轮迭代，测可逆性衰减 | 向量塌向零、多轮后绑定解体（7.1 ①） |
| **④ 关系推理 + 世界模型** | 推理引擎、时序预测模块 | 关系三元组匹配 + 下一状态向量预测误差 | 数据必须包含**动作前后的状态变迁**；区分"相关"与"因果"，需要干预数据 | 只学到平均状态，多模态分布塌缩 |
| **⑤ 多读出头联合微调** | 文本头、动作头、目标头、价值头 | 各头损失加权 + 共享表征 | 底层表征**冻结大半**，只微调浅层；头之间并行，节奏不同 | 文本头反向主导表征，架构退化成 LLM |

### 六个贯穿全程的注意事项

**① 向量空间必须归一化**

绑定算子（乘法/除法）对向量范数很敏感。训练时要约束特征向量长度稳定（归一化或按范数裁剪），否则少数维度爆炸会把其他维度淹没，可逆除法也会被噪声放大。

**② 归属必须有监督，防"特征串味"**

> 这是幻觉的机械根源（见 5.6 主张三）：没有客体槽，多特征必然混淆。

训练时要给"哪个特征属于哪个客体"提供监督标签（或弱监督）：红 + 圆绑在苹果上，蓝 + 直绑在杯子上。

**评估时要专门测「跨客体属性混淆率」**——把红的属性错配给杯子，就是这套架构的"幻觉"。

**③ 多任务损失要做梯度协调**

四类损失不要手工拍固定权重。可选手段：

- **梯度手术**：PCGrad / GradNorm，抵消冲突方向
- **不确定性加权**：按各任务的不确定性自动调权重
- **分阶段解冻**：对齐完成前，推理损失不参与回传

**④ 防止文本头反向绑架表征**

这是这套架构**最隐蔽的风险**：

> 语言只是末端读出头。但如果训练中文本损失占大头，表征会被拉向"适合说人话"，而不是"适合存世界"。

早期必须让**非语言任务**（动作预测、关系判断、状态推演）**主导表征**；文本头只在最后阶段接入。否则训出来就是一个"带向量包装的 LLM"。

**⑤ 持续学习通路要在训练期就预留**

实例级知识写入长期库、不更新权重这条路（8.6），训练架构时就要设计好：

- **实例库与推理权重分离**，新增实体不触发反向传播
- 通用规则的增量微调走 **LoRA + EWC**，锁定基础物理规则权重
- **原型层（5.3）要留更新接口**，但更新速率受约束，防止原型漂移

**⑥ 原型层：从多实例凝练，区分不变与可变**

原型向量不是训练出来的"类别标签"，而是从大量实例中**归纳**出来的：

- 用对比学习把"不变核心特征"（苹果的外形结构）和"可变属性"（颜色、尺寸）分开
- **原型更新要慢**，否则看多了塑料苹果，原型会偏向玩具（5.3 原型漂移）

### 数据要求：目前最大的现实瓶颈

现有人工标注数据集基本不匹配，需要四类数据：

| 数据类型 | 用途 | 来源 |
|---|---|---|
| **多感官成对样本** | 投影层对齐（阶段②） | 仿真器采集为主，**真实机器人触觉数据稀缺** |
| **动作-状态时序对** | 世界模型（阶段④） | 仿真环境脚本化动作序列 |
| **多物体遮挡/移动场景** | 槽位分配、身份追踪 | 仿真器生成遮挡、穿越、分离 |
| **干预/因果数据** | 区分因果与相关 | **主动动作实验**，而不是被动视频流 |

**必须做的增强：** 噪声注入、局部遮挡、外观扰动——否则模型在干净数据上认得准，一上真实传感器就崩。

> 现实路径大概率是 **仿真预训练 → sim2real 微调**。纯真实数据成本过高，纯仿真又有域差。

### 评估指标：不能只看识别准确率

如果沿用 LLM 那套"问答正确率"当指标，会掩盖真正的问题。

| 指标 | 测什么 | 对应风险 |
|---|---|---|
| **绑定可逆误差** | 多轮 bind/unbind 后特征还原程度 | 绑定解体 |
| **ID 保持率** | 遮挡/移动前后，同一实体追踪不串 | 身份漂移 |
| **关系推理正确率** | 包含/接触/可放入等三元组判断 | 关系表征失效 |
| **状态预测误差** | 世界模型对下一状态向量的预测偏差 | 模式塌缩 |
| **属性混淆率** | 特征错配到别的客体的比例 | **幻觉** |
| **焦点切换召回** | 休眠物体被重新唤醒后能否找回 | 长期库检索失效 |

### 诚实边界

**这套端到端训练范式目前不存在成熟成品**（第三部分、8.1 都标注过）。上面是从认知原理、对比学习、持续学习、具身智能现有方法推导出的**候选训练路线**：

| 状态 | 内容 |
|---|---|
| ✅ **有现成方法支撑** | 对比学习对齐、LoRA + EWC、梯度手术、自监督预训练 |
| ⚠️ **尚未验证** | 可逆绑定在真实高维向量上的长期稳定性、槽位分配的自动策略、原型自动凝练、非语言表征不被文本头绑架 |

7.1 列的五个未解问题，在训练阶段就会依次暴露——尤其 **③ 槽位分配策略** 和 **④ 动态身份维持**，是数据和监督设计上最难补的两块。

## 5.6 流水线式模块化训练范式

> **后文更新**：本节是模块化的最初设想。关于「专家重训会不会摧毁热插拔」的边界、坐标漂移与裁决机制，已在 **9.1** 中收紧并给出验收流程；此处保留当时的原始推演，不重复叙述。

> **这一节是对 5.5 的组织形态补充。**
> 5.5 讲"训什么、按什么顺序训"；这一节讲"由谁来训、怎么并行、怎么局部更新"。

### 核心判断

整套架构的模块化设计，天然支持**流水线式分模块训练**：

> **模块解耦、独立迭代、模块可异构、支持局部热更新，不用整体重训。**

**和 LLM 的根本区别：**

| | LLM | 本架构 |
|---|---|---|
| 结构 | 单一体模型，所有知识、感知、推理全压缩在同一套 Transformer 权重里 | 每个模块是**独立单元**，接口固定（统一公共语义向量） |
| 改一个能力 | 基本要全局微调，容易灾难性遗忘 | **只单独训练/更新其中一个模块，其余模块保持不动** |

### 流水线链路（固定接口，模块异构）

```
原始感官信号
    ↓
【感官专家模块】→ 特征向量
    ↓
【跨模态投影对齐模块】→ 公共语义向量
    ↓
【实体槽位绑定模块】→ 带客体归属的 obj 向量
    ↓
【关系推理 + 世界模型模块】→ 实体状态 / 新关系向量
    ↓
【多输出头（动作 / 文本 / 目标）】
```

> **核心规则：模块之间只传递标准化向量，不传递原始图像、原始触觉数据、文本 token。**
> 只要输入输出向量接口约定不变：

1. 视觉专家可以是 CNN / ViT / SNN，触觉专家可以是 MLP 或小 Transformer，**不需要同一种模型**
2. 关系推理模块可以随时替换、局部热更新，**不需要重新训练视觉专家**
3. 单独升级触觉传感器，只需要重训触觉专家 + 它的投影层，**推理模块完全不动**

### 流水线训练逻辑：逐段验收，逐级交付

训练顺序严格顺着流水线从前到后：

**阶段 1：独立训练各个感官专家（并行开展）**

视觉、触觉模块分开训练，互不干扰。目标是从原始传感信号提取稳定特征。训练完成，**冻结权重**，作为固定上游组件。

> 可以多人/多团队并行开发：A 做视觉，B 做触觉，互不影响。

**阶段 2：训练跨模态投影层**

上游感官专家冻结，只训练投影层，把不同感官输出映射到同一个公共语义向量空间。

> 上游输出是固定向量，投影层的训练数据集就是「**同一物体，视觉特征 + 触觉特征**」成对向量，**不再需要原始图片**。

**阶段 3：实体绑定模块训练**

上游（感官 + 投影）全部冻结。输入公共语义向量，训练槽位绑定、特征归属拆分，把特征打包成 `<objX>{属性向量}` 的实体结构。

**阶段 4：关系推理、世界模型训练**

上游全部冻结。输入已绑定好的实体 obj 集合，训练实体间空间、因果、包含关系与时序状态预测。

> **这一段可以独立迭代、热更新。**
> 重点：如果后续要新增物理规则（如"玻璃撞击会碎裂"），**只更新推理模块**，前面视觉、触觉、绑定模块完全不动。

**阶段 5：输出头训练**

前面所有表征链路冻结，只训练末端动作头/文本头，把实体向量映射成文字或机器人动作指令。

> ✅ 流水线核心：**上一模块训练完成、验证达标、冻结；输出标准化向量作为下一模块的固定输入。**

### 两大关键特性

**特性一：模块异构**

感官专家和推理模型不需要是同类网络：

| 模块 | 可选实现 |
|---|---|
| 视觉专家 | ViT / CNN / SNN，负责图像提取特征 |
| 触觉专家 | 小型 MLP / 小 Transformer，处理压力传感器信号 |
| 关系推理模块 | 向量符号引擎 / 小型 GNN / SNN，专门处理实体关系运算 |

> 只要输入输出向量维度、归一化规则、表征约定统一，**不同类型模型可以拼接在一起**。

**特性二：推理模块热更新**

推理模块存储两类知识，更新方式完全不同：

| 知识类型 | 例子 | 更新方式 |
|---|---|---|
| **通用物理/因果规则** | 玻璃摔碎、衣服放入洗衣机 | 增量微调 + **EWC 保护旧规则**，不需要重训感知模块 |
| **场景实例知识** | 当前房间里的这个杯子、这件衣服 | 放在实体场景库，**完全不改动神经网络权重**，只是向量库的增删改查 |

> **后者是"无权重热更新"——这是整套架构在持续学习上最硬的优势（详见 8.6）。**

新增一条规则"陶瓷盘子掉落也会碎裂"时：只需拿实体时序数据微调推理模块，**上游视觉、触觉、绑定模块权重完全保留**，不会破坏已学会的物体识别。

### 流水线模式的四个风险

**① 误差会沿流水线逐级累积**

上游模块的微小特征误差，会一路传递放大到下游推理。**上游一旦有偏差，下游再怎么优化推理模块都没用。**

> 应对：每个模块设独立验收指标，**上一模块不达标，不进入下一阶段训练**（流水线质检）。

**② 接口锁死带来的表征瓶颈**

一旦提前固定向量维度、归一化策略，后续想修改表征空间，**整条流水线都要重新跑一遍**。

> 应对：接口设计预留版本号，向量空间定义尽量稳定；版本切换做平滑迁移。

**③ 不存在完全隔离，弱耦合依然存在**

虽然上游冻结，但如果上游表征本身缺少某类关键信息（比如材质细微特征），**下游推理模块永远无法补回来**。

> **上游能提取什么，下游才有什么。**

**④ 分阶段训练容易出现「分布偏移」**

训练下游模块用的是**固定上游模型的输出向量**；但真实部署时传感器噪声、环境变化会让上游向量分布偏离训练数据。

> 应对：上游训练时就注入噪声、遮挡扰动，模拟真实传感输出，缩小 sim2real 差距。

### 与端到端 LLM 的对比

| 项目 | 端到端 LLM | 本架构流水线 |
|---|---|---|
| 模型结构 | 单一整体网络，权重耦合 | 独立模块，标准化向量接口，**模块异构** |
| 训练方式 | 端到端联合训练，一次性优化全部损失 | 流水线逐段训练，**上游冻结，下游单独训练** |
| 迭代成本 | 新增知识大概率全局微调，容易遗忘 | 升级单一模块，其余保持不动；**实例知识无需改权重** |
| 更新方式 | 只能权重微调 / RAG 外挂 | **模块替换、模块微调、实体向量库热更新**三种方式 |
| 并行开发 | 很难拆分 | **多团队并行开发不同感官模块** |

### 小结

> 整套架构天然支持流水线式训练：模块之间依靠标准化公共语义向量作为接口，模块可异构独立开发、单独训练；上游模块验收冻结后，输出向量作为下游模块的固定输入。
> 推理模块支持局部热更新——新增物理因果规则**不需要重新训练感知层**。
> 代价是误差会沿流水线累积，因此每一段都必须有独立的验收标准。

## 5.7 这个架构的核心主张（三条）

1. **思考不需要经过语言。** 语言是可选读出头，不是媒介。
2. **状态必须显式。** 把状态压进 token 序列，是自回归效率与推理稳定性的共同病根。
3. **归属必须显式。** 没有客体槽，多特征必然混淆——这是幻觉的机械根源。

# 第六部分 可运行 Demo

## 6.1 实现了什么

用 Python + NumPy 做了一个最小可运行版本，验证上述架构的**核心链路**：

```
感官专家 → 投影 → 结构化绑定 → 工作记忆 → 推理引擎 → 文本读出
```

**全程无 token，全部是向量运算。**

### 关键设计选择

| 环节 | 实现 | 说明 |
|---|---|---|
| 绑定算子 | **逐元素乘法**（Hadamard） | 精确可逆：`unbind(bind(x,s),s) = x`。循环卷积虽容量更大但只是近似可逆 |
| 投影层 | 随机正交矩阵 | 模拟训练好的投影头。真实系统应为对比学习训练的 MLP |
| 概念识别 | 模板相似度匹配 | 学习和识别走同一绑定-解绑流程，故相似度可达 1.000 |
| 客体槽 | 4 个随机单位向量 | 对应人脑 γ 相位槽 4 个，也对应工作记忆 4±1 组块 |

## 6.2 核心代码

### 绑定算子（精确可逆）

```python
def bind(feature_vec, slot_vec):
    """绑定：逐元素乘法。精确可逆。"""
    return feature_vec * slot_vec

def unbind(bound_vec, slot_vec):
    """解绑：逐元素除法。精确可逆。"""
    safe_slot = np.where(np.abs(slot_vec) < 1e-6, 1e-6, slot_vec)
    return bound_vec / safe_slot
```

### 结构化绑定模块

```python
class ObjectBinding:
    def __init__(self, n_slots=4):
        self.slots = [random_vector() for _ in range(n_slots)]

    def bind_object(self, features_dict, slot_idx):
        """把一组特征绑定到指定客体槽"""
        slot = self.slots[slot_idx]
        obj_vec = np.zeros(DIM)
        for _, feat_vec in features_dict.items():
            obj_vec += bind(feat_vec, slot)
        return obj_vec

    def unbind_object(self, obj_vec, slot_idx):
        """解绑出所有特征的叠加"""
        return unbind(obj_vec, self.slots[slot_idx])
```

### 属性查询（在绑定空间直接比较）

```python
def query_attr(obj_vec, slot_idx, all_attr_basis):
    slot = binding.slots[slot_idx]
    scores = {}
    for attr_name, basis_vec in all_attr_basis.items():
        bound_attr = bind(basis_vec, slot)
        scores[attr_name] = cosine_sim(obj_vec, bound_attr)
    return sorted(scores.items(), key=lambda x: -x[1])
```

> ⚠️ **调试中踩到的坑**：属性基向量必须**先经过投影层**，才能和客体里的特征在同一空间比较。否则相似度全是噪声——这是"空间不对齐"问题在 Demo 里的真实复现。

| **噪声鲁棒性** | 未做传感器噪声测试，真实场景相似度会降到 0.7~0.9 |

## 6.6 对比实验：Token 推理 vs 向量推理（同一道物理题）

> **这个实验是为了直接验证 5.1 提出的核心主张**：思考是否真的不需要经过 token。
> 同一道物理推理题，用两条路径各跑一遍，量化对比计算量。

### 题目

```
桌面上有一个红色光滑的苹果（半径 0.25），初始在 x=0；
旁边 x=2.2 处有一个蓝色杯子（半径 0.25）。
苹果被向右推了一下，速度 1.0 m/s。
问：3 秒后苹果在哪？会不会碰到杯子？
```

### 两条路径的实现差异

**路径 A：Token 自回归（模拟 LLM）**
- 每一步都把"初始场景描述 + 之前所有步骤的结论"重新拼接成上下文
- 再输入 Transformer 预测下一步
- 上下文长度随步数线性增长，注意力开销 O(N²)

**路径 B：向量空间（显式工作记忆）**
- 工作记忆里存两个客体：`obj_apple`、`obj_cup`
- 每个客体的属性向量（颜色/形状/纹理）只存一次，**永不参与每步计算**
- 物理推演只修改 `obj_apple["pos"]` 这一个 2 维向量
- 碰撞判断 = 两个客体位置向量的欧氏距离

### 运行结果

**路径 A：Token 自回归**

| t | 输入 token | 注意力开销 (N²) | 结论 |
|---|---|---|---|
| 1 | 157 | 24,649 | x=1.0，距离 1.20，还没碰 |
| 2 | 232 | 53,824 | x=2.0，距离 0.20，**会碰到** |
| 3 | 309 | 95,481 | x=3.0，距离 0.80，已越过 |

**累计注意力计算量：173,954**

**路径 B：向量空间**

| t | 苹果 x | 距离 | 判定 | 本步计算维度 |
|---|---|---|---|---|
| 1 | 1.0 | 1.20 | 还没碰到 | 仅位置 2 维（跳过 192 维属性） |
| 2 | 2.0 | 0.20 | **会碰到杯子** | 仅位置 2 维（跳过 192 维属性） |
| 3 | 3.0 | 0.80 | 还没碰到 | 仅位置 2 维（跳过 192 维属性） |

**物理答案完全一致**：t=2 时苹果到达 x=2.0，距杯子 0.2 < 阈值 0.5，发生碰撞；t=3 时已越过。

### 量化对比

| 维度 | Token 自回归 | 向量空间推理 |
|---|---|---|
| 每步输入信息 | 初始场景 + 全部历史 | 仅当前状态 |
| 输入长度增长 | **线性增长**（157→232→309） | **恒定**（始终 2 个客体） |
| 注意力复杂度 | O(N²) 每步 | O(1) 位置更新 |
| 累计计算量 | **173,954** | 恒定：3 步 × 2 维 |
| 不变属性（红/光滑/硬质） | **每步都要重述，重复算 3 遍** | 完全不参与，只存一次 |
| 实体身份 | 靠文本描述维持 | 靠客体槽天然绑定 |
| 跨步状态 | 全部平铺在上下文 | 原地修改位置向量 |

### 这个实验证明了什么

1. **物理推演不需要经过文字。** 两条路径给出相同答案，但向量路径从头到尾没有生成一个 token。

2. **不变属性不该参与每步计算。** "苹果是红色光滑的"这个事实，在 3 秒推演里没有变过，但 Token 路径把它重复描述了 3 遍，每遍都重新过一遍注意力。向量路径里这些属性向量一直待在工作记忆里，物理推演只动了"位置"这 2 个数字。

3. **步数越多，差距越大。** Token 路径的开销按 N² 增长；向量路径单步成本恒定。推演 10 步、100 步，差距会从现在的几十倍变成几个数量级。

### 这个实验的边界

必须诚实标注：

- 这里的"Token 路径"是**模拟**，不是真实跑一个 LLM。真实 LLM 有 KV Cache，不会每步完全重算；但 KV Cache 仍然让上下文长度线性增长，且无法避免"不变属性持续占用注意力预算"的问题。
- 这里的"向量路径"也只是**最朴素的状态更新**（位置 += 速度 × dt），不是学到的世界模型。真实世界模型需要从数据学习物理规律。
- 但**结构性差异是真实的**：一个把状态平铺成序列反复重算，一个把状态作为可读写变量原地更新。这不是工程优化能抹平的，是范式差异。

## 6.7 从"认识物体"到"能干活"：关系表征与动作算子

> **这是整场讨论的第三个关键转折。**
> 前面所有 demo 都在解决"这是什么"。但一个机器人要真正干活（洗衣服、做饭、收拾桌子），需要的东西完全不同：
> **它要理解物体之间的关系，理解动作的因果，能规划多步操作，还能在每步之后验证结果对不对。**

### 为什么这比单客体识别难一个数量级

| 单客体识别 | 洗衣服任务 |
|---|---|
| 一张图 → "这是苹果" | 维护整个场景的**关系图谱** |
| 一帧就够 | 8~12 步长程序列 |
| 不需要因果 | 按按钮 → 机器转 → **洗完才能开门** |
| 不需要等待 | 要等洗衣机完成 |
| 不需要异常处理 | 门没开成功怎么办？ |
| 状态是物体属性 | 状态是**物体之间的关系** |

### 这一层需要新增三块

**① 关系向量（不再只是物体属性）**

之前公共语义空间存的是 `obj0 = {红, 弧形, 光滑, 50cm}`。
现在要加：`衣服 in 洗衣机`、`洗衣液 held_by 手`、`门 open`、`按钮 pressed`。

在向量空间里，**关系本身也是向量**（`rel_in`、`rel_held`、`rel_open`）。三元组 `(衣服, in, 洗衣机)` 用结构化绑定打包：

```
fact = bind(衣服, 主语槽) + bind(rel_in, 关系槽) + bind(洗衣机, 宾语槽)
```

和我们之前给特征打 obj 槽是同一个机制，只是槽位从"标记哪个物体"扩展到"标记三元组里的主语/关系/宾语"。

**② 动作算子（状态变换函数）**

每个动作不是一个文字指令，而是一个**对状态向量的变换**，带前置条件和效果：

| 动作 | 前置条件 | 效果 |
|---|---|---|
| `open(洗衣机门)` | 门 closed，机器 stopped | 门 → open |
| `put_in(衣服, 洗衣机)` | 衣服 held，门 open | 衣服 held → false；衣服 in 洗衣机 → true |
| `pour(洗衣液, 洗衣机)` | 洗衣液 held，门 open | 洗衣机内有洗衣液 |
| `press(按钮)` | 门 closed，有水，有洗衣液，衣服在内 | 机器 → running |
| `wait(机器 stopped)` | 机器 running | 机器 → stopped；水排掉；衣服 → clean |
| `take_out(衣服, 洗衣机)` | 衣服 in 洗衣机，门 open | 衣服 held |
| `hang(衣服, 晾衣架)` | 衣服 held | 衣服 on 晾衣架 |

**③ 任务规划 + 感知闭环**

- **规划**：从初始状态搜索动作序列到达目标状态
- **感知闭环**：每步执行后用视觉/触觉验证"门真的开了吗？衣服真的进去了吗？"——不对就停下来重新决策

> **这是具身智能和纯开环策略的本质区别。** 现在很多机器人笨，就是因为它们是"感知→反应"的开环，没有显式的关系状态和动作模型。

### Demo 跑通了什么

`laundry_task_demo.py` 完整模拟了 12 步流程：

```
初始：衣服在篮子里，门关着，机器停着
  ↓ 1.拿起衣服 → 2.开门 → 3.放进衣服 → 4.拿起洗衣液
  ↓ 5.倒洗衣液 → 6.关门 → 7.注水 → 8.按开始
  ↓ 9.等洗完（机器停、水排掉、衣服变干净）
  ↓ 10.再开门 → 11.取出衣服 → 12.挂到晾衣架
最终：衣服 on drying_rack ✅
```

每一步都做了三件事：
1. **前置条件检查**（不满足就拒绝执行并报告阻塞）
2. **执行动作**（修改状态）
3. **感知验证**（打印当前场景快照，模拟视觉/触觉确认）

### 这个 Demo 的关键设计

状态不是用 if-else 写死的，而是一个**关系集合**：

```python
state.relations = {
    ("clothes", "in", "washer"),
    ("detergent", "on", "counter"),
}
```

每个动作只是对这个集合做**增删**：
- `put_in`：删除 `("clothes", "in", "basket")`，添加 `("clothes", "in", "washer")`
- `open`：翻转 `door_open` 布尔值

> **真实系统里，这个关系集合不是 Python set，而是一组 SBP 绑定向量。**
> 动作就是对这些向量做"移除旧绑定、添加新绑定"。
> 感知端（视觉专家）直接输出关系向量，不需要翻译成逻辑谓词——**感知和规划共享同一个向量空间，没有符号接地断层。**

### 这个 Demo 的边界（必须诚实标注）

| 没做到 | 说明 |
|---|---|
| **动作序列是手写的** | 12 步是我们规划好的，不是规划器自动搜索的。真实系统需要从"初始状态+目标状态"自动 BFS/A* 搜索动作序列 |
| **前置条件是 if-else 写死的** | 真实系统应该从交互数据里学习"做这个动作需要什么前提" |
| **没有异常处理** | 如果开门失败了怎么办？如果洗衣机里已经有水怎么办？真实系统需要重试、回退、重新规划 |
| **状态是代码直接改的** | 真实系统里状态变化应该来自感知验证（看到门开了），而不是代码直接设 `door_open=True` |
| **没有和感知前端对接** | 视觉专家怎么从像素里识别出"衣服在洗衣机里"？这是另一个难题 |

> **这个 Demo 验证的是结构：状态 = 关系集合，动作 = 前置条件 + 状态变换，任务 = 动作序列。**
> 它证明了"能干活"这件事在架构上可以拆解成清晰的部件；但每个部件的学习方式还没实现。

### 和传统符号规划（PDDL）的区别

| | 传统 PDDL/STRIPS | 本架构的向量版本 |
|---|---|---|
| 关系表示 | 离散逻辑谓词 `in(clothes, washer)` | SBP 绑定向量 `bind(clothes, subj) + bind(rel_in, rel) + bind(washer, obj)` |
| 感知对接 | 需要一个"感知→符号"翻译层（接地问题） | 感知专家直接输出关系向量，**无翻译断层** |
| 动作模型 | 手写 precondition/effect | 从交互数据学习的状态变换算子 |
| 容错 | 硬逻辑，不满足就失败 | 向量相似度软匹配，部分满足也能尝试 |
| 可学习性 | 规则是人写的 | 关系向量和动作算子都是学出来的 |

> **核心优势：感知和规划在同一个向量空间里。** 视觉专家说"衣服好像在洗衣机里"（一个相似度 0.8 的向量），规划器直接用这个向量做推理，不需要先变成一个硬逻辑谓词。

# 第七部分 遗留问题与后续方向

## 7.1 技术层面的五个关键未解问题

**① 可逆绑定的数值稳定性**

多轮迭代后，向量会慢慢失真，绑定可能解体。逐元素除法在噪声下尤其脆弱（接近零的分量会被放大）。

> 需要研究：迭代多少次后需要"rebind"重整？是否需要周期性从感官重新提取？

**② 多任务损失的梯度冲突**

跨模态对比 + 绑定解构 + 世界模型 + 问答，四项一起训练互相干扰。可能需要：
- 分阶段训练（先对齐，再绑定，最后联合微调）
- 梯度手术（GradNorm / PCGrad）

**③ 客体槽数量与场景复杂度**

4~8 个槽对应人脑上限，但真实场景物体可能更多。槽位分配策略（何时复用、何时新增）需要设计。

> **→ 与 ④ 合并后已给出候选解法，见 7.3。**

**④ 动态客体身份维持**

物体移动 → 视觉底层特征持续变化，但系统必须知道"还是 obj0"。人脑有专门的追踪机制，这里没有。

> **→ 看似两个问题，实为同一个（有限记忆 vs 无限场景），候选解法见 7.3。**

**⑤ 长期记忆的写入策略**

什么时候把工作记忆里的客体固化进长期概念库？如何避免灾难性遗忘？

## 7.2 可选的下一步实验

按实现难度排序：

| 优先级 | 实验 | 验证目标 |
|---|---|---|
| ★★★ | **加噪声鲁棒性测试** | 看识别准确率随噪声强度的衰减曲线，找到绑定算子的容量边界 |
| ★★★ | **加世界模型（状态推演）** | 苹果位置随时间变化，工作记忆原地更新，验证"不需要重读历史"。**已做最小版（见 6.6）**，下一步是从数据学习物理规律而非手写公式 |
| ★★☆ | **加动作输出头** | 不输出文字，直接输出"伸手/不伸手"的动作向量，验证多读出头 |
| ★★☆ | **真实像素输入** | 用一个简单 CNN 替代手工特征基向量，验证"自动特征提取 + 绑定"链路 |

## 7.3 候选方案：3D 场景图 + 注意焦点的双层记忆

> **这一节是对 7.1 中 ③（客体槽数量）和 ④（动态身份维持）两个难点的正面回应。**
> 核心判断：**这两个问题其实是同一个问题——有限的工作记忆，如何对应无限的场景物体。**

### 先合并两个问题

| 表面看是两个问题 | 实际上同一个 |
|---|---|
| 场景物体多于槽位，怎么分配？ | 都是"**记忆容量有限 vs 世界无穷**"的一体两面 |
| 物体移动后怎么维持 ID？ | 一旦记忆分成"持久层 + 焦点层"，两者同时被解决 |

**解法不是让工作记忆装下更多物体，而是让绝大多数物体根本不需要进工作记忆。**

### 方案三层结构

| 层 | 内容 | 作用 |
|---|---|---|
| **持久几何层** | 激光扫描建成的 3D 场景图 | 所有物体的位姿都存在这里，**不占工作记忆** |
| **工作记忆层** | 3~5 个注意力槽 | 当前正在推理的物体 |
| **关联层** | 移动/遮挡 = 位姿变化，不是 ID 变化 | 把上下两层粘起来 |

```
┌─────────────────────────────────────────┐
│  全局 3D 场景图（持久，外部记忆）          │
│  ├─ obj0: 位姿(2.1, 0.4, 0.9)   苹果     │
│  ├─ obj1: 位姿(1.8, 0.4, 0.9)   杯子     │
│  ├─ obj2: 位姿(0.5, 0.3, 0.0)   洗衣机   │
│  └─ ...（数百个都装得下）                 │
└─────────────────────────────────────────┘
              ↑ 注意力只取 3~5 个
┌─────────────────────────────────────────┐
│  工作记忆（当前焦点，推理发生在这里）       │
│  [ obj0 苹果 ]  [ obj2 洗衣机 ]           │
└─────────────────────────────────────────┘
```

**这一下同时解决两个原难点：**

- **绑定漂移**：物体 ID 不再只靠视觉外观匹配，而是绑定到「**3D 位姿 + 外观特征向量**」联合匹配。遮挡后重现时，激光给出精确坐标，视觉给出外观向量，**双重匹配，ID 几乎不会丢**。
- **容量上限**：不需要把所有物体关系塞进工作记忆。数百个物体的关系全部沉在 3D 地图里，**工作记忆只挂当前要操作的 3~5 个**。

### 这个方案最关键的洞察

> **物体不需要"一直被想着"，它就在世界里。**

这恰好是人脑的工作方式。家里有 200 件物品，但你现在脑子里只有"手机、杯子、电脑"三个。**其他东西不是不存在，是不在注意焦点里。**

想拿剪刀时，视线扫过书桌，3D 场景图立刻把剪刀位姿调进工作记忆，才开始规划动作。

> 这也解释了为什么工作记忆是 **4±1** 而不是 40±1——**不是因为人脑存不下 40 件东西，而是因为同时推理 40 个对象之间的关系没有意义。**

### 四个必须诚实面对的细节问题

**① SLAM 自己也会漂移**

激光雷达建图，走一圈回来会有**几厘米到几十厘米的累积误差**。大场景必须做**回环检测（loop closure）**修正。

> 要承认：3D 地图不是绝对坐标系，是**相对坐标系**。物体位姿存储的是"上一次观测到的位置"，不是"此刻的真实位置"。

**② 数据关联：物体被挪动 vs 新物体进来了**

"移动 = 改变位姿，ID 不变"这个说法要能区分两种情况：

| 场景 | 判断依据 |
|---|---|
| 苹果从桌上被拿到地上，桌上空了 | 地上物体的外观向量 = 之前桌上的苹果 → **同一 obj，更新位姿** |
| 苹果被拿走，梨被放到桌上 | 桌上新物体外观向量 ≠ 之前苹果 → **新 obj，分配新 ID** |

依靠「**3D 位姿变化轨迹 + 外观特征向量相似度**」联合判断。

> 这是 SLAM 里每天处理的**数据关联（data association）**问题。不是新问题，但不简单。

**③ 休眠物体的位姿会过期**

半小时前看到杯子在桌上，现在它还在吗？

"注意力回到它时再即时找"是对的，但执行细节是：

```
1. 休眠时存的是「最后已知位姿」（先验）
2. 注意力回来时，先用激光/视觉在该位置附近搜索
3. 找到了 → 更新位姿
4. 找不到 → 标记「已移动/已消失」，触发重新探索
```

> 这和人找东西完全一样：记得钥匙在抽屉里，拉开没有，就开始找别处。

**④ 3D 地图里存的不只是坐标**

只记坐标/方位是不够的，否则地图只是个点云：

```
obj0:
  位姿:     (x, y, z, rx, ry, rz)    ← 几何
  外观向量: [视觉特征向量]            ← 用于识别
  原型标签: 【苹果】                  ← 语义
  物理属性: 可食用 / 直径8cm          ← 按需累积
```

> **只存坐标的地图是死的；绑定了语义向量的地图才是这套架构的地图。**

### 对架构原设计的修正

这个方案实际上**重设计了第六层（长期记忆库）**：

| 原设计 | 修正后 |
|---|---|
| 长期记忆 = 大向量数据库，实体关系平铺 | 长期记忆 = **3D 场景图**，几何位姿 + 语义向量绑定 |
| 物体靠向量相似度检索 | 物体靠「**3D 位置 + 外观向量**」联合检索 |
| 未考虑容量问题 | 工作记忆只挂 3~5 个，**其余在地图里休眠** |

但必须注意职责划分：

| 层 | 负责 |
|---|---|
| **几何层（3D 地图）** | 定位：东西在哪 |
| **语义层（公共语义空间）** | 理解：是什么、为什么、怎么用 |
| **工作记忆** | 当前推理 |

- 3D 地图告诉你杯子在桌上
- 公共语义向量告诉你杯子用来装水、易碎、可以拿起
- 推理引擎告诉你现在渴了，所以该去拿杯子

> **三层缺一不可。没有几何，语义会漂；没有语义，几何只是点云。**

### 与经典机器人方案的关系（诚实说明）

这个方案非常接近机器人学已经在做的事：**SLAM、3D Scene Graph、主动视觉（active vision）**。

那本架构的独特价值在哪？

> **经典机器人的地图里存的是几何，不是语义。**
> 它知道"桌上有个圆柱体"，但不知道那是杯子、能装水、易碎、可以递给人。

本架构的独特性不在 3D 地图本身，而在：

- **几何位姿 + 语义向量绑在同一个实体上**
- **关系向量（包含、接触、可倾倒）直接在语义空间做运算**
- **动作算子直接修改关系，不需要"语义 → 符号 → 语义"来回翻译**

> **3D 地图是底座，公共语义空间才是上层。**

### 一个额外收益：它同时也是「计算爆炸」的解法

这一点在提出方案时没有明说，但它是同一个结构带来的第二个好处。

**如果所有物体都在焦点，关系推理是 O(N²)。**

场景里 200 个物体，两两关系判断就是 4 万次比较。物体越多，增长越快。

**绝大多数物体休眠时，只有 3~5 个活跃，复杂度是 O(k²)，且 k 有常数上界。**

```
全部活跃：O(N²)      N = 200  →  约 40,000 次关系比较
焦点活跃：O(k²)      k = 4    →  约 16 次关系比较
```

> **所以「容量上限」和「算力上限」其实是同一个约束的两面。**
> 限制工作记忆只放 3~5 个，既解决了"记不住那么多"，也解决了"算不过来那么多"。

这个性质在后续章节被反复用到：

| 应用场景 | 见 | 说明 |
|---|---|---|
| 碎片拼接 | 7.4 ② | N 个碎片两两匹配是 O(N²)，改为**只在推理时按需拼接**，平时碎片休眠 |
| 长时序任务 | 6.7 | 状态只更新变化的关系，不动休眠实体 |

> **休眠不只是省存储，更是省计算。** 注意焦点是一个「计算开关」，不只是一个「记忆开关」。

### 这个方案没有解决的

| 仍未解决 | 说明 |
|---|---|
| **物体外观剧烈变化后的重识别** | 杯子被摔碎成几片，几何位姿还在，但外观向量完全变了。算同一个 obj 的状态变化，还是拆成多个新 obj？没有明确规则。**→ 已在 7.4 给出判定规则** |
| **相似物体的区分** | 桌上有三个一模一样的白杯子，位姿接近。数据关联时必须靠位姿精确区分，激光精度不足时会串位 |
| **3D 建图的实时成本** | 激光 SLAM 在大场景下计算量大，和"实时闭环控制"存在资源竞争。**注意：这是建图本身的成本，不是关系推理的成本**——后者已由上面的焦点机制压住 |
| **语义属性的自动累积** | 位姿能自动更新，但"这个杯子易碎"这类物理属性怎么从交互中自动沉淀进 3D 图，仍是开放的 |

### 小结

> **把"记住所有物体"变成"记住所有物体的位置"。**
> 几何位姿沉进 3D 场景图，语义向量挂在实体上，工作记忆只放当前焦点的 3~5 个。
> 物体被遮挡、被移动、暂时离开视野，ID 都不丢——因为它从来不需要靠"一直被看着"来维持身份，它靠的是**在 3D 空间里的那个位置**。

## 7.4 物体解体与碎裂：实体同一性的判定规则

> **这一节回应 7.3「这个方案没有解决的」中的第一条：**
> 杯子被摔碎成几片，算同一个 obj 的状态变化，还是拆成多个新 obj？
>
> 核心结论：**实体同一性的根基不是外观相似度，而是「连续时序 + 3D 空间的因果观测」。**
> **有过程观测 → 因果确定；只有结果观测 → 只能做概率反推。**

### 两种场景，两种确定性

#### 场景 A：亲眼目睹杯子从桌上掉落摔碎

**连续时序观测，因果链完整。**

```
t0:  <obj0> = 玻璃杯，完整，位姿(1.8, 0.4, 0.9)   ← 已在 3D 场景图中锚定
t1:  观测到：obj0 位姿下落，速度增大
t2:  观测到：obj0 与地面接触，几何结构发生断裂
t3:  同一位置出现 3 个新几何体
```

系统处理：
1. 原 `<obj0>` **不消失**，状态更新为【已解体/已破碎】
2. 生成新实例 `<obj1>`、`<obj2>`、`<obj3>`，对应每一块碎片
3. 在关系库中写入**因果关联**：`<obj1>`,`<obj2>`,`<obj3>` ←POF（part-of-fracture）→ `<obj0>`

> 语义：碎片是**原杯子的产物**，但碎片本身是**独立可操作实例**。
> 机器人后续可以执行"收集 obj1~obj3 碎片"，且它们的溯源指针指回那个杯子。

✅ **因为有时序 + 3D 空间观测，因果是确定的，不是猜测。**

#### 场景 B：没有目睹破碎，直接看到地上的一堆碎片

**无事件观测，无因果链，只能反推。**

```
现在只看到：<obj1>, <obj2>, <obj3> 三块玻璃状几何体，散落在地
```

系统处理：

1. 视觉 + 激光分割，得到碎片实例，提取**局部特征向量**（玻璃材质、曲面弧度、厚度、断裂面纹理）
2. 碎片局部特征 → 与**类别原型的局部子特征**做相似度检索
   - 碎片曲面弧度 ≈ 【玻璃杯】原型的侧壁曲率 → 匹配
3. 得到**概率假设**，不是事实：

```
假说：这堆碎片大概率来自一个玻璃杯
置信度：0.78
状态：UNCONFIRMED（待验证）
```

**若多种物体碎片混杂（玻璃 + 陶瓷）：**

```
第一步：碎片特征向量聚类分组
        └─ 组A：玻璃材质（obj1, obj2, obj3）
        └─ 组B：陶瓷材质（obj4, obj5）

第二步：组内做几何拼接
        └─ 按断裂面曲率、边缘吻合度尝试配对

第三步：拼接后的整体特征向量 → 与各类原型比对
        └─ 组A 拼合结果 ≈ 杯形 → 假说：原为玻璃杯
        └─ 组B 拼合结果 ≈ 盘形 → 假说：原为陶瓷盘
```

> **全部结果是假设/猜想，必须标记置信度，不能断言"这就是杯子碎出来的"。**

### 两条判定规则

| 观测条件 | 判定方式 | 确定性 | 系统行为 |
|---|---|---|---|
| **连续观测（目睹全过程）** | **确定性因果绑定** | 确定 | 保留原 obj 历史，新增子碎片实例，建立父子因果链 |
| **非连续观测（只看到结果）** | **概率反向推理** | 不确定 | 特征聚类 + 几何匹配 + 原型相似度，输出带置信度的假说，可被后续观测推翻 |

> **这是本架构处理"实体同一性"的总原则：先问"我看到了过程吗"，再决定用哪种推理模式。**

### 与人脑认知的对齐

用户的原话已经把这个机制说准了：

> "如果这个杯子是在我眼前从桌子上掉下去摔碎了，那我能够建立起玻璃碎片和原始杯子之间的因果关系。但假如我没有目睹这个过程，我看到地上一堆散落的玻璃碎片我也会很懵——我也许能从碎片中看出一些曾经属于玻璃杯的特征向量，但也只是猜测这堆碎片的前身是一个玻璃杯。"

人脑的运作正是如此：

| 情形 | 人的反应 |
|---|---|
| 目睹摔碎 | "杯子碎了"——**确定**，还会心疼 |
| 只看到碎片 | "这好像是个杯子碎了……吧？"——**猜测**，会蹲下来看、试着拼 |
| 多种碎片混杂 | "这是啥？"——**懵**，先分类再拼 |

> **"懵"不是认知缺陷，是系统正确识别到"因果链缺失"后的诚实反应。**
> 一个可靠的系统也应该会"懵"，而不是硬编一个答案。

### 四个工程难点

**① 局部特征提取**

碎片只有物体的一部分。**不能拿完整物体原型做全局比对**，必须让类别原型支持**局部子特征检索**。

> 例：【玻璃杯】原型 = {圆柱侧壁曲面, 半透明, 底部平面, 把手环}。
> 一片碎片可能只匹配"圆柱侧壁曲面"这一条子特征，其余不匹配。

**② 碎片几何匹配的计算开销**

N 个碎片两两匹配断裂面，复杂度接近 O(N²)。碎片多时计算量爆炸。

> 可以依靠注意力机制：**只在需要推理时才执行碎片拼接**，平时碎片作为独立实例休眠在 3D 场景图中，不参与计算。（这正是 7.3「注意焦点即计算开关」的又一次应用——**休眠省的不只是存储，是 O(N²) 的比较量**）

**③ 歧义无法消除**

> **两片来自不同杯子的碎片，断裂面有可能恰好能拼在一起。**

哪怕几何匹配成功，也**不能 100% 确定来自同一个原始物体**。系统必须保留不确定性，而不是把高置信度当成事实。

**④ 原 obj 还存在吗**

原 `<obj0>` 破碎后，这个实体该怎么处理？需要明确设定：

| 实体 | 处理方式 |
|---|---|
| **原 `<obj0>`** | 保留为**历史实体**，状态标记【已解体】，**不再参与物理操作**，仅用于因果溯源 |
| **新碎片 `<obj1..n>`** | 独立实例，状态为【碎片】，可被抓取、清理、移动 |

> 这样设计的好处：溯源链不断（可以回答"这些碎片原本是什么"），同时不干扰当前操作（不会试图去抓一个已经碎掉的杯子）。

### 小结

> 实体同一性的根基是**连续时序 + 3D 空间的因果观测**。
> 有过程观测时，破碎是原 obj 的一次状态变迁，碎片继承溯源指针，因果确定。
> 缺失过程观测时，系统只能依靠碎片局部特征、断裂几何匹配、原型相似度做**概率猜测**，输出必须带置信度，且可被后续观测推翻。
> 多物体碎片混杂时，需先对碎片特征向量**聚类分组**，再组内**几何拼合**，最后反推原始物体原型。
> **能确定时确定，不能确定时诚实地"懵"——这比硬给一个高置信度答案更可靠。**

## 7.5 这份推演的元层收获

回头看，整个过程最有价值的地方不是最终架构，而是几个**认知转折点**：

1. **区分「生物湿件的最优解」与「问题的最优解」**
   spike 不是特征绑定的唯一方案，只是细胞膜和轴突这套硬件的约束下的最优。换硬件，最优解就换。

2. **从"怎么实现绑定"转向"逻辑模型吃什么格式"**
   前者是工程细节，后者是架构瓶颈。表征格式决定上层能力上限。

3. **"不兼容"不是玄学，有明确理论**
   正交旋转不变性解释了为什么两个独立训练的网络，向量空间天然错位。这让"必须加投影层"从经验变成必然。

4. **状态是否显式，决定效率与稳定性**
   Token 自回归把状态压进序列，导致既要重算历史，又难维持中间结论。这是范式级缺陷，不是工程优化能解决的。

5. **文本是读出头，不是思考媒介**
   一旦接受这点，整条架构的输出侧就被打开了：动作、目标、价值都可以并行直出。

## 8.0 架构边界：什么时候有优势，什么时候 LLM 更合适

### 必须先承认的一件事

如果任务只是**问答、写文章、摘要、代码**，LLM 完全够用，这套架构**没有明显优势**，甚至是过度设计。

> **优势的主战场不在纯文本对话，而在【具身机器人、动态物理环境、持续实体追踪、实时闭环控制】。**

### 表面上看，两者能完成同一个任务

以洗衣服为例：给 LLM 一段 prompt，它可以直接输出 12 步流程；给它状态描述，它能推理下一步。

这套架构也能做同样的事（见 6.7 的 demo）。**在纯文本问答场景下，二者输出结果可以完全一样。**

差别在底层机制。

### 逐项对比（具身场景）

| 维度 | Token LLM 范式 | 公共语义向量架构 |
|---|---|---|
| **场景状态存储** | 状态平铺在上下文 token 序列，每次推理必须把"衣服、洗衣机、门、洗衣液、位置关系"全部编码进文本反复输入。KV Cache 只能缓存 token，**无法分离独立实体** | 场景拆成独立客体 slot + 关系向量。衣服、洗衣机各自是独立向量；`衣服 in 洗衣机` 是独立关系。**只局部修改变化的状态** |
| **感知-规划断层** | 视觉输出 → 多模态模型翻译成文字 → 送入 LLM。**两次转译损耗**，丢失连续物理信息（位置、距离、角度、形变） | 视觉/触觉专家输出特征向量**直接进入公共语义空间**，不需要翻译成文字。感知、关系、规划、世界模型共享同一套表征 |
| **物理连续量** | 物理量被离散成文本符号，难以做连续动力学推演；学到的是**文本共现**，不是真实动力学 | 向量天然连续，直接做向量加减与动力学预测 |
| **长时序开销** | 开销随上下文长度**平方增长** | 工作记忆实体数量固定，步数增加开销几乎不变 |
| **感知闭环容错** | 观测翻译成文字容易出现符号错误；一旦描述写错，后续全部推理跑偏 | 相似度匹配天然支持概率表征：`衣服 in 洗衣机，置信度0.85`，可在不确定下规划 |
| **语言能力** | **原生极强**，对话、概括、抽象、写代码是强项 | 语言只是外挂读出头，需要额外模块，纯文本弱于 LLM |

### 一个具象例子

机器人执行到第 5 步（倾倒洗衣液），摄像头观察到：**洗衣液没倒进洗衣机，洒在了地上。**

**LLM 路线：**
视觉模型把画面翻译成文字："洗衣液洒落在地面，没有进入洗衣机"，追加进上下文。随着任务变长，上下文越来越长，每一步都要重复描述所有物体。描述一旦出现歧义，推理就出错。

**向量路线：**
视觉专家直接更新关系向量：`洗衣液 in 洗衣机` 置信度下降，新增 `洗衣液 on 地面`。**只修改这一条关系，其余客体属性完全不动**。规划器直接在向量空间检测异常，触发重规划，全程不需要转成文本。

> **关键差异：LLM 擅长用语言描述世界；向量架构擅长持有世界本身的表征。**

### 边界总结

| 场景 | 谁更合适 |
|---|---|
| 纯文本问答、写作、代码 | **LLM**（更成熟、更简单、成本低） |
| 多实体物理交互、长时序具身任务、需要实体追踪与闭环 | **本架构**（结构性优势） |

> 两套不是替代关系，是**分工关系**：LLM 是语言思考器；本架构是面向物理实体的具身推理引擎。

## 8.1 与主流潜空间世界模型的差异

### 主线区分

现在主流世界模型（**DreamerV3、Genie、Sora、RoboGen**）本质是**像素/潜空间预测器**：学习从当前观测预测下一个画面/潜向量。

本架构是**实体-关系世界模型**：不预测原始画面，而是维护**独立客体 slot + 客体间关系向量**，在实体层面做状态推演。

> 一句话：
> **主流世界模型：预测感官会看到什么（画面/潜特征）**
> **本架构世界模型：预测世界里各个物体本身会变成什么状态、关系会怎么变**

### 主流世界模型的原理与短板

**原理：**
- 输入图像/视频潜编码，输出预测的下一时刻潜特征（可解码成画面）
- 表征介质：**全局潜向量**，整个场景打包成一个大向量，**场景内部物体没有独立身份槽位**
- 推理粒度：像素/视觉特征层面，学到的是视觉统计变化
- 规划方式：在潜空间采样未来多帧视觉轨迹，选可行动作

**优势：** 端到端，直接从原始图像学习，不需要人工定义客体。

**短板：**

| 短板 | 说明 |
|---|---|
| **实体混淆（entity leakage）** | 多物体靠近、遮挡时表征会混在一起，身份丢失。它知道画面会怎么变，但不知道"这还是同一个衣服，只是被挡住了" |
| **隐式表征不可读** | 内部没有可读的实体、关系，很难做符号化因果查询（"衣服是不是在洗衣机里？"） |
| **长时序漂移** | 没有独立客体身份锚点，推演越长越漂 |
| **规划成本高** | 要反复采样多帧视觉潜变量 |

### 本架构的对应表现

- 表征介质：**分离式 slot 客体向量 + 结构化绑定关系向量**。每个实体有持久表征槽，**遮挡也不丢 ID**
- 推理粒度：物理实体与实体间关系（在哪里、谁在谁里面、门开还是关）
- 规划方式：直接在实体/关系空间搜索动作序列，**不需要采样未来画面**

### 横向对比

| 对比维度 | 主流潜空间世界模型 | 本架构：实体-关系向量世界模型 |
|---|---|---|
| **表征基本单元** | 全局场景潜向量，无显式实体 | 独立 slot 向量 + 关系绑定向量，**物体是一等公民** |
| **预测目标** | 下一帧视觉潜特征（画面长什么样） | 客体属性与关系状态变化（物体会发生什么） |
| **实体身份** | 隐式，遮挡易混淆 | 显式 slot，身份稳定，抗混淆 |
| **可解释性** | 黑盒潜向量，无法直接读取事实 | 向量可检索，相似度即事实查询 |
| **规划开销** | 高，需采样多条视觉想象轨迹 | 低，只更新变化的客体/关系 |
| **感知接口** | 原始图像 → 全局潜编码 | 原始图像 → 感官专家 → 分解为多个客体向量 |
| **适用场景** | 视频生成、视觉想象、简单具身交互 | 长时序机器人任务、多实体交互、因果推理 |
| **短板** | 实体绑定弱、长任务漂移、状态不可读 | **客体分解（视觉前端）训练困难**，整体训练范式不成熟 |

### 三个容易混淆的澄清

**① Slot Attention 不是同类东西**

Slot Attention 只是**视觉前端工具**，负责从图像里分割出多个客体 slot 向量。它本身**不带关系表征、没有结构化绑定、没有规划引擎**。

> 本架构 = Slot 式客体提取 + **关系结构化绑定** + 工作记忆 + 实体层面世界模型 + 任务规划器。

**② "LLM + 潜空间世界模型"的组合方案仍有断层**

流行方案是 LLM 做高层规划 + 世界模型做视觉想象。但 LLM 用 token，世界模型用画面潜向量，**是两套完全不同的表征**，需要不断在「文本 ↔ 图像潜特征」之间来回转译。

本架构里，高层规划、世界模型、感知**全部在同一个公共客体向量空间**，无转译。

**③ 边界要划清**

✅ 优势场景：机器人多实体长任务、容器/接触/包含关系、需要查询实体关系、处理遮挡、长时序闭环。

❌ 劣势场景：**单纯视频生成、画面纹理生成、纯视觉想象——这些 Sora 这类模型更强。** 不要在本架构不擅长的领域硬吹。

## 8.2 与李飞飞 Atlas（World Labs）的差异

### 核心区分

> **Atlas 是「空间渲染 / 新视角生成模型」，核心目标是预测画面。**
> **本架构是「认知推理架构」，核心目标是维护实体、特征、关系，做物理因果规划。**

Atlas 的核心能力不是简单"预测下一帧视频"，而是：**给定相机位姿，预测这个新机位下你会看到什么画面**——新视角渲染。底层仍是 Transformer 自回归，只是把文本 token 换成「图像 patch + 相机位姿」作为输入单元，学习像素层面的空间统计规律。

### 表征方式的本质差别（最大分界）

**Atlas：隐式表征世界**

| 特点 | 说明 |
|---|---|
| 内部状态 | 场景信息**隐式保存在 KV 缓存/潜向量**，**没有独立可单独取出的物体实体** |
| 实体绑定 | 物体、背景、光影全部揉在同一场景潜向量中，**没有显式客体绑定**。无法直接读取"苹果：红色、圆形、距离50cm" |
| 预测目标 | **输出像素图像**。哪怕理解 3D 几何，最终损失仍是"生成画面与真实画面是否一致"——本质是**可学习渲染器** |
| 记忆 | 用带相机位姿的图像帧集合做空间记忆，检索附近视图做上下文切换，**不维护物体持久属性**。物体被遮挡时内部表征易漂移 |

**本架构：显式客体 + 特征向量**

| 特点 | 说明 |
|---|---|
| 内部状态 | **显式拆分 `<obj0>`、`<obj1>`**，每个绑定一组特征向量（颜色、形状、曲面、距离、材质） |
| 实体绑定 | 物体身份独立。**苹果被遮挡，`<obj0>` 仍然保留它的颜色、形状属性** |
| 预测目标 | 预测**实体状态变化与关系变化**，不是渲染画面 |
| 绑定机制 | 原生做 binding problem——正是人脑 γ 振荡解决的那个问题。Atlas 没有专门设计，靠网络隐式学到 |

### 训练目标不同

| | Atlas | 本架构 |
|---|---|---|
| 损失函数 | 新视角下图像的重建/生成损失 | 实体特征预测 + 关系预测 + 动作导致的状态变迁损失 |
| 学到什么 | 场景长什么样、换角度画面怎么变 | 物体 A 的属性在动作后怎么变、A 与 B 的空间/包含关系、动作序列规划 |
| 擅长 | 3D 重建、场景漫游、新视角生成 | 机器人执行长任务 |
| 短板 | **物体身份维持、抽象因果推理、长时序规划不是原生能力** | 视觉渲染质量远不如 Atlas |

> 类比：**Atlas 像大脑的视觉皮层 + 空间成像模块；本架构是在感知之上额外做了客体抽象、关系记忆、因果规划的联合认知系统。**

### 推理方式不同

**Atlas：** 仍是自回归生成，只是 token 换成图像 patch。生成新画面时按顺序预测，成本随场景上下文增大而上涨。内部向量是**场景全局潜向量，不能直接做物体间的关系代数运算**。

**本架构：** 公共语义向量**可直接做关系运算**。计算"衣服"与"洗衣机内部"的包含关系、洗衣液倾倒后的位置体积变化，**不需要生成像素就能完成规划**。

### 能力边界对比

| 项目 | Atlas | 本架构 |
|---|---|---|
| 核心能力 | 3D 重建、新视角渲染、空间几何 | 多感官融合、实体绑定、关系建模、具身规划 |
| 世界表征 | 隐式场景表征，无独立对象 | 显式独立实体 + 特征向量 |
| 输出产物 | 图像/视频画面 | 实体状态更新、动作规划（渲染可选） |
| 物体身份追踪 | 隐式，遮挡易丢失 | 原生实体 ID，物体持久存在 |
| 推理位置 | 图像潜空间 | 抽象客体语义向量空间 |
| 适合任务 | 场景重建、数字孪生、3D 漫游 | 机器人长任务、物理因果推理 |

### 不是二选一，可以组合

```
Atlas（视觉/3D 感知专家，输出几何与空间信息）
    ↓
本架构公共语义空间（转成 <obj0><obj1> 实体特征向量）
    ↓
关系推理 + 世界模型 + 任务规划
```

> **Atlas = 强大的视觉 3D 感知专家模型（相当于本架构视觉专家模块的升级版）**
> **本架构 = 感知之上的上层认知、关系推理、规划系统**

### 一句话区分

- **Atlas 回答**：从这个新相机位置看过去，场景长什么样子？
- **本架构回答**：如果我执行这个动作，各个物体会发生什么变化，能不能达成目标？

## 8.3 与主流真机 VLA 架构的差异（宇树 / Optimus / Helix）

> **前置声明，必须先说清楚：**
> 宇树、Figure、特斯拉都是**已经在实体机器人上真机落地的 VLA（视觉-语言-动作）架构**；
> 本架构目前停留在**理论推演 + numpy 原型 demo**，没有仿真大规模训练，没有真机部署。**成熟度差距是数量级的。**
> 三家厂商的完整内部实现并未全部公开，以下描述基于官方技术博客、论文与公开发布信息。

### 三家分别是什么

**① 宇树 UnifoLM-WLA-1.0（World-Language-Action，6B）**

| 项 | 内容 |
|---|---|
| 底座 | UnifoLM-ER-1-4B，基于 **Qwen3-VL-4B**；WLA 整体 6B |
| 数据 | 约 **2500 小时真机数据** + 500 万+ 具身推理样本 |
| 覆盖 | 单模型 64 项任务（54 桌面 + 10 全身），支持平行夹爪与两种灵巧手 |
| 结构 | 视觉、语言、**动态区域 Token**、动作 Token 进同一个多模态模型；再加 **MMDiT Action Expert** 把离散 token 解码成连续动作（末端位姿 / 关节 / 夹爪） |
| 演进路线 | WMA（世界-动作）→ VLA（视觉-语言-动作）→ WLA（世界-语言-动作）：**先预测"哪里会变"，再生成"怎么动"** |

**② Figure Helix（快慢双系统 VLA）**

三家里**分层最明确**的一个：

| 系统 | 角色 | 模型 | 频率 |
|---|---|---|---|
| **System 2** | 慢思考：场景理解、语言理解 | 7B 互联网预训练 VLM | **7–9 Hz** |
| **System 1** | 快反应：视觉运动控制 | 80M 跨注意力 Transformer（仿真预训练视觉骨干） | **200 Hz** |

S2 把所有语义、任务相关信息**压缩成一个连续潜向量**，经共享内存传给 S1；S1 以该潜向量为条件，输出 35-DoF 全身连续控制（腕位姿、手指屈伸、躯干与头部朝向），并额外预测一个"任务完成百分比"动作用于自行判定终止。

> 两系统**端到端联合训练**，通过潜向量通信。

**③ 特斯拉 Optimus**

| 项 | 内容 |
|---|---|
| 范式 | **端到端单网络**：相机 + 本体感觉 → 单一神经网络 → 关节指令 |
| 中间层 | **无独立人工设计的感知/规划/执行模块**，无规则中间层 |
| 视觉底座 | 与 FSD 自动驾驶**同源**的视觉基础模型 |
| 训练 | 模仿学习 + 仿真强化学习 |
| 语言 | V3 集成 Grok 补充语言理解 |
| 硬件 | 纯视觉、无激光雷达；AI5 芯片端侧推理 |

> ⚠️ **特斯拉内部细节公开极少**，上表多为报道与行业推演，不排除有未披露的中间模块。

### 核心维度对比

| 维度 | 宇树 WLA / Helix / Optimus | 本架构 |
|---|---|---|
| **表征介质** | 骨干是 VLM/Transformer，内部是**潜 token 序列**；Helix 层间只传**一个压缩潜向量** | **显式客体 slot + 特征向量 + 关系向量**，挂在公共语义空间 |
| **实体状态** | 隐式藏在权重/潜向量里，**没有可单独读取、单独追踪、单独写回的实体** | 独立 `<obj>` 槽，可检索、可追踪、可持久化、可热更新 |
| **世界模型目标** | 宇树的"世界"是**动态区域预测**，服务动作生成；Optimus 是端到端直接映射 | **实体-关系状态推演**：预测哪个物体、哪条关系怎么变，**不预测像素/潜帧** |
| **中间结构** | Optimus 无显式中间表征；Helix 双系统但 S2→S1 只过一个潜向量 | 多级**模块化流水线**，模块间传标准化向量，可异构、可局部替换 |
| **语言的地位** | 语言是骨干的**一等输入通道**（VLM 底座） | 语言只是**末端读出头**，不参与底层推理 |
| **训练范式** | 端到端联合训练（Helix 双系统也是端到端），靠大规模真机/视频数据 | **分阶段流水线训练**，上游冻结、下游单独训，模块可热更新 |
| **可读性** | 潜空间黑盒，难直接读出"杯子在桌上"这条事实 | 关系向量可直接做事实查询与检索 |

### 最值得对比的一处：Helix 的快慢分层 vs 本架构的焦点分层

这是三家里与本架构**唯一有几分神似**的地方，但目标完全不同：

| | Helix | 本架构 |
|---|---|---|
| **分层依据** | **速度**：S2 慢思考 / S1 快反应 | **记忆**：持久 3D 场景库 ↔ 焦点工作记忆 ↔ 推理引擎 |
| **层间传递** | **单个连续潜向量**（语义压缩包，不可拆分客体） | **结构化客体集合**：哪几个 obj、各自特征、彼此关系 |
| **实体可见性** | 潜向量内部不区分独立物体实例 | 客体在层间是**独立可读写单元** |
| **解决的问题** | 实时性：既要泛化又要 200Hz 控制 | 实体归属：遮挡、复现、长时序追踪、多实体混淆 |

> **Helix 的分层解决"快与慢"，本架构的分层解决"记得住与算得清"。**
> 两者可以叠加，但目标不同。

### 主流 VLA 路线的真实优势（必须客观陈述）

| 优势 | 说明 |
|---|---|
| **不需要人工定义中间接口** | 感知-规划-控制的接口由学习自动对齐，人的先验错误不会被写进架构 |
| **数据规模化泛化** | 互联网视频 + 海量真机示范喂给预训练 VLM，可零样本抓取数千个未见过的物体 |
| **工程闭环已跑通** | 三家都在真机上执行真实任务；本架构连仿真验证都还停在 numpy 阶段 |

### 本架构的主张性差异（仍是假设）

| 主张 | 说明 | 状态 |
|---|---|---|
| **实体可显式持有** | 遮挡、物体消失重现、长时序追踪、碎片溯源（7.4）有结构性抓手，不靠隐式表征硬扛 | ⚠️ 未验证 |
| **关系可直接运算** | 动作规划在实体-关系空间完成，不必经过 token 自回归 | ⚠️ 未验证 |
| **模块可局部更新** | 新增规则只动推理模块；实例知识不进权重（8.6） | ⚠️ 未验证 |
| **显式长期状态** | 3D 场景图 + 注意焦点（7.3）承接它们藏在潜向量里的那部分 | ⚠️ 未验证 |

### 边界与免责

1. **不排除 VLM 预训练后内部已隐式学到物体概念**——只是不外露、不可单独读写、不可持久保存。本架构的差异在于"显式可得"，不在于"它有我没有"。
2. 本架构所有优势目前**只在简易 demo 里验证链路可行性**，无大规模鲁棒性测试、无真机。
3. 行业趋势（"VLA 已死，世界动作模型当立"这类判断）说明端到端路线也在往世界模型方向走——**两条路线在靠拢，不是对立**。

### 一句话区分

| 方案 | 回答的问题 |
|---|---|
| 宇树 WLA | 先预测哪里会变，再生成怎么动 |
| Figure Helix | 慢想目标、快做动作，如何同时兼顾泛化与 200Hz |
| Optimus | 能不能用一条端到端网络直接吃掉感知到控制 |
| **本架构** | **世界状态存在哪里、由谁持有、能不能单独读写与更新** |

## 8.4 即使 LLM 能力无限强，也解决不了的范式约束

### 先划清能解决的部分

假设 LLM 无限强、无限上下文、完美 KV Cache、极强规划与纠错能力，以下问题确实**会大幅改善**：

- 高层任务规划：写洗衣服步骤、识别前提、生成备选方案、处理简单异常
- 抽象推理、常识、长链条逻辑、自然语言交互
- 把视觉观测的文本描述转换成动作指令

> 也就是**任务的"思考脚本"**这一层，理论上可以做到近乎完美。

现在很多机器人方案就是这条路：**LLM 作高层大脑 + 视觉模型 + 底层控制器**。

### 但这一层补不上（范式自带，不是能力不足）

根源：**LLM 的内部状态没有原生独立实体表征，所有世界状态都要编码到离散 token 序列里。**

哪怕无限参数、无限上下文，以下缺陷依然存在。

**① 实体绑定问题（Entity Binding）**

LLM 没有"永久独立槽位"来固定一个物理实体。所有物体信息只是上下文里的文字描述：`衣服A、衣服B、洗衣机、洗衣液瓶`。

当场景复杂、实体多、发生遮挡、位置动态变化时，**文本描述很容易混淆实体**。哪怕 LLM 很聪明，也只能靠语言描述区分 A 和 B；描述一旦有歧义或观测有噪声，就会认错。

> 本架构：衣服 A、衣服 B 天然是两个独立 slot 向量，**身份由底层保障**，不靠文本描述区分。
> **关键点：LLM 只能描述实体，不能持有实体本身的稳定表征。**

**② 连续物理量与动力学的符号转译损耗**

物理世界是连续的：坐标、距离、速度、角度、形变、摩擦力。LLM 只能接收离散文本：`距离大约0.2米`。

- 连续量必须先量化、翻译成文字；执行时还要把文字再转回控制量
- **两次转换必然丢精度、引入噪声**
- LLM 学到的是**文本里的物理常识**，不是真实连续动力学。它可以"知道苹果会掉"，但很难原生地做毫米级实时状态迭代

**③ 状态存储开销的底层缩放规律**

LLM 上下文开销随状态信息量**超线性增长**。哪怕 KV Cache 优化得再好：实体越多、时序越长，要写入上下文的描述就越多。

向量 slot 架构：实体数量固定时开销基本恒定，只更新变化的关系向量，不变属性不重复存储。

> **这并非模型不够聪明的问题，而是状态编码方式带来的复杂度差异。** 单纯提升模型能力无法改变复杂度。
> **运行时的具体机制（每步读什么、为什么不重读历史）见 5.4。**

**④ 感知噪声下的概率性状态维护**

传感器永远带噪声：观测结果是置信度，不是非黑即白的事实。

LLM 输入是"观测翻译成的确定文本"，很难原生维护**概率场景状态**（`衣服 in 洗衣机，置信0.82`）。它擅长离散命题，不擅长在高维连续概率空间维护实体状态。

向量架构天然是相似度/置信度表征，**直接处理模糊观测**。

### 洗衣服例子对照

> 场景：倾倒洗衣液，摄像头拍到洗衣液洒在地上，没进洗衣机。

**超强 LLM 方案：** 视觉模型翻译成文字"洗衣液洒落在地面，没有进入洗衣机"，追加进上下文。LLM 读到后推理：需要清理、重新取洗衣液。
- 问题：所有物体状态必须反复写在上下文；实体多了容易混淆；视觉到文本的翻译本身丢连续空间信息。
- **LLM 解决的是：看懂这段文字之后该采取什么高层动作。**

**实体向量架构：** 视觉前端直接更新关系向量，只改这一条关系，其余客体状态完全不动；规划器直接在向量空间检测异常。

> **LLM 强，是"理解文字描述"的能力强；但它没有一个原生的"世界状态内存"来存放物理实体。**

### 正确的分工

| | 擅长 |
|---|---|
| **LLM** | 高层抽象、自然语言、任务拆解、常识推理、人机交互、生成方案、处理全新抽象任务 |
| **实体向量世界模型** | 实时场景状态保存、实体追踪、连续物理动力学、传感器概率闭环、长时序具身执行 |

> **最优工程方案是组合**：实体向量架构维护底层物理场景状态；LLM 作高层语言/抽象规划器，读取向量空间提取出来的事实，处理复杂抽象决策。

### 一句话

> **更强的 LLM 可以大幅简化高层规划、常识理解、人机交互；但 token 范式天生缺少独立实体 slot 与原生连续状态表征，实体绑定、连续物理闭环、长时序状态开销这些底层约束，无法仅靠提升能力根除。**

## 8.5 与外挂知识库的本质区别：符号接地

### 一个真实的质疑

看到本架构的实体与关系表示：

```
<obj1> : {类别:衣服, 材质:棉, 状态:干燥, 位置:衣架}
<obj2> : {类别:洗衣机, 状态:待机, 内部:空}
关系：包含、接触、可放入、可倾倒
```

**第一反应必然是：这不就是一个关系型知识库？不就是给 LLM 外挂的规则库？**

静态数据视图上，几乎看不出差别。很多 Agent 项目给 LLM 挂知识图谱、数据库，看起来完全一样。

**但存在一层本质鸿沟。**

### 核心差异一句话

> **LLM + 外挂知识库：知识库是文本符号数据库，LLM 是 token 推理器，两者之间存在符号接地问题（symbol grounding problem）。**
> **本架构：`<obj>` 与特征、关系不是文本符号，而是和多感官感知绑定的向量表征；推理是在统一语义空间里直接做实体、属性、关系的向量运算。**

### 差异一：存储内容 — 文本符号 vs 感官绑定向量

**LLM + 知识库：**

```json
{"obj1": "衣服", "属性": "干燥，材质棉，位置衣架",
 "关系": "衣服可以被放入洗衣机"}
```

`"衣服"` 仅仅是**文字标签**。模型本身不知道"衣服"长什么样、摸起来什么手感、体积多大。只能读懂**token 构成的句子**。

> **符号接地问题：符号与真实物理世界没有原生绑定**，全靠 LLM 的文本先验去脑补。
> 遇到全新物体（从未在文本里见过的新型面料），符号就是空洞的文字，**模型没有对应的感知表征**。

**本架构：**

`<obj1>` 不是字符串标签。它是**实体标识，挂载一组来自视觉专家、触觉专家输出的特征向量**：
- 视觉向量：轮廓、曲面、颜色、纹理、距离、3D 尺寸
- 触觉向量：软硬、粗糙程度、形变特性
- 属性和关系同样编码为**公共语义空间内的向量，不是文本**

> 这个 `<obj1>` 是**感知-概念绑定的实体**，不是文字。
> **哪怕这个物体没有名字、没有文本描述，只要视觉触觉采到信号，就能生成实体向量并推理。**

### 差异二：推理方式 — token 预测 vs 向量关系运算

**LLM + 知识库流程：**

```
1. 接收任务：把衣服放进洗衣机
2. 从知识库检索符号事实：衣服可以放入洗衣机
3. 把检索到的文本塞进 prompt
4. LLM 逐 token 生成下一步文本（基于统计预测下一个词）
5. 再解析文本，翻译成机器人动作指令
```

**推理发生在文本 token 空间，所有物理推演都是语言层面的模拟——它是在"用文字想象世界"。**

**本架构流程：**

```
1. 视觉感知提取向量，生成 <obj1>衣服、<obj2>洗衣机
2. 公共语义空间内直接计算关系：
   - 衣服向量 与 洗衣机内部区域向量 是否满足「可包含」约束？
   - 执行【移动衣服】动作，预测两个实体关系向量如何变迁
3. 输出实体状态变更 + 动作指令，不需要生成文本作为中间步骤
```

**推理直接在实体语义向量空间做关系运算——它是在"操作世界实体的内部表征"。**

### 差异三：实体绑定 — 符号主键 vs 持续追踪的感知实体

**LLM + 知识图谱：**

图谱里的 `obj1` 只是数据库主键。**主键和现实世界物体没有自动绑定**。需要额外一套视觉模块识别画面，再手动映射到字符串 ID。

物体被遮挡、移动导致识别出错 → **ID 映射断裂，整个知识库错乱**。

> 图谱本身没有能力从连续感官流里自动维护物体身份。

**本架构：**

`<obj>` 实体 ID 是**从感知流里持续跟踪出来的**。视觉专家输出的 3D 特征向量做跨帧关联：衣服被部分遮挡，只要特征向量匹配，仍绑定同一个 `<obj1>`。

> **实体绑定是原生内置能力，不是外挂附加功能。**

### 差异四：学习机制 — 文本记忆 vs 多感官经验内化

**LLM + 知识库：**

只能存储**预先写好的静态事实**。机器人在现实世界试错得到的感官经验（比如这件棉衣服泡久了会变形），**不会自动转化入库**。要新增这条知识，必须人写成文字插入。

> **模型无法自主从感官体验里归纳出新关系。**

**本架构：**

机器人实操后，多感官采集新向量，**自动更新实体属性与关系向量**：
- 单次经验 → 更新实例级实体状态（**不需要训练权重**）
- 多次重复同类经验 → 归纳出通用关系向量（可选少量微调内化规则）

> **可以从物理交互经验里自主学到新因果关系，不需要人把经验翻译成文字。**

### 对比表

| 维度 | LLM + 外挂知识图谱/RAG | 本架构 |
|---|---|---|
| 存储单元 | 文本符号/字符串 | 实体 ID + 多感官融合特征向量 |
| 接地性 | **符号与物理世界间接绑定，存在符号接地问题** | 向量直接来自视觉、触觉，**天然接地** |
| 推理载体 | 文本 token 自回归 | 实体向量间直接关系运算，文本是可选输出 |
| 实体 ID 来源 | 人为定义主键，需外部系统映射 | 感知流自动分配、跨帧持续追踪 |
| 经验学习 | 需人类把感官经验转成文字 | 可直接从感官交互产生新实体、新关系 |
| 核心定位 | 语言模型 + 外部事实数据库 | 多感官感知 → 客体抽象 → 向量空间因果推理 |

### 一个必须澄清的误区

> "向量数据库不就是你这个？"

**向量数据库依然是把文本 embedding 成向量，源头还是文字。**

而本架构的特征向量源头**不是文字，是原始感官信号（图像、触觉压力信号）**。

**这是最根本的分界。**

### 小结

> 虽然实体、属性、关系在静态层面看起来类似外挂关系知识库，但二者本质不同：LLM + 外挂知识库存储的是**文本符号**，推理依赖 token 预测，符号与物理世界需要人工桥接，存在经典的符号接地难题；而本架构中，实体表征源于视觉、触觉等多感官输入的特征向量，实体 ID 由感知系统自动追踪维护，因果推理直接在向量语义空间完成，不需要文本作为中间媒介，系统可从物理交互的感官经验中自主学习新的物体关系。

## 8.6 持续学习：为什么能不完全依赖重训

> **后文更新**：本节解释「为什么能不重训」。具体到**谁有权改、改到什么程度、哪些必须留在离线**，见 **9.6**（L1–L4 权限隔离、L2 原型数据结构、新原型准入门槛）。

### 问题的根源

传统大模型最大的问题：**只能一次性预训练，完成后权重固化，想改只能重训**。

人脑不是这样：一辈子持续增量学习，学新东西不会把旧的全部抹掉。

**根源在哪？**

> Transformer 的权重是**全局共享**的。知识弥散在全部参数里，**没有独立实体分区**。
> 修改任何一小块知识，都会扰动其他所有知识。

这就是灾难性遗忘（catastrophic forgetting）的结构性成因。

### 现有大模型的增量学习方案（都不需全量重训，但各有短板）

| 方案 | 做法 | 短板 |
|---|---|---|
| **RAG 检索增强** | 不改权重，新知识存外部向量库，推理时检索塞进上下文 | **不是"学会"，只是临时读取**；不会内化；复杂因果推理易断 |
| **LoRA / QLoRA** | 主模型冻结，只训练少量低秩适配器 | 一个 LoRA 是一套独立技能；**叠加多个会冲突**；新知识污染旧知识，仍有遗忘 |
| **Memory 模块** | 独立记忆库存事件与实体属性，模型读取 | 和 RAG 类似，**记忆在模型外，不是底层表征更新** |
| **在线持续学习（CL）** | 流式数据小幅更新权重，用 EWC、MAS 等方法对抗遗忘 | 约束随任务增多越来越复杂，**容量慢慢耗尽**，最终仍会遗忘，只适合小范围增量 |

> **共性短板：知识没有独立实体分区。**

### 本架构的路径：两层分开更新

核心优势：**知识不是全部弥散在网络权重里，一部分放在独立实体对象、特征向量、关系库中。**

**第一层：感知专家 → 可以局部增量更新**

视觉专家负责从图像提取特征向量。不需要每学一个新物体就重训整个视觉模型。

方案：
- 少量样本的 **LoRA / 元学习**，遇到新物体（如没见过的洗衣液瓶），只用少量图片在线微调视觉专家
- 加 **EWC 持续学习约束**，保护之前识别苹果、衣服、洗衣机的能力

**第二层：公共语义空间 + 实体关系库 → 可以不改权重直接改知识（最大亮点）**

实体和关系是显式存储：

```
<obj1>：{类别:衣服, 材质:棉, 状态:干燥, 位置:衣架}
<obj2>：{类别:洗衣机, 状态:待机, 内部:空}
```

当机器人获得新经验：

> 例：发现这种洗衣液不能直接倒在衣服上，必须倒进料盒

✅ **不需要修改底层模型权重，直接修改实体间关系向量/关系知识库。**
推理网络保持冻结，只更新 `<洗衣液>` 与 `<洗衣机料盒>` 的关系。

| | 要记住这件事 |
|---|---|
| LLM | 必须修改模型权重，或依赖 RAG 上下文 |
| 本架构 | **实体关系是独立存储的向量，直接写入语义空间，推理器直接读取，不碰权重** |

**第三层：推理器本身 → 慢速在线微调（只在学通用规则时）**

如果学到更深层的通用因果规则（如所有液体的倾倒物理规则），才需要微调推理模块。因为表征是实体向量间的运算，可以用 EWC：
- 标记负责基础物理规则（物体不能穿透、重力）的权重，**锁定**
- 只微调与新规则相关的一小部分权重，**最大限度避免遗忘**

### 关键区分：两种不同的"学习"

| 学习类型 | 例子 | 本架构的处理 |
|---|---|---|
| **实例级知识** | 这个杯子是蓝色、放在桌上 | **直接写入实体库，零权重更新**。这就是实时在线学习，类似人脑的情景记忆 |
| **通用概念知识** | 所有玻璃杯易碎、液体会流动 | 方案 A：存在关系知识库，不改权重<br>方案 B：少量样本在线微调（LoRA + EWC），内化通用规则 |

> **人脑也是这样**：单次看到一件事形成情景记忆（不修改底层突触主干）；反复多次经历，才慢慢修改突触，固化成长期通用概念。

### 仍然存在的难点

| 难点 | 说明 |
|---|---|
| **实体绑定漂移** | 在线持续观察时，如何保证 `<obj0>` 始终指代同一个物体，遮挡/移动后不混淆 ID。这是类脑持续学习的核心难题 |
| **关系库容量上限** | 实体和关系越存越多，需要类似人脑的记忆压缩与遗忘机制——不重要的旧关系慢慢衰减，重要的保留 |
| **感知专家遗忘** | 视觉小模型反复在线学新物体，久了识别旧物体能力下降，需要持续学习算法保护 |

### 一句话总结

> 传统大模型知识弥散于全局权重，新增知识难以增量更新；而基于显式客体公共语义空间的架构，将**实例记忆从神经网络权重中剥离**，实体属性与物体间关系可直接写入语义向量库，**无需重训主模型**；仅当学习通用物理/因果规则时，使用 LoRA + EWC 等持续学习方法做局部在线微调，抑制灾难性遗忘。

## 9.1 模块化的真实边界：热插拔、坐标漂移与故障裁决

### 9.1.1 必须分开的两样东西

"专家重训会不会拖垮模块化"这个争论，根源是把两件事混成了一件：

| 对象 | 内容 | 上游专家重训时 |
|---|---|---|
| **公共语义空间的"外壳规约"** | 维度、L2 归一化、bind/unbind 算子定义、原型库中已存的原型 | **不变**。全体下游共用的固定靶空间 |
| **某模态到靶空间的"映射函数"** | 该感官专家权重 + 它专属的 MLP 投影头 | **必须变**。全参重训会重构内部特征坐标系，旧适配器失效 |

> 一句话：**靶子没换，换的是瞄准镜。**
> "投影头要重训"不等于"公共语义空间要重训"——后者意味着重定义坐标系、作废全部历史实体向量。

### 9.1.2 变动链与两种流程

全参重训一个感官专家，需要重训的只有：

```
[该感官专家] + [该专家专属 MLP 投影头]
```

不需要动的：绑定模块、工作记忆、推理引擎、世界模型、原型库、其他模态通路、全部输出头。

| 操作 | 端到端 VLM | 本架构 |
|---|---|---|
| 完整重训视觉编码器 | 整模型联合重训 | 仅【视觉专家 + 视觉投影头】重训 |
| LoRA 微调（保持输出分布） | 仍扰动主干，需联合微调 | 旧投影头可复用，下游零改动 → **真热插拔** |
| 新增一个模态 | 整体重新联合训练 | 只新增该模态专家 + 投影头 |

> 热插拔的成立条件：**输出表征契约（分布、坐标系、归一化）兼容**。这与软件工程同构——接口签名不变的实现类可热替换；接口数据语义变了，适配层必须改。

| 动作 | 性质 | 流程 |
|---|---|---|
| LoRA 增量、加类别、加能力 | 热插拔 | 复用旧投影头，下游零改动，小样本验证即上线 |
| 全参重训 / 换骨干 | 版本升级 | 新专家 + 新投影头离线训练 → 对齐校验 → A/B 灰度 → 整体切换 |

> 把"版本升级"要求成零成本，是把工程期望错置到架构定义上；把版本升级说成"模块化失效"，同样不成立——**隔离收益仍在：重训与故障被限制在感知前端的一条通路。**

### 9.1.3 坐标漂移与冻结锚点

新视觉通路若校准不到位，会出现：视觉看到苹果的输出落到桃子原型附近，而触觉的苹果向量还在旧位置 → **同物跨模态向量距离拉大，融合失效**。

> **地图类比**：地图图纸（维度、原型地标）一字节没改，换的是 GPS 接收机；新 GPS 没校准，苹果就被投到错误经纬度。**地图没坏，是转换器算歪了。**

只有单路失真：触觉通路、原型库、推理内核全部完好——只用触觉输入，系统仍能正确识别。

正确的重训姿势是**拿不动的锚点做监督**：

```
冻结：其他模态专家与其投影头、原型向量库（梯度关闭）
冻结：新专家骨干（只训它的 MLP 投影头）

正样本对：新视觉(苹果) ↔ 旧触觉(苹果)；新视觉(苹果) ↔ 冻结的苹果原型
负样本对：新视觉(苹果) ↔ 杯子 / 橙子的原型与触觉样本
```

> 目标不是让它随便找个新位置，而是**强迫对齐已固定的锚点**。
> 诚实边界：同步配对数据质量差、样本少时，约束再严也会漂移；但故障被局限在该模态通路。

### 9.1.4 谁裁决：没有金标准

原型向量不是上帝常量，而是**历史多模态观测的统计中心**，它继承了旧硬件与旧模型的系统性误差。于是有三种可能，不能预设答案：

1. 新视觉坏了；
2. 旧触觉本身一直有系统偏差；
3. 两者都有小偏差，误差叠合后才暴露。

| 场景 | 裁判 | 做法 |
|---|---|---|
| **离线（版本升级）** | **同一实例、同一时刻的多传感器同步配对数据**（物理事实，不依赖任何模型自述） | 策略 A 保守迭代：冻结其他模态与原型，只训新投影头；策略 B 全模态重对齐：解冻、更新原型，代价是**历史实体向量作废** |
| **线上（无标注）** | 没有裁判，只能暴露冲突 | 各通路输出向量 + 置信度（工况、不确定性、历史出错率、时序连续性）→ 加权融合 `Z=(Cv·V+Ct·T)/(Cv+Ct)`；两路都高置信却冲突 → 打【观测冲突】标记交上层，主动多看/多摸来消解 |
| **原型更新** | 四条门槛全满足才允许 | 离线、海量高质量样本、统计上系统性偏离、已评估历史库迁移代价 |

> ❌ 线上绝不因单次观测冲突改写原型库——一次噪声就能污染地标。
> 策略选择的依据是数据：若校验集反复显示"旧触觉与物理同步观测矛盾"，则旧触觉才是故障源，应转策略 B。

### 9.1.5 实践检验与控制变量

实践是**最高裁判，但不是根因探针**：它回答"有没有病"，不回答"病灶在哪"。

```
Step 1 基线复现：切回旧视觉+旧投影头，其余全不动
        性能立即恢复 → 锁定【新视觉专家/投影头】链路
Step 2 链路内二分：新专家原始特征 + 旧投影头
        恢复 → 投影头训练不到位；仍差 → 专家本身特征质量
Step 3 怀疑触觉时：只替换触觉输入为历史可靠样本，其余不动
```

**陷阱一：多模态补偿效应（最易误判）**

旧系统触觉有偏差、旧视觉误差刚好互补，融合后表现很好；换新视觉后补偿被打破，缺陷暴露，性能下跌。切回旧视觉又恢复——极易把锅甩给新视觉。

> 对策：**必须补单模态隔离评测**。若"旧视觉一般、旧触觉很差，但融合后很好看"，说明旧系统靠补偿掩盖缺陷，此时不应让新视觉迁就错误触觉，应转策略 B。

**陷阱二：分布漂移冒充模型故障**——新摄像头光学参数改变导致分布偏移，控制变量仍能定位到视觉通路，但需区分"权重问题"与"硬件环境变化"。

**边界**：控制变量只定位"哪条链路"，不告诉"怎么改"；样本量、正负配比、损失权重仍需人工分析。

### 9.1.6 上线验收清单

**重训某模态投影头**

## 9.2 表征与推理主干：注意力、`<obj>` 与绑定的数学边界

### 9.2.1 多头双向自注意力：能放哪，不能放哪

标准 Transformer 编码器隐含一个前提：输入是一维有序 token 列表，**没有实体槽归属**。直接照搬会给本架构带来三个问题：

1. **丢失 slot 身份**：只看向量内容，多层融合后不同客体特征无约束渗透（正是 5.7"归属必须显式"要防的）；
2. **隐含顺序敏感**：物理实体集合无一维次序；
3. **破坏可逆解构**：多层非线性混合后无法可靠 unbind，五类算子的基础被动摇。

| 位置 | 是否可用 | 说明 |
|---|---|---|
| 感官专家（ViT） | ✅ | 像素/patch 级提取，属感知前端；patch 不能直接进公共空间 |
| MLP 投影头 | ❌ | 线性 + LN + GELU 即可 |
| bind/unbind | ❌ | 纯逐元素运算，必须可逆 |
| 推理引擎 / 世界模型 | ⚠️ 两条路线 | 见下 |
| 文本读出头 | ✅ | 条件 Decoder，语言只作输出 |

**路线 A（基准，Demo 路线）：完全不用自注意力**

余弦相似度（检索）、向量运算（比较）、bind/unbind（组合解构）、MLP 世界模型（状态预测）。
✅ 可逆性完整、训练目标清晰；❌ 物体多、交互复杂时对两两及间接关系建模弱。

**路线 B（增强）：实体-集合改造版轻量注意力**

四点改造：输入是已绑定的完整 `<obj>`（一个单元 = 一个物理物体）；移除位置编码；**Value 只输出客体间关系向量，不携带原始特征**；**客体自身特征原地不动**。

> ⚠️ 红线：**注意力只能算"A 与 B 是什么关系"，不能改写"A、B 自身是什么"。**

**训练目标**：不是预测下一个 token，而是**预测每个 `<obj>` 下一时刻的公共语义状态**；文本损失只是读出头的辅助项。

### 9.2.2 `<obj>` 的两层结构

```
逻辑视角（结构体）          计算视角（公共空间坐标）
<obj0>                      obj = (Fv⊙Sv) + (Ft⊙St) + ...
├─ slot 基向量（固定）        ← 逐元素乘法打归属标记
├─ 各路绑定向量             ← 可 unbind 拆回各路 F
└─ 元数据：ID/置信度/位姿/时间戳  ← 不参与向量运算
```

- **一个模态公共特征 = 一个点**：单次观测的猫外观就是单个 $F_v$；多个实例或多时刻才成点云，原型是点云中心；
- `<obj>` 是**容纳这组点的容器**，本身不是向量点；
- 对比方案 B（相加合并）：混成一个点，无法提取纯外观分量。

> **为什么猫狗相似**：LLM 里 `"猫"`、`"狗"` 接近，来自文本共现；本架构里实体向量接近，来自**现实世界猫狗本身物理特征相似**。但相似度只反映观测到的感官，不是内置生物学知识——外观酷似真狗的机器狗，只有接入触觉才会被推开。

### 9.2.3 加法的数学边界：信息坍缩

$$
unbind\big(bind(F_v,S)+bind(F_t,S),\ S\big)=F_v+F_t
$$

| 运算 | 性质 |
|---|---|
| $unbind(bind(A,S),S)=A$ | ✅ 单分量可无损还原 |
| $unbind(bind(A,S)+bind(B,S),S)=A+B$ | ⚠️ 只得总和 |
| 由 $A+B$ 反推 $A,B$ | ❌ 数学上无唯一解 |

二维例子：$obj_0=[0.9,0.55]$，$S_0=[1.0,0.5]$ → $unbind=[0.9,1.1]$，恰等于 $F_v+F_t$，无法再拆。

> **责任在加法，不在绑定算子**：bind/unbind 可逆，`+` 聚合毁掉了可分离性。
> 原 Demo 是单模态属性检索（不需要逐个拆解，只做相似度打分），**一旦跨模态相加就失效**。

三条路线：**A 各模态独立不放加（推荐）** / B 保留相加只做打分（仅原型验证） / C HRR 卷积绑定（绕不开加法解混约束）。

### 9.2.4 方案 A：实体为多模态向量集合

$$
obj=\{bound_v,\ bound_t,\ bound_g,\dots\},\quad bound_m=F_m\odot S_m
$$

**推理六步**：投影得各路 $F$ → 分别 bind（禁止相加）→ 与分模态原型库按置信度加权匹配 → 按需取某一路做关系对比 → 世界模型（A-1 分模态独立 MLP / A-2 concat 联合后 split，推荐后者）→ 读出头。

**训练要点**：slot 冻结、bind 为纯算子无可训参数；流水线顺序同 5.5/5.6；InfoNCE **作用在 unbind 后的原始公共特征上，不作用在 bound 向量上**；原型按模态分别聚类；世界模型**分模态独立 MSE 求和**。

> 收益：模态无损分离、单路失效不污染其他路、适配"看不见但摸得到"的真实工况。
> 代价：数据需分模态配对真值；实体由点变集合，下游 I/O 全要适配；内存与原型库规模上升；不能再用单次余弦比较两个实体。
> 未解决：投影头漂移（9.1）、实体同一性与碎裂（7.4）、unbind 近零分量噪声放大（需裁剪保护）。

## 9.3 识别链路：从观测到类别

### 9.3.1 一个点，还是一簇点

| 情况 | 结果 |
|---|---|
| 单次观测、单物、单模态 | **1 个向量点** |
| 同一只猫多角度/多时刻 | 一组略偏移的 $F_v$，绕原型成簇 |
| 很多只不同的猫 | 点云簇，聚类中心 = 【猫】原型 |

### 9.3.2 检索不必暴力全搜

先分清两类计算：

| 任务 | 访问原型库 |
|---|---|
| 实体识别（这是什么） | ✅ 需要 |
| 实体-实体关系（比大小、包含） | ❌ 不需要，只用工作记忆内特征互算 |

识别路径的四级裁剪：

1. **场景上下文**（3D 场景图先验）把全库缩成场景高频候选；
2. **模态掩码**按置信度跳过不可用模态；
3. **ANN 索引**只召回 top-K，精确余弦仅在少量候选上执行；
4. **帧间跟踪复用**：已识别物体后续帧只做特征校验，达标即跳过原型检索，只有遮挡/形变/光照剧变才重检索。

```
unbind 取特征与置信度 → 上下文裁剪 → 模态过滤
→ 各模态 top-K 求交 → 短列表内精确余弦 → 置信度加权输出
```

> 边界：无场景先验时退化为 ANN 全库近似检索，但**仍不会对全部原型做精确余弦**；ANN 有极小漏检，需留召回余量。

### 9.3.3 分层原型树：由宏观到微观

节点存分模态原型集合 `{vision, tactile, geometry, infrared}`，不是文本标签。

```
根
├─ 活物 → 大/中/小/微型 → 猫 →（英短 / 布偶）、狗、鸡鸭鹅
└─ 无生命物体 → 家具 / 餐具
```

**建树**：完全由样本递归聚类生成，人工不写层级；离线校验分支语义，不合格就调超参重生成；**上线后树与节点全部冻结**。

**检索：置信度驱动的动态 top-N**

```
存在子节点 > T_high 且显著高于其余 → 只走该单分支（携带路径置信度）
否则取 top-N（≤ N_max）多分支并行
全部子节点低于下探阈值 → 终止该分支，停在当前层级
汇总候选 + 全局加权 → 不强制唯一答案
扁平 ANN 兜底交叉验证，冲突则标记高不确定性
```

| 风险 | 缓解 |
|---|---|
| 链式错误（上层错则全废） | 动态 top-N + 下探阈值 |
| 模态分支错位 | 各模态共同加权、多路径并行、最后融合 |
| 聚类语义不可控（按纹理聚成"带斑点物体"） | 校验调参全在离线，上线冻结 |
| 分支爆炸 | $N_{max}$ 上限 |

> 取舍：放弃人工语义树的可控性，换"树由数据流形自然生长"的贴合度。

### 9.3.4 活体与非活体：多线索证据，没有开关

| 线索 | 含义 | 主要干扰 |
|---|---|---|
| 热红外 | 活体特征温度辐射 | 热水杯、晒热石头；休眠/低温动物信号弱 |
| 自主运动 | 无外力时是否自主改变位姿 | 风吹窗帘；动物静止 |
| 局部周期性形变 | 呼吸、眨眼、胡须微动 | 距离远分辨率不足 |
| 自发声音 | 该位置自发产生生物类叫声 | 电子玩具播放录音；安静不发声 |
| 气味 | 与动物体味原型相似度 | 沾染他物气味；距离远 |
| 触觉接触 | 体表温度 + 软组织按压回弹 | 未接触则完全不可用 |
| 生物部件（静态） | 眼、耳、须、爪 | 玩偶可复刻，仅弱证据 |
| 目标导向行为 | 躲避、追随等 | 仿真机器人也能 |

融合规则：每条输出 $s_*(0\sim1)$ 与观测可靠度 $c_*$（条件不满足则 $c_*=0$ 不参与），加权平均或 D-S 融合；**无任何一票否决/一票确认**；结果作为**原型树根节点的附加证据**。

> 毛绒猫：部件 0.95，但热红外 0.10、运动 0.05、声音 0、气味 0.10 → 总活体置信被压低。
> 睡猫：整体不动 0，但热红外 0.90 + 呼吸形变 0.85 → 活体置信仍高。
> 结论：**单线索失效时，其余线索补位。**

### 9.3.5 嗅觉：强证据，但不是真理开关

理想条件（近距离、气味充足、环境干净、训练集完备）下，$C_{olf}\approx1$，**单靠嗅觉就能完成物种识别**——黑暗环境中视觉失效，嗅觉支路可独立沿原型树下行。

真实约束：气味**没有空间边界**（混合叠加难分离）、距离衰减、个体状态与沾染、人工电子鼻灵敏度差距。

> 规则：嗅觉与其他模态平等，无优先硬规则；$C_{olf}$ 自动调节权重；即便给出高相似度也要全局融合——避免"环境混杂导致把玩偶判成猫"。

## 9.4 推理模式全景

### 核心认知推理（5 类）

| 模式 | 输入 | 运算 | 输出 |
|---|---|---|---|
| **① 实例识别** | 单实体分模态特征与置信度 | 帧间校验 → 原型树动态 top-N + 根节点证据融合 + ANN 兜底 | 类别候选 + 置信度 + 属性 |
| **② 时序状态/轨迹预测** | 激活实体 + 位姿 + 待执行动作 | 世界模型推演多步（不止轨迹，还有形变、碎裂、腐烂） | 多步预测状态集合 |
| **③ 实体-实体关系** | 2+ 实体，按需 unbind | 几何算距离/接触/包含；属性算大小/软硬；结合世界模型判因果 | 带置信度的关系三元组 |
| **④ 目标驱动规划** | 当前实体、目标状态、动作库 | 识别状态缺口 → 迭代前向推演搜索动作链 → 校验前置条件 | 动作序列 + 每步预期变迁 |
| **⑤ 冲突检测** | 多路观测 + 预期状态 | 计算观测间、观测-预测间冲突度 | 冲突标记 + 建议主动观测 |

> 模式 ③ **不访问原型库**，计算量由工作记忆实体数（≤4–8）约束。

### 支撑辅助推理（3 类）

| 模式 | 作用 |
|---|---|
| **⑥ 实体追踪与同一性** | 特征-位姿关联，维持 `<obj_id>`；解体碎裂时生成碎片子实体（7.4） |
| **⑦ 注意力焦点调度** | 场景实体超容量时，按任务目标挑少数进工作记忆，其余休眠于 3D 场景图（7.3） |
| **⑧ 记忆检索** | 以查询向量在长期实体库、原型树中 ANN 检索 |

### 读出头（4 类，非推理）

文本头（条件 Decoder）、动作头（关节指令）、目标-价值头（内部驱动，不对外）、想象头（可选）。

> **关掉读出头，内部推理仍可完整执行。**

### 一条典型链路

```
任务：识别地面物体，若是活猫则驱赶到垫子上
① 追踪 → 生成 <obj0>
② 识别（原型树 + 活体证据；矛盾则触发冲突检测）
③ 关系（obj0 与垫子的空间位置）
④ 规划（调用时序预测推演动作序列）
→ 动作头输出；循环中追踪维持身份、注意力维持激活；需要人机交互才启用文本头
```

## 9.5 与 LLM 的分工：三个结构约束与一张总表

### 三个结构性约束

1. **状态序列化膨胀**：LLM 必须把位置、属性、置信度、冲突、历史全写成 token，交互步数越多上下文越长，开销 $O(N^2)$；KV-Cache 只加速，**不消除"全状态存在一维 token 序列"**。本架构休眠实体留在 3D 场景图，开销只随激活实体数 k（4–8）走。
2. **缺原生实体 slot**：LLM 靠字符串 ID，遇遮挡、消失重现、碎裂极易混淆；本架构有 `<obj>` slot + 位姿 + 特征维持身份。
3. **高频闭环不适合自回归**：距离计算、置信融合在本文是矩阵运算可并行；在 LLM 要转成文本算术，串行且易数值幻觉。

> 结论：**不是做不到，而是每帧调用代价极高，速度跟不上控制周期。**

### 边界：LLM 适合什么

✅ 高频任务策略、抽象常识、异常高层决策、人机自然语言交互。
❌ 每帧实体追踪、多模态证据融合、连续物理状态更新、低延迟关系判断。

现实 VLA 的妥协：感知输出结构化观测 → LLM **低频**输出高层动作 → 底层高频控制交给小模型。遗留短板是感知描述一旦有歧义，高层推理即被带偏。

### 一张总表（合并原分散对比）

| 维度 | 纯 LLM | 本架构 |
|---|---|---|
| 状态存储 | token 序列，随上下文膨胀 | 有限激活实体，不随步数膨胀 |
| 实体管理 | 字符串 ID，易混淆 | `<obj>` slot + 3D 场景图 |
| 多模态证据 | 转文本，置信表达笨拙 | 原生分模态向量，0–1 加权融合 |
| 高频闭环 | 自回归串行，宜低频 | 矩阵运算可并行 |
| 情绪/情感 | 藏在 token，易跳变 | 独立结构化状态（9.7） |
| 目标来源 | 靠 prompt，易跳变 | 需求+情感→动机向量，连续稳定（9.7） |
| 安全控制 | 易被 prompt 绕过 | 硬护栏并行，独立且不可绕过（9.8） |
| 故障响应 | 依赖 prompt，易幻觉 | 独立检测 + 分级降级（9.8） |
| 价值审计 | 藏在 token 与权重 | 三层隔离，打分明细可复现 |
| 离线能力 | 断网基本不可用 | 本地感知、原型库、安全护栏继续运行 |
| 强项 | 抽象符号、海量文本知识、语言创造 | 物理闭环、实体追踪、时序推演、证据推理 |
| 弱项 | 高频闭环算力、实体绑定幻觉 | 链路复杂、多模态数据门槛高、原生语言弱 |

> 一句话：**LLM 是这套架构的高层顾问，不是它的推理引擎。**

| 层级 | 内容 | 端侧权限 | 更新方式 |
|---|---|---|---|
| **L1 实例记忆** | 实例向量、观测快照、3D 场景图、关系记录、冲突样本 | ✅ 自主读写（实时） | 本机保存，不自动同步他人；候选样本/异常快照回传后台 |
| **L2 原型层** | 分层原型树节点、各类别原型向量 | 📖 只读 | 后台多机聚合聚类 → 人工审核 + 回归 → **增量原型包 OTA** 全网同步 |
| **L3 适配层** | 投影头、LoRA 适配器 | 📖 只读 | 离线训练验证，整包灰度发布；无端侧微调 |
| **L4 认知规则** | 世界模型规则、打分算子、价值向量、安全护栏、状态机 | 📖 只读 | 重大版本迭代，完整回归后灰度；端侧无权重修改能力 |

> L1 = 个体短期记忆；L2 = 群体共享的类别概念。**单机不能私自创建类别**。

### 9.6.2 闭环：四步

```
① 端侧采集提案（L1）：聚类成实例簇，附观测向量/环境/置信/冲突快照，仅上传
② 后台聚合：多机同类样本合并聚类，提炼候选原型（单机样本不足）
③ 人工审核 + 回归：语义、安全边界、混淆测试、旧能力不回退；不通过转负样本
④ OTA 分发：只发增量包，各机原型树追加叶子，原原型不动；可单独回滚
```

> 安全收益：单机噪声无法污染全局；原型包与权重解耦可单独撤销；数千台设备的样本聚合让原型鲁棒性远高于单机学习。

### 9.6.3 L2 原型的数据结构与免重训条件

新增的不是权重，而是**公共语义空间内的静态向量集合**：

```json
{
  "node_id": "proto_leaf_0042",
  "parent_node": "obj_living_mammal",
  "category_name": "豚鼠",
  "modality_protos": { "vis": [...], "ir": [...], "olf": [...], "geo": [...] },
  "stat_meta": { "sample_count": 142, "variance": 0.078,
                 "confidence_threshold": 0.72, "confusable_with": ["兔子","仓鼠"] },
  "safety_tag": { "is_living": true, "is_dangerous": false },
  "version": "proto_pkg_v1.3"
}
```

**为什么不用重训**：骨干是固定映射函数（原始信号 → 公共向量），坐标系已定；新增原型只是**在固定坐标系里多标一个聚类中心**，全程无反向传播。

| 场景 | 判定 | 处理 |
|---|---|---|
| A：特征落在预训练分布内（如新增豚鼠） | 映射可靠 | 仅新增原型，不重训 |
| B：完全超出分布（全新光谱/材质） | 输出不可靠 | 加原型无效，走 L3 微调 / L4 版本发布 |

> 原型不能凭空写：必须来自真实样本聚类；人工随手写一组数字与坐标系不匹配，毫无意义。

### 9.6.4 向量有效性：能输出 ≠ 可用

感官专家是确定性映射，**任何输入都会吐出 D 维向量，不会报"无法识别"**；超分布时同类向量四处飘散、异类挤在一起。

准入三要素（缺一不可）：

1. **聚集一致性**：不同场景/角度/光照的同类向量紧密聚类，簇内方差低于阈值；
2. **类别可分性**：与已有原型的距离足够大，混淆率低于指标；
3. **人工审核**：语义合理、安全标签合规、回归不破坏旧能力。

自动预审（提交人工前先跑一遍，阈值待实验标定）：

| 指标 | 超标处理 |
|---|---|
| 簇内方差 / 平均类内距离 | 自动驳回 |
| 最小类间距离（最近邻原型） | 驳回或转重点审 |
| 跨设备一致性 | 差异过大视为分布外，转 L3 |
| 样本量与覆盖度 | 退回继续采集 |

> 若不设这道闸门：分布外物体照样吐出散乱向量、本地聚成"假簇"，一旦误批，**全网在这个类别上都会幻觉跳变**。

## 9.7 交互层：情感、动机与目标

### 9.7.1 情感的三层辨析

| 概念 | 含义 | 本架构 |
|---|---|---|
| 主观感受（qualia） | "真的感到" | ❌ 不追求、不宣称 |
| 功能情感状态 | 识别 + 状态变量 + 策略 + 表达 | ✅ 实现 |
| 实体关联情感 | 人对物体的情感投射（旧玩偶唤起怀念） | ✅ 作为一路模态 |

**情感模态**：人脸表情/语调/姿态/语言 → 情感子专家 → 情感向量 → bind 到 human 实体的 `emotion` 模态，与识别颜色、材质**完全同构**。

**内部情感状态**（L1，不是 `<obj>` 上的感知模态）：

```json
{ "valence": 0.7, "arousal": 0.3, "trust": 0.65, "fatigue": 0.15 }
```

- 由外部事件驱动的固定状态转移（L4）更新，**只改 L1，不改权重**；
- 用于驱动动机、目标优先级、表情语调——**不是主观体验**。

> 三条硬规则：① 关联情感模态**不能作为动机来源**（玩偶不能产生欲望）；② 原型语义禁止注册"物体拥有主观情绪"这类拟人断言；③ 情感只调权重，**永不覆盖硬安全**（9.8）。

### 9.7.2 情感如何介入推理

| 模式 | 作用 |
|---|---|
| 识别/证据融合 | 对方恐惧 → 调高安全证据权重 |
| 关系判断 | 更新实体间情感关系（友好/戒备） |
| 目标规划 | 情绪低落 → 提升"陪伴安抚"；极度愤怒 → 后退、停止交互 |
| 冲突检测 | 情感异常作为冲突事件存快照 |

### 9.7.3 需求 → 动机 → 目标

```
需求信号（4 类） → 融合情感得动机向量 → L2 目标原型检索
→ 综合打分（安全一票否决） → 主目标进入规划（模式④）
```

| 需求 | 来源 | 示例 |
|---|---|---|
| 硬件维持 | 电量、故障、过热 | 去充电 |
| 任务 | 外部指令、后台任务包 | 拿水杯、巡逻 |
| 社交交互 | 情感模块导出 | 陪伴安抚（对方抗拒则降权） |
| 探索 | 受控好奇心 | 低置信实体，**带安全闸门** |

打分因子：动机相似度、**安全风险（一票否决）**、资源成本、与主目标冲突度、L1 历史成败。

目标实例生命周期（存 L1）：`候选 → 激活 → 执行中 → {完成 / 暂停 / 终止}`，可被高优先级事件抢占；同类执行形成实例簇 → 提案 → 审核 → 成为 L2 目标原型全网下发。

> 边界：无主观欲望，只是信号融合与状态机；探索动机必须限幅；L4 内置动机衰减防"偏执循环"；冲突超预设边界时存快照上报，**不自主发明仲裁逻辑**。

## 9.8 约束与韧性：价值护栏与异常降级

### 9.8.1 三层护栏（上层一票否决下层）

**第一层：硬安全黑名单（L4 固化，并行监测，不可绕过）**

| 类别 | 示例 |
|---|---|
| 人身伤害 | 挤压人体、高速撞击、抓取危险尖锐物、明火接触 |
| 隐私越界 | 未授权录制敏感场景、侵入私密空间 |
| 设备自毁 | 电池过充、电机过载、碰撞自毁 |
| 法律合规 | 执行违法操作 |

> 触发即抢占主目标、强制停止；**任何 LLM、情感、动机模块都无法改写或绕过**。

**第二层：量化价值向量（L4 固化）**

```json
{ "human_safety": 1.0, "human_comfort": 0.85, "task_fidelity": 0.6,
  "self_preservation": 0.4, "resource_efficiency": 0.3, "exploration_restraint": 0.2 }
```

```
final_score = similarity × value_weight × safety_coeff − cost_penalty
```

> 是固定配置参数，不是网络权重。例：搬运目标带轻微人体风险 → `human_safety` 大幅压分，目标被放弃。

**第三层：场景/社会价值原型（L2 OTA）**

如「深夜保持低声」「对老人放缓动作」「儿童交互约束」，节点存向量 + 适用场景 + 权重修正 + 安全标签；本地只读，新增须审核（重点：文化适配、反偏见）。

**嵌入位置**：感知打属性标签 → 动机受价值修正 → 目标打分 → 冲突仲裁 → 执行持续校验。**贯穿全链路，不是后置过滤器。**

### 9.8.2 审计快照

每次价值参与决策都存：观测向量、实体信息、情感状态、动机向量、候选目标打分明细（价值贡献）、最终决策、护栏触发与否及原因。

> 用途：异常可完整复现定位（原型问题/感知噪声/规则边界）；扩充回归集；合规审计。
> 边界：**无内生善恶意识**；复杂伦理两难**不自主决定**——标记快照、停止执行、等人工介入。

### 9.8.3 四级降级

| 等级 | 触发 | 行为 |
|---|---|---|
| **Normal** | 无异常 | 全功能 |
| **Warning** | 单帧噪声、个别实体方差高 | 持续运行；不稳定实体降权；存快照 |
| **Degraded** | 单相机失效、大范围漂移、动机震荡 | 停非必要动作；关探索目标、压社交优先级，只留自保与安全监护；**暂停提案上传**（防脏样本）；向用户播报 |
| **Emergency** | 多传感器失效、过热、高风险冲突 | 停止主动动作、制动断电；仅留硬安全监测；存快照等人工 |

异常四类：感知（硬件故障/信号质量/向量漂移/模态冲突）、推理（死锁/置信低迷/动机震荡/检索异常）、硬件执行、通信断连。

检测器并行常驻，输出 `system_health{health_level, fault_list}`。要点：

- **硬安全在任一级别都保持激活**；
- 传感器部分损坏仍会吐向量 → 靠**方差校验降权**，不直接采信标签；
- 状态切换设防抖门槛，避免 warning/degraded 震荡；
- **断网不停机**：本地 L1、原型库、安全护栏独立运行；
- 中重度故障关闭提案上传，杜绝故障期错误簇污染后台。

## 9.9 定位：AGI 与自我迭代

### 9.9.1 AGI 的两派定义与工程判据

| 流派 | 主张 | 判定 |
|---|---|---|
| 行为/功能派（工程主流） | 跨领域通用求解：无需专门预训练即可学新任务、适应新环境，接近人类水平 | 可用任务集测试 |
| 认知/现象派 | 还须有主观意识、自我觉知、qualia | 目前无可操作判据 |

工程判据七条：开放环境感知、跨任务迁移、自主目标生成、受控在线学习、常识/反事实/因果、自我认知与状态监控、可处理模糊矛盾信息。

### 9.9.2 本架构的自我定位

| 判据 | 本架构 |
|---|---|
| 开放环境感知 | ✅ |
| 跨任务迁移 | ✅（受 L2 审核节奏限制） |
| 自主目标生成 | ✅（9.7，安全一票否决） |
| 持续在线学习 | ⚠️ 半自主（L2 需人工 + OTA） |
| 因果/反事实 | ✅（有限；深层因果仍待解） |
| 自我认知 | ✅（`self` 实体 + `system_health`） |
| 模糊信息 | ✅（置信加权、冲突上抛、证据融合） |

> **结论：属"受控开放世界实体智能"，是工程 AGI 的重要子集，但不是完整 AGI。**

不是因为做不到，而是主动舍弃：底层推理逻辑不可改、价值体系不可改、学习有强制人工断点、不能凭空创立认知框架。

> 类比：它能不断认识新事物、学会新目标，**但不能自己重新定义善恶，也不能关掉安全闸门**。

若采用"意识派"标准，则无论跑多完美都不算 AGI——9.7.1 已明确不做主观体验。

### 9.9.3 自我迭代的三层

| 层级 | 内容 | 是否 AGI | 本架构 |
|---|---|---|---|
| **A 参数调优** | 超参搜索、局部调优 | ❌ | 放开 |
| **B 模块级重构** | 自设特征提取器/检索算子，不碰价值与安全 | ≈ 强通用智能 | 允许，但**必须过人工闸门 + 回归 + OTA** |
| **C 深层自重构** | 重写 L4 公理、价值、决策根基（Recursive Self-Improvement） | ✅ AGI 标志 | **禁止** |

**B 级所需五项能力**：自身建模（知道模块组成、短板、失效模式）、因果推理（改 X 会带来什么副作用）、跨领域迁移、不确定性评估（区分安全小改与高危改）、目标规划（分步方案 + 验证用例）。
**C 级额外三条**：反思并识别自身公理缺陷；推演全系统连锁后果（含伦理长期影响）；在无人类目标函数时**自主确立"为什么要改自己"**。
> 最大难点：改底层价值等于改变"判断好坏的标准"本身 → **目标漂移/价值腐蚀**，正是对齐研究核心难题。

### 9.9.4 与 LLM 的天花板对比

| 能力域 | 谁更高 | 说明 |
|---|---|---|
| 物理开放世界、机器人自主任务、长期交互、安全审计 | **本架构** | 原生实体、硬件感知、并行硬护栏；LLM 接机器人属外挂 |
| 纯抽象数学、海量书本知识、开放语言创造 | **LLM** | 直接吸收全部文本；本架构需转为实体/原型，效率低 |
| 自我优化 | 各有约束 | LLM 可做 A、有限 B，C 级缺护栏易漂移；本架构 B 级强制闸门、C 级禁止 |

> 不是"能不能做到"，而是"要不要放开"。本架构主动压低自我迭代上限，换取可审计与安全。
> 即使只做 B 级也有风险：隐性缺陷导致感知漂移、与 L4 规则隐性冲突 → 一律后台回归 + 人工审核 + OTA 灰度 + 可回滚。

## 本章收束

> **模块化不是没有兑现，而是兑现的形式是"隔离爆炸半径"。**
> 真正让这套架构跑起来的，不是更强的模型，而是**显式实体、分模态证据、分层检索、有边界的算子复用**。
>
> 后半程把系统从"能推理"推到"能长期安全运行"：**学习权限**决定谁能改知识，**情感**给交互层提供状态表征，**动机与目标**把需求转成行动，**价值与护栏**约束行动边界，**异常降级**保证坏天气下不失控。
>
> 完整闭环：
>
> `多模态感知 → <obj> 实体表征 → 情感状态 → 需求信号 → 动机向量 → 候选目标 → 价值+安全打分 → 动作执行（硬安全并行校验） → L1 记忆与快照回传 → 后台审核 → 原型 OTA 更新`
>
> 最终定位：**受控开放世界实体智能**——工程 AGI 的重要子集，而非完整 AGI。自我迭代上限被主动压低：调参放开、模块优化过人工闸门、底层公理自改写明确禁止。这份克制不是能力不足，而是安全与可审计性的代价交换。
