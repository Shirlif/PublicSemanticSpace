## 2. 动作头：闭环推力任务

任务：把桌面上的方块推到随机目标点（容差 6 cm）。动作头输出 `push(force, direction)`，由 MuJoCo 执行物理推力；每轮重新读取位置并修正方向。

| 指标 | 值 |
|---|---:|
| 试验数 | 10 |
| 成功率 | **0.900** |
| 平均最终距离 | 0.039 m |
| 平均推力次数 | 7.6 |

失败的一例最终距离 0.116 m，主要是方块被推过目标后的滞后修正；其余 9 例在 1–6 cm 内。

> 动作头是**规则控制器**（方向 = 目标 − 位置，力 ∝ 距离），不是学习策略。它验证的是"实体状态 → 原语参数 → 执行器"这条读出链路；学习版可以替换 `propose_push_to`，接口不变。

### 2.1 学习动作头（行为克隆，2026-11-22）

`pss/heads/action/learned.py` 用规则控制器采 60 条 demo（约 480 个状态-动作样本），训练 7→64→64→3 的 MLP，预测 `(direction_x, direction_y, force)`。接口与规则头一致。

held-out 10 trials（同一 seed+1000，规则头也在同一批上评）：

| 头 | 成功率 | 平均最终距离 | 平均推动次数 |
|---|---:|---:|---:|
| 规则 | 0.900 | 0.042 m | 7.4 |
| **学习 BC** | **1.000** | **0.027 m** | **6.2** |

- 学习头不是新能力，而是把"非学习动作头"这个边界补上；它仍只做单方块推力。
- 行为克隆自规则控制器，训练分布和评测分布相同；不能据此声称复杂操作泛化。
- 检查点：`checkpoints/phase8/action_head/action_head.pt`。

## 3. 文本头

- **参数量：0**。纯只读投影，没有梯度路径。
- 输入：实体列表 + 关系事实 + 可选计划；输出：自然语言。
- 示例输出：

```
cup_02 是 cup，位于 (-0.12, -0.16, 0.05)。
toy_fruit_01 是 toy_fruit，位于 (0.16, 0.00, 0.05)。
tool_02 是 tool，位于 (-0.04, 0.10, 0.01)。
plate_01 是 plate，位于 (-0.29, -0.22, 0.01)。
```

- 预留 `CallableAdapter`：可插入外部冻结 LLM；本环境未安装 LLM，默认使用模板适配器。
- 语言只出现在末端，核心推理与规划不经过文本。

## 4. 价值/目标头

目标点 `(0.20, 0.0)`，按"目标接近度 + 安全相关度"打分：

| 实体 | 类别 | 价值 |
|---|---|---:|
| toy_fruit_01 | toy_fruit | 0.614 |
| tool_02 | tool | 0.498 |
| cup_02 | cup | 0.365 |
| plate_01 | plate | 0.313 |

这个分数直接作为 Phase 6 工作记忆的 `task_scores` 先验。演示中 `AttentionScheduler(capacity=2)` 选中 `toy_fruit_01`、`tool_02`，与价值排序一致。

### 4.1 学习价值头（合成偏好，2026-11-22）

`pss/heads/value/learned.py` 用非线性合成效用生成 4000 对偏好，训练一个小 MLP：

```text
U = 0.6 * task(d) + 0.3 * safety + 0.1 * novelty - 0.25 * max(0, 0.25 - safety)
loss = Bradley-Terry pairwise + 5.0 * utility regression
```

held-out 1000 对 + 200 组 5-way：

| scorer | pairwise accuracy | top-1 accuracy (5-way) |
|---|---:|---:|
| 规则价值头 | 0.972 | 0.975 |
| **学习价值头** | **0.992** | **0.985** |

- 学习头在 pairwise 和 5-way top-1 上都超过规则头。
- 关键是加了 utility regression：只用 pairwise 时 top-1 只有 0.840；pairwise 准确率不等于绝对排序质量，回归项负责校准分数。
- 这是合成偏好数据，不是人类偏好；结论只证明训练链路和接口，不证明价值判断能力。

## 5. 文本头消融（核心断言）

| 项 | 值 |
|---|---:|
| 测试样本 | 18 |
| 文本头调用前准确率 | 1.0000 |
| 文本头调用后准确率 | 1.0000 |
| delta | **+0.0000** |
| 原型库 hash 未变 | ✅ |

在两次识别之间插入了 20 次文本头渲染。**delta 为零是架构保证，不是训练结果**：文本头没有参数、没有梯度路径，消融用于防止意外改写核心状态。

这对应 5.7 主张一：**语言是读出接口，不是思考媒介**。如果训练时让文本损失主导表征，就会出现 5.5 警告的"带向量包装的 LLM"；本实现从结构上切断了这条路径。

## 6. 冻结的决策

| # | 决策 |
|---|---|
| 1 | 文本头只读、零参数；LLM 只能通过冻结适配器接入 |
| 2 | 动作头接口固定为 `propose_* -> ActionProposal`；规则版 + 行为克隆版并存 |
| 3 | 价值头是注意力先验，不是奖励模型；规则版 + 合成偏好学习版并存 |
| 4 | 消融以"核心状态不变"为验收，不以训练指标变化为验收 |
| 5 | 文本、动作、价值三个读出头并行，互不阻塞 |

## 7. 已知边界

| 边界 | 说明 |
|---|---|
| 动作头非复杂策略 | 规则版 + BC 版；不能泛化到抓取/装配 |
| 文本头非 LLM | 模板适配器；未接真实语言模型 |
| 价值头学习版是合成偏好 | pairwise 0.992 / top-1 0.985，但训练目标是人工定义的效用，不是人类偏好 |
| 消融是结构性的 | 不证明"如果允许梯度会怎样"，只证明当前路径无泄漏 |
| 闭环任务简单 | 单方块推力；不是抓取/装配 |
