## 4. 关键发现

### 4.1 遮挡追踪达标

4 条遮挡序列全部 100% ID 保持、零切换、零唤醒延迟、零 ID 膨胀。位姿 + 外观 + 时序联合，加上 dormant 轨道的 re-ID，足以在这类静态遮挡场景维持身份。

### 4.2 Episode 的失败来自瞬移动作，不是关联算法

Episode 里 lift/place 是运动学代理（直接把物体移到目标），5 帧内位置大跳变；跟踪器的常速度预测跟不上，导致 25% 的轨迹出现切换、25% 的 ID 膨胀、重现成功率 0。

> 这不是流程 bug，而是 Phase 2 已标注的边界：动作不是物理抓取。真实系统需要动作前后的连续观测，或者显式的动作算子告诉跟踪器"这个物体被移动了"。

### 4.3 工作记忆的"槽 ≠ 身份"成立

- 驱逐只丢绑定，不删实体；
- 重新激活时从 raw 重新绑定新槽；
- 6 个实体、容量 4、逐个切换，recall 余弦全部 1.0000。

这是 Phase 1/4 的契约在运行时的第一次闭环验证。

### 4.4 注意焦点就是计算开关

200 个实体时，活跃 4 个只需 6 组两两关系；全场景是 19,900 组。空间查询 0.115 ms/帧，说明"休眠省的是计算，不只是存储"（7.3）。

## 5. 冻结的决策

| # | 决策 |
|---|---|
| 1 | 实体身份归场景图，槽只是工作记忆位置 |
| 2 | 关联只用位姿/外观/时序，GT id 只用于评测 |
| 3 | dormant/missing/historical 三级生命周期；re-ID 用宽松门限 |
| 4 | 工作记忆 4 槽，Hadamard 绑定，换槽从 raw 重建 |
| 5 | 碎片：**目睹事件**用确定性 API（`SceneGraph.fragment`）；**仅结果观测**的概率假说留给 Phase 7 |
| 6 | 空间索引用粗网格，足够数百实体；大规模再换 octree/ANN |

## 6. 已知边界

| 边界 | 说明 |
|---|---|
| 模拟位姿噪声 | 没有真实 SLAM、回环、重定位 |
| 静态遮挡物体 | 遮挡序列物体不动，难度偏低 |
| Episode 瞬移 | lift/place 非物理抓取，跟踪器被压力测试 |
| 外观弱 | 冻结小 CNN，不是真实预训练骨干 |
| 无碎片假说 | `fragment` 只覆盖"看到过程"的分支 |
| 无关系推理 | 场景图只存实体，尚未接关系/动作/世界模型 |
